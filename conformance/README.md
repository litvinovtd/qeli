# Cross-language conformance fixtures

The production transport is the shared Rust core on the server, CLI and all native apps.
Retained C# and Swift wire primitives, plus every platform's config/share-link parser, are
still independently testable. Every duplicated primitive is a chance to disagree, and the
failure mode is **silent**: the tunnel may still "work" while one path does something weaker
or different.

Generated cross-language fixtures use `platforms` to name their required consumers.
The legacy hand-written `qeli-links.json` instead uses `cases`/`reject`, and
`config-boundary.json` uses `base`/`cases`; neither currently has a `platforms` list.

## Why this is not paranoia

Real divergences these fixtures caught (or would have caught):

- **M6 — the data-plane nonce.** The counter-derived PRP nonce landed in Rust, C# and
  Swift; **Android kept generating a random 96-bit nonce for a whole release**, carrying
  exactly the birthday risk the design removes. Nothing noticed: there was no
  `PacketCodec` test on Android at all, and the only fixture at the time covered link
  parsing. → `prp-nonce.json`
- **`qeli://` links.** Android emitted `mtu` but had no branch to parse it back; an
  omitted `bind_static` silently re-defaulted to ON, demanding a key the link never
  carried; the port was range-checked in Swift and C# but not in Rust (accepted `0`) or
  Kotlin (accepted anything). → `qeli-links.json`

## Generated vs hand-written

Project-generated wire fixtures check consistency between implementations; they do not
independently prove a cryptographic primitive correct. Primitive known answers must come
from an independent oracle. The NIST and RFC fixtures are frozen external vectors and are
never regenerated by the Rust primitive under test.

```bash
cd qeli
cargo run --features conformance-gen --bin gen-conformance            # rewrite the files
cargo run --features conformance-gen --bin gen-conformance -- --check # fail if stale
```

The generator is [`qeli/src/gen_conformance_main.rs`](../qeli/src/gen_conformance_main.rs).
`--check` regenerates in memory and compares against disk, exiting non-zero on drift, so a
fixture can never quietly fall out of step with the implementation it pins. Wire it into CI
as a gate.

> `gen-conformance` is behind the off-by-default `conformance-gen` feature, so normal
> server / CI / FFI builds never compile it. It also lives at `src/gen_conformance_main.rs`
> rather than `src/bin/` — `.gitignore` carries `**/bin/`, which would silently keep it out
> of git (the same trap `src/client_main.rs` documents).

## Independent cryptographic known answers

`mlkem768-nist.json` contains all 60 ML-KEM-768 cases from the NIST ACVP keyGen and
encapDecap internal projections at commit `65370b861b96efd30dfe0daae607bde26a78a5c8`.
Each retained case records its original `tgId`/`tcId`; `sources` pins the original
[ACVP keyGen](https://github.com/usnistgov/ACVP-Server/tree/65370b861b96efd30dfe0daae607bde26a78a5c8/gen-val/json-files/ML-KEM-keyGen-FIPS203)
and [encapDecap](https://github.com/usnistgov/ACVP-Server/tree/65370b861b96efd30dfe0daae607bde26a78a5c8/gen-val/json-files/ML-KEM-encapDecap-FIPS203)
URLs and SHA-256 of the complete downloaded source files. Five modified ciphertexts
pin the expected implicit-rejection secret, rather than expecting an error. All keys
and seeds here are public test material, never deployment secrets.

`chacha20poly1305-rfc8439.json` pins [RFC 8439 section 2.8.2](https://www.rfc-editor.org/rfc/rfc8439.html#section-2.8.2).
Its empty-AAD expectation was generated independently using Python cryptography after
checking that implementation against the published RFC vector. Rust tests check the
actual allocating and detached wrapper paths and reject every one-bit ciphertext/tag
mutation, a wrong nonce/AAD and truncated tags. X25519 RFC 7748 section 6.1 inputs and
expected outputs are embedded directly in `crypto/exchange.rs` tests.

These external fixtures have their own explicit schema (`sources`, algorithm-specific
case lists or RFC fields), consumed only by shared Rust core unit tests. They do not use
the generated cross-language `platforms` schema below. Native apps use the same compiled
crypto implementation. JSON here is machine-readable test data; Qeli configuration
remains INI. Known answers are neither an external security audit nor side-channel proof.

## File format

```jsonc
{
  "_comment": [ "why this file exists, how to use it, what is settled" ],
  "primitive": "prp-nonce",
  "generator": "qeli/src/gen_conformance_main.rs",   // absent for hand-written files
  "platforms": ["rust", "csharp", "swift"],
  "cases": [ { "name": "...", "why": "...", /* inputs */ , /* expected */ } ]
}
```

**`platforms` is load-bearing for generated cross-language fixtures.** It lists the implementations *required* to pass the file.
Their consumers assert their own name is present — so a renamed primitive or a moved file
makes the test **fail**, instead of leaving it green having verified nothing. A green test
that checked nothing is the precise failure these fixtures exist to prevent.

Every case carries a `why`. If you cannot say what a case would catch, it is not pulling
its weight.

## Consumers

| Platform | Test | How it finds the file |
|---|---|---|
| Rust | `qeli/src/protocol/packet.rs` (tests), `qeli/src/config/share.rs` (tests) | `include_str!` — compiled in, so a moved path breaks the build |
| C# | `qeli-shared/QeliShared/Protocol/PrpNonceConformance.cs`, `…/Model/LinkConformance.cs`, run by standalone `qeli-shared/QeliConformance selftest` on both desktop CI hosts | walks up from the working directory |
| Kotlin | `qeli-android/app/src/test/kotlin/com/qeli/QeliLinkConformanceTest.kt` (`qeli-links.json` only) | walks up from the working directory |
| Swift | `qeli-ios/QeliIOSTests/…` | walks up from `#filePath` |

The standalone C# runner may also be invoked outside a repository, so a missing fixture is
a SKIP — **except** under `QELI_CONFORMANCE_REQUIRED=1`, which CI sets so that a moved file
cannot turn the gate into a no-op. Production desktop applications do not compile or ship it.

CI already lists `conformance/**` in its path filters, so touching anything here runs all
five suites.

## Adding a primitive

1. Add a case builder to the generator and regenerate (or hand-write the file if the
   inputs are not something the canon computes, e.g. link strings).
2. Write the `_comment` block first: **why** the file exists, **how** to use it, and what
   is deliberately *not* covered. The next person needs to know what a failure means.
3. Add a consumer test in each language on the `platforms` list, asserting its own name is
   listed.
4. If a platform legitimately does not implement the primitive, leave it **out** of
   `platforms` — do not add a test that skips.

### What is easy and what needs a seam

- **Decoding is deterministic by construction** — given a key and a record, the plaintext
  is fixed. A decode fixture pins framing, AEAD, counter placement and padding-trailer
  stripping across the three retained primitives **with no test-only decode seam**.
- **Encoding needs the randomness injected** (nonce seed, PRP key, padding), which means a
  test-only seam in each implementation. Worth it: this is the class M6 belonged to — the
  primitive was correct everywhere, the *wiring* was not.
- **Some things cannot be byte-pinned at all** (the fake-TLS ClientHello: GREASE,
  extension shuffling, random, key_share). Assert structural invariants instead, or route
  every client through the canonical builder already exported over FFI
  (`qeli_build_faketls_clienthello`).

## Not covered yet

Record **encoding** (needs the randomness injected — see the seam note above), obfs
keystream, AWG junk bodies, WebSocket framing (currently an inline vector in
`ObfsStreamTest.kt` — should move here), fake-TLS ClientHello (structural assertions only —
it cannot be byte-pinned).

Junk decoys and MTU probes carry random bodies by design, so their bytes cannot be pinned;
`udp-frag.json` covers their FRAMING via `classify`, and the deterministic probe ACK in
full.

### An integer-width note worth knowing

The QUIC fixture is consumed by Rust and the retained C# and Swift primitives; desktop and
Android production connections now use the shared Rust transport core rather than separate
C#/Kotlin data planes. Rust and Swift use an unsigned 32-bit packet number, while the retained
C# API uses the same bit pattern in a signed `int`. The `short-header-pn-high` case proves that
all four bytes are preserved in network byte order when the high bit is set.

## Notes for specific platforms

**Android.** Constructing the codec in a JVM unit test needs
`testOptions { unitTests.isReturnDefaultValues = true }` (already set in
`qeli-android/app/build.gradle.kts`): `PacketCipher` touches `android.util.Log` at
class-init, and the default framework stubs throw "not mocked". Without that line the wire
codec — the most safety-critical code in the app — is untestable off-device, which is
precisely why Android had no `PacketCodec` test at all and why the M6 fix went missing
there unnoticed.

## Shared managed/native lifecycle checks

`QeliConformance selftest` also exercises the production C# adapter through the actual
host native library: 32 create/start/event/stats/stop/free generations, invalidated
handles and refusal of a fabricated plan acknowledgement without a pending plan.
Observer failures are injected separately into log, status, drop and completion
notifications. Packet-pump fixtures verify read failure/early exit, cancellation and
ownership retained until all worker tasks have stopped, including the actual 8 second
Stop timeout and a later successful cleanup retry. Reflection verifies that
managed wire codecs and BouncyCastle are excluded from the production QeliShared
assembly. Release-metadata fixtures check the 1 MiB body limit and cancellation after
headers; the optional public HTTP check has a single 10 second deadline.

These are ABI/lifecycle and fake-TUN checks; they do not install routes/firewall rules,
exercise a live desktop VPN connection, or replace platform integration tests. The
Rust core and native artifacts are unchanged by these managed checks. Mandatory-fixture
mode is verified by running an isolated copy without fixtures and by an empty config
boundary corpus: both must fail, without a successful SKIP gate.

Desktop route-reader fixtures also cover mixed line endings, the 65,536 UTF-16-unit line
boundary, cancellation before newline, and Unicode comment batches constrained before
serialization. The existing 14,113-route CIDR/OpenVPN equivalence, merging and cancellation
checks still exercise the shared native route parser.
