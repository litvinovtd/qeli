# Q25-F146: concurrent server INI writes

1 October 2026. Base: `0bef4299`. D07 remains **IN_PROGRESS**.

The panel serialized its own saves only within one process. A separate `qeli set-web-password` command took no lock, so overlapping read-modify-write operations could read the same revision and silently overwrite one another. Backup restore also did not share a cross-process lock. In addition, exact restore deleted `server.conf.lock`, and an archive could replace the lock inode; subsequent `flock` participants then synchronized on different files.

All five panel INI write paths (Quick Start, form, raw INI, history, blocked settings), CLI, and restore now hold the same sidecar `FileLock` from first read through publication. Panel lock admission runs in `spawn_blocking` with a 5-second bound; restore waits on its blocking worker within the overall 60-second budget. Form and raw PUT bind revision reads to the canonical path under lock and reject path changes. New backups exclude `*.lock`, old archived lock files are ignored during publication, and exact restore preserves active lock files.

Verification on isolated .11: 35 editor tests, including a new two-writer regression; 23 backup tests and 2 expected ignores; strict Clippy for library and CLI; CLI build and a held-`flock` check where `set-web-password` times out without changing the INI, then succeeds after release. The targeted tests and strict `--lib --bin qeli` Clippy were run separately.

Limit: a manual SSH editor does not honor the advisory lock. POSIX `rename` offers no atomic content compare-and-swap, so an external edit between the panel's final read and publication can still be overwritten. The full D07 field/path matrix and this case remain open. Register: **5/15 DONE**.
