# Q33: service-user transitions and installer secret ownership

8 October 2026. F439–F441 / Q33-F042–F044. Q33 remains IN_PROGRESS.

## Findings and changes

- **F439 / Q33-F042:** installer, Debian postinst and default-unit `set-service-user qeli` recursively handed all /etc/qeli files to the daemon account. This included root0600 password receipts and config backups. They now traverse daemon state without following symbolic links, exclude `client-links` and `*.bak-*`, preserve their file metadata, and restore the receipts directory to root0700. Old receipts whose file owner was already changed are protected by the private directory; their individual ownership is not reconstructed.
- **F440 / Q33-F043:** the CLI did not validate the state root before recursive chown. For a symbolic link passed as that root, chown could succeed without repairing the real state, after which the root override was removed. It now rejects linked/non-directory state/receipts roots and retains the existing error-before-removal ordering for repair failures. Non-root callers still cannot change it. A partial ownership repair is not rolled back; daemon-reload failure after removal remains outside these failure scenarios.
- **F441 / Q33-F044:** reinstalling with the default qeli choice left an old root override in place. Installer now applies the selected QELI_RUN_AS after final staged-INI validation and before config publication, including default qeli. Invalid configuration or helper failure retains the live config. This does not make the whole installer transactional.
