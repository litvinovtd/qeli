## Findings and changes

- **F427 / Q33-F030:** summary/per-user writes followed symlinks; wildcard chmod could change an unrelated external target. Generated names are now checked before dependencies and again at secret-stage entry. Private same-directory temporary files are renamed into place; no wildcard chmod. Hardlinks are broken by replacement rather than modifying external inodes. Newly generated links/summary use root0600. Already-kept generated links preserve their bytes through a private0600 copy, preserving the previous privacy behavior without following chmod into an external hardlink.
- **F428 / Q33-F031:** truncating summary before user creation lost the complete old list on partial failure. A CLI error/missing link after committing a user could also lose the generated password. Summary is staged until all users are handled; the old list remains on error. Before each add-client, a root0600 INSTALL-PENDING journal records that user's password; successful output adds its link. Failures keep this journal, even if link/summary publication fails. On successful summary publication it is removed. Accounts and individual links may already have changed; pending entries do not prove account creation. This is recoverability, not an all-or-nothing install or automatic account rollback.
- **F429 / Q33-F032:** web helper copied through the final config inode, so an interrupted write could truncate it and a hardlink could modify an external copy; failed awk leaked temporary data. Rewrite now uses a registered same-directory temporary file, explicit failure propagation, ownership preservation, mode600 and rename. Both awk/publish failures preserve the old config and clean the temporary file. This does not cover initial profile generation, the CLI's own rewrites or the complete reconfiguration transaction.
- **F430 / Q33-F033:** backups shared a second-resolution name and could overwrite a previous backup made in the same second. Both config and summary backups now use reserved unique names with root0600 and preserve source bytes. Two backups made under the same timestamp retain both versions.
- **F431 / Q33-F034:** retained users were described as having stale links because a new REALITY short_id was minted even for UDP/fake TLS. The notice now says to re-issue when endpoint/profile settings changed; existing passwords remain untouched, and the prior summary backup/recovery journal is referenced.
