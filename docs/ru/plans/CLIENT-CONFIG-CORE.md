## Что объединено

В существующую библиотеку Qeli добавлен API **1.16**. Отдельно скачиваемого парсера нет:
приложение и ядро поставляются согласованно. Файлы профилей — только **INI**;
`qeli://` остаётся переносимым подмножеством. JSON используется только как служебный DTO
внутри вызова FFI/JNI, не как формат конфигурационного файла.

| Общая реализация | Что теперь выполняет ядро |
|---|---|
| `qeli/src/config/editor/` | Импорт INI/URI, редактирование документа, диагностика, проверка, экспорт, runtime/probe-проекция |
| `editor/schema.rs` | 81 поле `[qeli]` и 3 поля `[logging]`, типы, defaults и отображение свойств клиентов |
| `scripts/gen_config_bindings.py` | Генерация проекций и констант defaults C#, Kotlin, Swift; `--check` запрещает дрейф |
| `config/client.rs`, `share.rs`, `format.rs` | Единственные грамматики конфигурации и ссылок; runtime использует тот же документный сервис |
| `config/policy.rs` + существующий `transport_core/network.rs` | IP/CIDR, вычитание исключений, лимиты маршрутов, локальные подсети, LAN-исключения и перехватывающие маршруты |
| `config/route_file.rs` | CIDR/OpenVPN-файлы маршрутов, маски, нормализация, порядок, дубликаты, номер ошибочной строки |
| `config/policy.rs` | Бюджет повторов, backoff/jitter, минимальный интервал и счётчик нестабильных сессий, сравнение версий, полный туннель, допуск roaming, условия приватного пути обновления |

Windows и macOS используют один `QeliShared/Model/ConfigCore.cs`, Android — `ConfigCore.kt`
и настоящий JNI, iOS — `ConfigCore.swift` и C ABI. Из моделей удалены местные парсеры,
валидаторы, INI/URI-сериализаторы и перечисленные алгоритмы. Модели и генератор остаются
проекциями данных, без резервного локального парсера. Linux использует Rust напрямую;
его решение о повторе, счётчик и расчёт задержки также используют общие функции.

## Контракт документа

Запрос имеет `version = 1`. Операции: `schema`, `import`, `export`, `validate`, `runtime`,
`uri`, `probe`, `policy`. Ответ содержит `ok` и `result` либо `error`.
`schema` возвращает типы, defaults, диапазоны числовой проекции и признак чувствительности;
это не исчерпывающая схема всех межполевых и платформенных ограничений.

- `import` INI открывает исправимый черновик. Дубликаты, неизвестные поля и неправильные
  скаляры сохраняются с диагностикой. Структурно неверный endpoint/INI может быть отвергнут.
  URI проходит строгую проверку сразу.
- `export` сохраняет черновик: отсутствующее поле отличается от пустого. Повторяемые списки
  и чужие платформенные поля сохраняются. Комментарии, отступы и исходный регистр не сохраняются.
- `values` накладывает изменённые значения формы на `source`; `patch` явно меняет ключи INI,
  включая удаление через `null`. Снятие маркера ошибочного скаляра в `unresolved` подтверждает
  исправление даже на отображаемое значение по умолчанию.
- `validate`, `runtime` и `uri` отвергают ошибки. Дубликат не выбирает сервер для запуска:
  черновик отображает первую запись, но активировать его нельзя до устранения неоднозначности.
- `runtime` материализует общие defaults. Для iOS проекция исключает desktop `kill_switch`,
  сохраняя его в переносимом документе: защита NetworkExtension/On Demand остаётся системной.
- Старое `dns = <IP-список>` мигрирует в `dns_servers`; явно заданный, в том числе пустой,
  `dns_servers` имеет приоритет. Legacy-режимы нормализуются общим ядром.

Общие клиентские defaults: **`gateway=true`, padding `0..255`, `heartbeat_jitter=2000` мс**.
Это изменение для CLI-профилей, где эти ключи отсутствовали. Для прежнего split tunnel явно
задайте `gateway=false`; для прежних padding/jitter также задайте желаемые значения явно.
Defaults серверных профилей этим не меняются.

## Границы и дополнительные кандидаты

| Область | Решение и причина |
|---|---|
| Парсер `route_file` | Перенесён; C# оставляет файловый I/O, отмену, загрузку порциями и объединение нескольких файлов. Mobile хранит пути, но не читает пути другого устройства |
| Маршруты и reconnect | Общие расчёты перенесены. Установка/откат маршрутов, таймеры, сон/пробуждение и события ОС остаются у адаптера |
| Обновления | Общие сравнение версий и условия приватного пути. Сеть, подписи, установка и факт перехвата самого приложения — ответственность платформы |
| Секреты | Маскировка диагностик и чувствительные поля — ядро. DPAPI, Keychain, Keystore, ACL и миграция хранилищ — ОС |
| FFI | Схема конфигурации генерируется. Полная генерация всех transport/event/path структур в эту миграцию не включена; существующие ABI gates сохраняются |
| Crypto/Protocol в managed/Swift | Сначала проверен production reachability: часть файлов — независимые conformance/benchmark-эталоны. Они не являются резервным production transport и не удаляются как мёртвый код |
| UI protection summary | Общие факты маршрутизации вынесены; отображение платформенных возможностей остаётся в UI. iOS не заявляет применение per-app правил без MDM |

## ABI, сборка и проверки: этап 22 сентября

`qeli_config_request` — чистая функция без сессии, DNS, чтения файлов, сети и запуска
`password_command`. C ABI использует буферы вызывающей стороны, ограничивает запрос 2 МиБ,
ответ 4 МиБ, документ 256 КиБ; граница перехватывает panic. Адаптеры очищают временные
байтовые буферы с секретами. Строки managed/Swift/JVM и исходный профиль не дают гарантии
полного стирания всех копий из памяти.

Для разработки/CI из корня репозитория:

```sh
python scripts/gen_config_bindings.py --check
python scripts/build_client_core.py --debug
```

Второй сценарий печатает `QeliNativeCorePath` для `dotnet` и
`QELI_CONFIG_NATIVE_LIBRARY` для JVM-тестов; установите эти переменные перед сборкой/тестом.
При стандартном Cargo target каталог — `qeli/target/client-core/host`.
`--github-env` автоматически передаёт пути следующим шагам GitHub Actions.
Для Android после установки pinned NDK/cargo-ndk и Rust targets:

```sh
python scripts/build_client_core.py --android
```

Установите напечатанный `QELI_NATIVE_JNI_DIR` перед Gradle: он заменяет весь набор `jniLibs`,
а не смешивает новые библиотеки со старыми. iOS использует `qeli-ios/build_native.sh`.
CI собирает fresh host core для .NET/JVM, Android `.so` для APK/emulator и iOS XCFramework.
Старый ABI не включает резервный парсер: требуется совместимая библиотека 1.16+.

Эти dev/CI-сборки не перезаписывают релизные артефакты или provenance.
Закоммиченные библиотеки всё ещё требуют штатных независимых A/B-сборок через
`scripts/build_native_libs_p4.py` и `scripts/build_android_so_11.py`, затем проверки
`native-libs/verify.sh` и `native-libs/provenance.py`. Для этих рецептов нужны чистый
зафиксированный источник и доступ к лаборатории. Gate соответствия source/artifact
сохранён и до пересборки закономерно не пройдёт.

Локальная проверка включает Rust unit/integration, настоящий C ABI из C#, настоящий JNI
из JVM, Windows selftest, Linux cross-check/Clippy и проверку генератора. Apple build/test,
реальные устройства, release A/B и итоговые пакеты остаются отдельными незакрытыми gates;
их наличие в CI не означает, что они уже выполнены на этом изменении.

## Аудит runtime reconnect — 22 сентября 2026

Все lifecycle-адаптеры используют общий Rust-расчёт счётчика, решения о повторе и задержки.
Linux вызывает функции напрямую; C#, Kotlin и Swift — `next_attempt` и `retry_decision`
через сервис конфигурации. `connected_ms` — монотонное время установленной сессии;
`elapsed_ms` в запросе задержки — время от начала попытки. Эти величины разделены.

Исправлены: ложная стабильность после долгого handshake/очистки desktop; сохранение старых
ошибок в Linux после стабильной сессии, завершившейся ошибкой; ожидание сети Android до
проверки запрета/лимита повторов; обход конечного бюджета через desktop settling и возврат
сети mobile; учёт намеренного iOS roaming fallback как обычной ошибки; невозможность
исчерпать максимальный допустимый лимит при насыщении 32-битного счётчика. Поколения
carrier и диагностическое число реконнектов Linux больше не обнуляются вместе с бюджетом.
SIGINT/SIGTERM также прерывает Linux-backoff и переводит цикл к очистке без нового подключения.

Общий минимальный интервал между началами попыток — 1,5 с. Desktop settling и возврат сети
mobile сокращают только задержку; исчерпанный бюджет останавливает цикл. Разница между
`reconnect_retries=0` и `reconnect=false` описана в [мануале](../manuals/CONFIG.md).
Очистка маршрутов, таймеры, наблюдение за сетью и терминальные security/kick-события
остаются ответственностью адаптера.

## Аудит границ конфигурации — 22 сентября 2026

На исходном коде воспроизведены восемь регрессионных сценариев: удаление управляющих символов
из ключей/значений; непереносимые имена полей в overlay; исчезновение дубликата legacy DNS;
обход строгой проверки URI через BOM; утечка секрета в ошибке при patch/URI/верхнем регистре
INI-ключа; исчезновение ошибочного `dns_servers` при миграции; подмена секции через dotted-ключ
`logging.*` внутри `[qeli]`. Все сценарии получили исправления в общем ядре и регрессии.

Восьмой сценарий: управляющие символы внутри URI исчезали при преобразовании в INI,
меняя адрес, транспорт или ключ сервера. Канонический `ClientLink` теперь проверяет
декодированные значения до нормализации; исправление распространяется и на импорт панели.

Грамматика `IniDoc` теперь отвергает неподдерживаемые управляющие символы до trim/сериализации,
поэтому правило действует и на серверные конфиги. Нормализация DNS сохраняет ошибки и
возвращает согласованные `source`/`raw`. Маскировка ошибок учитывает `values`, `patch`,
INI без зависимости от регистра ключей и декодированные реквизиты URI. В клиентских
моделях проверяются реальные open/clone/copy/save/reopen пути; для Swift тесты добавлены,
но требуют отдельного запуска на Apple.

## Параметры перед runtime — 22 сентября 2026

Продолжение Q02-F015–F019 закрывает дефекты: TOFU для неверной длины нулевого PIN,
отсутствие общей проверки host и самопроизвольное исправление порта при частичном edit.
Одна грамматика адреса теперь применяется в INI, URI, runtime и публичных endpoint панели.
Положительные случаи IPv4/IPv6, localhost, ASCII/Punycode и локальные `_`-имена сохранены.
Удалён старый предварительный валидатор панели; сохранение/summary/поиск занятых dev
читают профиль тем же парсером. Определение и автозапись dev учитывают BOM и регистр,
не удаляют комментарии. Запреты панели на команды и опасные пути сохранены.
Linux unit-тест этой границы требует исполнения; cross-Clippy подтверждает компиляцию.
Подробности: [реестр Q02](../reports/audit-0.8.2/AUDIT-Q02-CLIENT-PARSERS.md).

## Подтверждённый локальный прогон — 22 сентября 2026

- Rust/Windows: 655 unit + 51 editor/FFI + 7 examples + 12 server-INI — PASS.
- C# с новой Release DLL: 466 conformance; Windows: 143 selftest — PASS.
- Kotlin/JVM с той же DLL через JNI: 154 теста, без skipped — PASS.
- Windows и macOS managed Release build — PASS; macOS runtime здесь не запускался.
- Linux cross-Clippy: all-targets PASS на Rust 1.98 с одним исключением
  `clippy::chunks_exact_to_as_chunks` для существующего NDP-кода. Минимальная FFI-сборка
  проходит `-D warnings` без исключений; CI lint закреплён на Rust 1.97.
- Генератор, 69 native-contract тестов, rustfmt, 9 проверок документации и diff-check — PASS.
- Release provenance — ожидаемый FAIL (`STALE NATIVE CORES`): бинарники в репозитории
  не пересобраны. iOS/Xcode, Android NDK/emulator/device, Linux runtime E2E, fuzz-run
  и новый benchmark не выполнялись в этом локальном прогоне.

Эти результаты подтверждают перенос исходников и работу C ABI/JNI на хосте;
они не закрывают платформенную сертификацию и выпуск пакетов.

Свежий dev x86_64 APK проверен по SHA. Release A/B, полный конфигурационный/runtime контракт и остальные платформы открыты.
