# Раздельная маршрутизация ресурсов

Выберите, какие назначения идут через Qeli, а какие — напрямую. Географическое
разделение строится на вашем актуальном списке IP/CIDR: встроенной базы стран или
правил по доменным именам у этих параметров нет.

[Каталог и подготовка](README.md) · [English](../../eng/scenarios/SPLIT-ROUTING.md)

## Выберите модель

| Модель | Клиент | Результат |
| --- | --- | --- |
| Только перечисленные сети через VPN | `gateway=false`, `include` | Остальные назначения используют обычный маршрут |
| Всё через VPN, кроме исключений | `gateway=true`, `exclude` | Исключения намеренно выходят вне VPN |
| Маршруты выдаёт администратор сервера | повторяемый серверный `route` | Клиент принимает их при `pull_routes=true` |

Примеры `203.0.113.0/24` и `198.51.100.7` — адреса для документации. Они не дают
доступа к реальным ресурсам: замените их проверенным списком. CDN, anycast и смена
IP делают привязку к стране приблизительной.

## Только выбранные IP через VPN

В существующем клиентском профиле:

```ini
[qeli]
gateway = false
include = 203.0.113.0/24, 198.51.100.7/32
pull_routes = false
dns = system
```

Здесь `pull_routes=false` исключает дополнительные маршруты сервера; оно не отключает
локальные `include`, соединение с сервером или самостоятельную политику full-tunnel.
Если нужны также маршруты администратора, верните `pull_routes=true`.
Для выхода к публичным IP сервер должен иметь подходящий NAT или routed uplink;
для частной LAN нужен [обратный маршрут](HOME-LAN.md).

На Windows/macOS длинный список можно хранить отдельно:

```ini
[qeli]
gateway = false
route_file = C:\Qeli\selected-cidrs.txt
```

```text
# selected-cidrs.txt: один IP или CIDR на строку
203.0.113.0/24
198.51.100.7
```

На macOS замените путь, например, на `/Users/alice/.config/qeli/selected-cidrs.txt`.
`route_file` здесь — desktop-функция; для Linux CLI/мобильных клиентов используйте
`include`/`exclude` или server push. Не применяйте одновременно противоречащие списки.

## Всё через VPN с прямыми исключениями

```ini
[qeli]
gateway = true
exclude = 203.0.113.0/24, 198.51.100.7/32
dns = tunnel
```

Это осознанный обход VPN для указанных адресов. `exclude` задаёт маршрут, а не
серверный ACL и не разрешение firewall.

**Linux CLI:** при `gateway=true` и `kill_switch=true` обычный прямой трафик к
исключённым назначениям блокируется kill-switch. Он разрешает TUN, служебный carrier
и ограниченные системные исключения, но не создаёт разрешения по списку `exclude`.
Если перенесли настройки из [FULL-TUNNEL](FULL-TUNNEL.md), включённая там защита
сохранится: этот фрагмент её не отменяет. Отказ прямого соединения в таком сочетании
не означает, что маршрут не установился.

Не выключайте kill-switch автоматически ради работы исключений. Если нужны и
прямые назначения, и блокировка остального трафика при обрыве VPN, требуется отдельная
проверенная политика firewall; приведённый INI не реализует её. Для Windows/macOS и
Android проверьте правила конкретного клиента и ОС, включая Always-on/lockdown:
установка прямого маршрута сама по себе не гарантирует доступ к сети.

## Серверные маршруты и DNS

Вместо локального списка можно добавить в профиль или пользователя:

```ini
[profile:main]
route = 203.0.113.0/24 gateway=10.9.0.1 metric=100
route = 198.51.100.7/32 gateway=10.9.0.1 metric=100
```

`allowed_networks` должен разрешать назначения, но сам маршруты не устанавливает.
IPv6-адреса требуют собственной политики. Если домен имеет AAAA, одного IPv4-списка
недостаточно. `dns=system` сохраняет локальный DNS, `dns=tunnel` использует разрешённые
туннельные резолверы; ни один вариант не превращает IP-список в доменный маршрутизатор.

## Проверка и откат

Проверьте полный конфиг, переподключитесь и сравните маршрут к адресу из списка
и адресу вне него (`ip route get` в Linux, `Get-NetRoute` в Windows, `route -n get`
в macOS). Проверьте реальный TCP/UDP-сервис, DNS, IPv6 и сохранение маршрутов после
reconnect. При откате верните прежние поля/файл и штатно переподключите профиль;
не очищайте системную таблицу маршрутизации целиком.

Справочник: [CONFIG](../manuals/CONFIG.md). Выбор по процессу, а не IP:
[PER-APP](PER-APP.md).
