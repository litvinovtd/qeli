# Только выбранные приложения через Qeli

Выберите приложения, которым разрешён VPN-путь, сохранив обычную сеть для остальных.
Это отдельная ось политики: приложение выбирают `apps_mode`/`apps`, а назначения —
`gateway`, `include`, `exclude` и server push.

[Каталог и подготовка](README.md) · [English](../../eng/scenarios/PER-APP.md)

## Поддержка платформ

| Платформа | Идентификатор | Условие |
| --- | --- | --- |
| Windows | Полный путь к `.exe` | Штатный клиент и его драйверы, необходимые права |
| Android | Имя установленного пакета | Разрешение VpnService и корректный список приложений |
| macOS | Code-signing identifier, обычно bundle ID | Подписанные System/Network Extensions с entitlements; ad-hoc архив 0.8.3 этого не предоставляет |
| iOS | Bundle ID | Обычный профиль не применяет произвольный per-app; нужны MDM и NEAppRule, клиент не опубликован |
| Linux CLI | — | Не выполняет классификацию процессов по этим полям |

Списки между ОС не переносимы. Наличие сохранённых полей INI не доказывает, что
платформа применяет их. Для macOS не отключайте проверку подписанных extensions
и не заменяйте отказ режима незаметным full-tunnel всего устройства.

## Выбор приложений

`apps_mode=include` включает в VPN только список `apps`; `exclude` исключает список,
а `all` использует обычный режим всего устройства. Для include/exclude задайте
непустой список. Используйте GUI picker: он записывает правильный идентификатор.

Пример Windows, в существующем клиентском профиле:

```ini
[qeli]
apps_mode = include
apps = C:\Program Files\Mozilla Firefox\firefox.exe
gateway = true
dns = tunnel
```

Пример Android, VPN для всех приложений кроме выбранных:

```ini
[qeli]
apps_mode = exclude
apps = com.android.vending, com.google.android.youtube
gateway = true
dns = tunnel
```

Для подходящей подписанной macOS-сборки список, например, выглядит так:

```ini
[qeli]
apps_mode = include
apps = org.mozilla.firefox
gateway = true
```

Если нужен VPN только к корпоративным сетям, установите `gateway=false` и добавьте
маршруты по [SPLIT-ROUTING](SPLIT-ROUTING.md). Per-app сам full-tunnel не включает.
`apps_mode` и `apps` задаются локально, не переносите эту политику одной `qeli://`-ссылкой.

## Запуск и проверка

1. Убедитесь, что приложения установлены и идентификаторы соответствуют версии/пути.
   Полностью остановите и переподключите VPN после изменения политики.
2. В выбранном браузере откройте проверочный endpoint внешнего IP; затем тот же
   endpoint в невыбранном приложении. Для full-tunnel ожидаются разные пути.
3. Проверьте DNS и UDP выбранного приложения, не только TCP страницы.
   `curl` из отдельного терминала относится к другому процессу и сам по себе
   не подтверждает политику браузера.
4. Проверьте IPv6, дочерние процессы приложения и поведение после обновления его пути.
5. Проверьте потерю VPN. Для Android с Always-on/lockdown не предполагайте, что
   исключённые приложения сохранят прямой интернет: системная блокировка сильнее
   желания приложения обойти VPN. macOS per-app не является host-wide kill-switch
   и не перехватывает ICMP.

## Ошибки и откат

Windows/macOS отказывают per-app без применимых идентификаторов. Android отказывает
include, если не найден ни один установленный пакет; exclude без совпадений может
оставить все приложения в VPN с предупреждением. Не считайте такой результат
успешной проверкой списка.

Для возврата к обычному профилю штатно отключите VPN, задайте `apps_mode=all`,
удалите локальный список `apps` и переподключитесь. Проверьте восстановление сети
обоих приложений. Детали: [CONFIG](../manuals/CONFIG.md),
[матрица клиентов](../reference/CLIENT-CONFIG-MATRIX.md).
