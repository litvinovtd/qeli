# Личные, домашние и гостевые профили доступа

Разделите назначения и учётные данные семьи или команды. Профиль определяет точку
входа, пользователь — личность и разрешения, группа — значения лимитов/ACL по умолчанию.
Один общий пароль не обеспечивает индивидуальный отзыв доступа.

[Каталог и подготовка](README.md) · [English](../../eng/scenarios/ACCESS-PROFILES.md)

## Спроектируйте роли

| Роль | Профиль | Разрешённое назначение | Локальная политика клиента |
| --- | --- | --- | --- |
| Личный ноутбук | `personal` | Интернет по политике владельца | Full-tunnel, tunnel DNS |
| Домашнее устройство | `home` | `192.168.50.0/24` | Split-tunnel, системный DNS |
| Гость | `guest` | Только сервис-хост `192.168.50.30/32` | Split-tunnel, системный DNS |

Подготовьте три полных серверных профиля по [MULTI-PROFILE](MULTI-PROFILE.md), с
разными TUN/пулами/портами. Для personal настройте [FULL-TUNNEL](FULL-TUNNEL.md),
для home/guest — [HOME-LAN](HOME-LAN.md), включая обратные маршруты всех их пулов.
Не включайте client-to-client там, где он не требуется.

## Создайте отдельные учётные записи

```sh
sudo -u qeli qeli add-client alice-laptop --profiles personal --config /etc/qeli/server.conf
sudo -u qeli qeli add-client family-tablet --profiles home --config /etc/qeli/server.conf
sudo -u qeli qeli add-client guest-phone --profiles guest --config /etc/qeli/server.conf
```

Сохраните сгенерированные секреты приватно, выдавайте каждую ссылку только её
владельцу. Дополните существующие секции `users.conf`, не заменяя хеши:

```ini
[group:home]
allowed_networks = 192.168.50.0/24
max_sessions = 2

[group:guests]
allowed_networks = 192.168.50.30/32
max_sessions = 1
bandwidth_limit_mbps = 5

[user:alice-laptop]
profiles = personal
max_sessions = 1

[user:family-tablet]
profiles = home
group = home
route = 192.168.50.0/24

[user:guest-phone]
profiles = guest
group = guests
route = 192.168.50.30/32
```

Групповые лимиты наследуются **каждым** пользователем, это не общая квота группы.
Положительные личные лимиты и непустой личный ACL могут переопределить группу:
удалите ненужные старые переопределения при смене роли. `profiles` задавайте
пользователю явно; пустое/неограниченное значение не означает запрет всех входов.

`allowed_networks` — разрешающий список IP/CIDR, не фильтр портов. Гость из примера
имеет доступ к разрешённому хосту, а не автоматически только к HTTPS. Порты,
управляющие сервисы, metadata endpoint VPS и изоляцию LAN ограничивайте firewall.
`0.0.0.0/0` разрешает также частные IPv4-адреса; это не безопасный синоним
«только публичный интернет». Для IPv6 ACL задаётся отдельно.

## Клиенты и проверка

У личного профиля задайте `gateway=true`, `dns=tunnel`; у home/guest —
`gateway=false`, `pull_routes=true`, `dns=system`. При необходимости собственных
туннельных DNS добавьте их адреса в разрешённые назначения.

После проверки полного конфига и применения настроек испытайте **каждую** роль:
нужный профиль доступен, чужой отклоняется, разрешённый сервис работает, соседний
LAN-хост и управляющие порты недоступны гостю. Проверьте также IPv6 и предел устройств.
`max_sessions` ограничивает устройства одного пользователя: новое устройство может
вытеснить старую сессию; это не обещание отвергать всякий новый вход.

## Отзыв и откат

Для отзыва выключите нужного пользователя в панели/INI и завершите его активные
сессии штатным управлением; проверьте, что новое подключение запрещено. Не меняйте
общий пароль всех устройств. При откате восстановите прежние поля/группы и
пользовательские разрешения, сохранив права базы и не открывая гостям дополнительные
профили. Справочники: [CONFIG](../manuals/CONFIG.md), [PANEL](../manuals/PANEL.md).
