# UDP auto и дефолты Recordizer: аудит установки 31 октября 2026

Изменения подготовлены для **0.8.4, ещё не опубликованы**. Бинарники в
`release/dist` этой проверкой не заменялись.

## Найдено и исправлено

Полный `install-qeli-server.sh` уже задавал UDP rmem/wmem max 16777216, чего
достаточно для максимального запроса auto 16 МиБ. У `.deb` и обычного обновления
через него такого шага не было. Теперь пакет включает:

- `/usr/lib/sysctl.d/60-qeli-udp-buffers.conf` с лимитами 16 МиБ для загрузки ОС;
- `/usr/lib/qeli/udp-buffer-limits`, вызываемый из `postinst configure` и при
  установке, и при обновлении. Он повышает только меньшие runtime-лимиты и
  проверяет readback. Более высокие текущие значения сохраняются;
- зависимость `procps`, предоставляющую `sysctl`.

Полный установщик также перестал понижать более высокие rmem/wmem max:
они сохраняются в его persistent-файле и в recovery receipt.
Его проверка зависимостей теперь явно устанавливает `procps`, если отсутствует
`sysctl` — в том числе при установке из отдельного бинарника на минимальной ОС.
Пакетный helper не меняет `rmem_default`/`wmem_default`, qdisc, TUN или конфиги Qeli.
Прежние дополнительные настройки полного установщика не удалены.
На Linux raw `SO_RCVBUF` обычно вдвое больше запроса: для запроса 16 МиБ
не требуется повышать `rmem_max` до 32 МиБ.

До изменения sparse parser давал Recordizer `off`, новые профили — `prefer`,
а batching — `timed`. Теперь общий дефолт — **`prefer` + `opportunistic`**:
Rust/serde/INI, панель и 14 серверных профилей в пяти поставляемых шаблонах
согласованы. Три клиентских шаблона не фиксируют UDP receive и не вводят
несуществующие клиентские Recordizer-ключи. Режим приходит с сервера после AUTH.

Явные `off`, `required`, `timed`, fixed buffer и `0` при обновлении не заменяются.
Если ключи отсутствовали, новый parser применит новые дефолты при следующей сессии.
`prefer` включает PACKET_MUX_V1 с совместимыми клиентами, а не запрещает legacy-клиентов.

## Проверка

Изолированная проверка выполняется только на сборочной VM302, raw:
`/opt/qeli-udp-install-defaults-20261031-r01`.

Итог: **97 Python/chroot-тестов, 23 уникальных Rust unit-теста и 11 проверок шаблонов
реальным CLI прошли**. Из них 10 — новые defaults/helper/postinst tests,
18 — binary installer, 19 — dependency admission, 11 — tuning/recovery,
21 — updater, 17 — реальный Makefile/dpkg lifecycle, 1 — RU/EN default tables.
Rust: фильтр Recordizer включил 23 теста; входящий в него profile-default test
также повторён отдельно и второй раз в число уникальных не засчитан.

- Helper и настоящий `postinst` проверяются в private chroot с подменённым
  `sysctl`: первая установка, повторное configure/upgrade, сохранение конфигов,
  повышенные лимиты, отказ записи, успешная команда без изменения значения,
  невозможность прочитать прежний размер.
- Lifecycle-тест собирает инертные `.deb` реальным Makefile и устанавливает/
  обновляет их реальным dpkg в chroot: проверяются доставка helper/sysctl.d,
  выполнение hooks и сохранение состояния. CLI, debconf/systemctl и sysctl — seams;
  это не запуск production-демона и не реальная перезагрузка.
- Regression-проверки полного установщика сохраняют recovery receipts и
  подтверждают, что потолок 64 МиБ не понижается до 16 МиБ.
- Source/docs guards проверяют шаблоны, UDP auto и таблицы дефолтов RU/EN.
  Новый тест включён в Linux CI.

Два первых запуска остановились **до Rust-компиляции** по gate свободного места.
Отказы сохранены в `result.json` и `result-r2.json`. Удалялись только новые,
созданные этой проверкой копии промежуточного кэша. Следующая проверка использует
read-only нижний кэш и отдельный writable overlay в приватном mount namespace;
старые кандидаты, исходники, логи и результаты не перезаписываются.

Release integration-test `config_examples` не был засчитан как PASS: его test
harness `panic=unwind` конфликтует с release-зависимостями `panic=abort`
(лог `r3-examples-integration.log` сохранён). Это не скрыто и production panic
policy не менялась. В том же запуске успешно собрался native CLI; им выполнены
`check-config` пяти серверных и шести клиентских шаблонов без запуска VPN.
Для private-копий подставлены документированные тестовые ключи/short_id и
пустая private users DB. Исходный отказ REALITY placeholder также сохранён
в `cli-check-result.json`; проверка подготовленных копий — `cli-check-result-r2.json`.

## Ограничения

Обычная Linux-установка получает подходящие лимиты без ручного редактирования
клиента и сервера **при отсутствии явных ручных overrides**. Администраторские
sysctl.d-файлы могут переопределять пакетный файл при reboot; контейнер/ядро может
запретить изменение. В таких случаях выводится предупреждение, а окончательный
размер проверяется по диагностике живого сокета, не по запрошенному лимиту.

Нельзя обещать, что любой сервер получит по 16 МиБ каждому worker: действует
RAM-бюджет. Android/iOS и роутеры сохраняют свои ограничения ОС/прошивки.
Устранение всех потерь UDP, CPU steal и изменение скорости этой проверкой
не заявляются. VM300/301 и Proxmox не изменялись, релиз не публиковался.
