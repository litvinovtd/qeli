# Q25-F152: матрица INI и полный рестарт для logging

1 октября 2026. База: `8ce31599`. D07 остаётся **IN_PROGRESS**.

Сверка INI-кодека показала парность чтения и записи 150 фиксированных ключей: 7 в `[auth]`, 23 в `[web]`, 4 в `[logging]` и 116 в `[profile:*]`. Существующий `exhaustive_round_trip_every_server_key` содержит каждый из них и сравнивает структурные значения после повторного разбора. Повторяемые `listen` и `route`, а также ключи резервирования адресов присутствуют в том же fixture и дополнительных тестах. Это закрывает слой parse/serialize для фиксированных полей; runtime-применение всех полей ещё не доказано.

В runtime обнаружено расхождение для `[logging]`: `level`, `file` и `time_format` читаются до основного конфига при запуске supervisor и worker. После сохранения изменённого INI панель не помечала их как startup-only, поэтому прямой `POST /api/server/restart` допускал перезапуск только worker. В контейнере «Apply & Restart» при недоступном systemd тоже мог перейти на worker restart. В обоих случаях логирование supervisor оставалось прежним, а worker получал новые настройки.

`needs_full_restart_for_config` теперь сравнивает эти три поля с конфигом supervisor при старте. Ответ сохранения и worker-restart API требуют полный рестарт; контейнерный запасной путь не применяется. `logging.format` остаётся документированным инертным полем совместимости: значение `json` не делает JSON-конфиг и не меняет вывод логов, поэтому рестарт сам по себе ничего для него не исправляет.
