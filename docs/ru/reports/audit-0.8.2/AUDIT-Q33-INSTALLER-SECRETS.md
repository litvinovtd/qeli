8 октября 2026. F427–F431 / Q33-F030–F034. Q33 остаётся IN_PROGRESS. Здесь проверены публикация секретов/web-конфига и полный UDP control flow с явными CLI/systemctl/kernel seams, не настоящая установка VPN.

## Находки и исправления

- **F427 / Q33-F030:** запись summary и per-user файлов следовала symlink; wildcard chmod менял права внешнего файла. Имена генерируемых файлов проверяются до зависимостей и повторно на входе secret-stage. Запись идёт в приватные временные файлы того же каталога с rename; общий chmod удалён. Hardlink разрывается заменой файла без изменения внешнего inode. Новые links/summary создаются root0600. Сохранённые ссылки существующих пользователей копируются с теми же байтами в private0600: прежняя защита прав сохранена без chmod внешнего hardlink-файла.
- **F428 / Q33-F031:** summary обнулялся до создания пользователей, теряя полный предыдущий список при частичном отказе. Ошибка CLI/отсутствие ссылки после записи пользователя также теряли сгенерированный пароль. Теперь summary готовится отдельно до завершения обработки всех пользователей; старый список сохраняется при ошибке. Перед каждым add-client пароль записывается в root0600 INSTALL-PENDING journal; при успешном ответе туда добавляется ссылка. Отказ CLI или публикации link/summary сохраняет journal. После успешной публикации summary он удаляется. Аккаунты и отдельные ссылки уже могут измениться; pending entry не доказывает создание аккаунта. Это восстановимость, не атомарная установка/автоматический rollback пользователей.
- **F429 / Q33-F032:** web helper записывал через конечный inode конфига: ошибка записи могла обрезать его, hardlink менял внешнюю копию; failed awk оставлял temp. Теперь используются зарегистрированный temp в том же каталоге, явная передача ошибки, сохранение владельца, mode600 и rename. Отказы awk/publish сохраняют старый конфиг и удаляют temp. Первичная генерация профиля, перезапись самим CLI и вся транзакция reconfiguration этим не закрываются.
- **F430 / Q33-F033:** backups имели одинаковое имя в пределах секунды и перезаписывали предыдущий backup. Config/summary backups теперь резервируют уникальное имя, создаются root0600 и сохраняют исходные байты. Два backup с одинаковым timestamp сохраняют обе версии.
- **F431 / Q33-F034:** для retained users сообщалось о новом REALITY short_id и устаревшей ссылке даже при UDP/fake TLS. Теперь уведомление рекомендует перевыпуск при изменении endpoint/profile settings; старый пароль не меняется, указаны previous summary backup/recovery journal.
