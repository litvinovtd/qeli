# Q25-F147: загрузка TLS PEM и неполная автопара панели

1 октября 2026. База: `ba06e7db`. D07 остаётся **IN_PROGRESS**.

Панель открывала `web.tls_cert` и `web.tls_key` через обычный `File::open` и передавала поток PEM-парсеру без проверки типа и размера. FIFO в этих путях мог ждать писателя и задерживать старт панели; большой регулярный файл загружался без установленного предела. Отдельно отсутствие одного из двух файлов автосозданной пары вызывало генерацию **обоих** файлов и замену уцелевшего ключа или сертификата.

Перед разбором PEM теперь открывается с `O_NONBLOCK` на Unix, проверяется открытый inode как обычный файл, а чтение ограничено 4 МиБ плюс один байт. Симлинк на обычный PEM по-прежнему допускается для ротации сертификатов. Проверка наличия автопары использует `symlink_metadata`: обе отсутствуют — создать новую пару; обе существуют — загрузить; существует только одна — отказ без замены и инструкция восстановить пару или удалить оба файла для осознанной ротации. Ошибка TLS оставляет HTTPS-панель выключенной по существующему обработчику, не меняя VPN-конфиг.

Проверка на изолированной лабе `.11`: пять тестов — создание и чтение новой пары с ключом `0600`, сохранение уцелевшего ключа, отказ для 4 МиБ + 1 байт, FIFO без ожидания, поддержка симлинка; `cargo fmt` и строгий Clippy библиотеки/CLI.
