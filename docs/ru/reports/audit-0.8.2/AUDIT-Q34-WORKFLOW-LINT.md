# Q34: постоянная проверка GitHub Actions

<!-- normative-sync: q34-workflow-lint-v1 -->

9 октября 2026. F488 / Q34-F042 закрыт в пределах проверки семантики workflow.

## Проблема и изменение

Предыдущий пакет F487 выявил ошибку job-level `env`, которую обычный разбор YAML
не обнаружил. После её исправления все четыре workflow уже проходили ручной
проверочный запуск. Оставался пробел: actionlint не входил в постоянный CI.
Это пробел контроля, а не новая ошибка клиентского парсера.

В CI добавлена обязательная job `workflow-lint`. Общий сценарий
`scripts/check_workflows.py` перечисляет все непосредственные `.yml` и `.yaml`
в `.github/workflows`, включая новые файлы. Отсутствующий или пустой каталог,
необычный тип файла, ошибка проверки или timeout приводят к отказу.

Официальные архивы и исполняемые файлы [actionlint 1.7.12](https://github.com/rhysd/actionlint/releases/tag/v1.7.12)
закреплены SHA256 отдельно для Linux x86_64 и Windows AMD64. Инструмент ставится
только в указанный каталог; существующий неподходящий файл не перезаписывается
и не запускается. CI использует `$RUNNER_TEMP/qeli-actionlint`. Глобальной
установки и выполнения самих workflow при проверке нет.

Локальный запуск из корня репозитория:

```sh
python scripts/check_workflows.py --install-dir /tmp/qeli-actionlint
```

Можно передать `--actionlint` с путём к уже полученному официальному бинарнику;
его SHA также проверяется. Внешние ShellCheck и pyflakes здесь отключены явно:
этот gate проверяет семантику Actions, контексты и выражения. Отдельный существующий
ShellCheck job сохраняет свой прежний охват; проверка каждого inline shell/Python
фрагмента и настройки branch protection этим пакетом не подтверждаются.

## Проверки

На Windows и Linux: по 11 unit-тестов допуска/отказа и по восемь сценариев
с настоящим инструментом. Пройдены загрузка и установка по закреплённому SHA,
повторное использование, четыре исходных и пять корректных workflow. Ошибочный
job-level `env`, новый некорректный `.yaml`, изменённый cached binary, пустой и
отсутствующий каталог реально отклонены. Unit-тесты дополнительно проверяют
подмену архива, несовпадение извлечённого файла, отказ сети, timeout и очистку
временного файла после неудачной атомарной установки. Синтетический unit binary
не исполняется; семантические проверки выполняет официальный actionlint.

На .11 использован собственный временный каталог. Точные входы и логи сохранены
в SHA-проверенный архив, его содержимое сверено, затем каталог и удалённая копия
архива удалены после проверки процессов, дескрипторов и mount points. Служба
активна, PID 777/845 и SHA установленного Qeli сохранены. .10 не использовалась.
Ошибка начальной локальной команды (неверный рабочий каталог) сохранена отдельно;
успешные запуски используют явный корень проекта.
