# Q25: DNS принадлежит конкретному поколению соединения

Дата: 23 сентября 2026. Baseline: `e9193f57`.
Q25-F061–F062 исправлены в указанных границах. Разделы 14/21/25 остаются **IN_PROGRESS**.

## Подтверждённые проблемы и исправления

**Q25-F061, P2 — cleanup мог сбросить DNS, который этот план не устанавливал.**
TCP/UDP и fallback guard вызывали `restore_dns_for(name)` независимо от `dns=off`,
пустого DNS-плана и успеха получения маркера. Setup помечал DNS начатым до попытки
применения. Поэтому маркер другого владельца с тем же именем давал право очистки
соединению, которое DNS не меняло. Запись простого маркера также перезаписывала
прежнего владельца без межпроцессной блокировки.

Теперь setup guard получает необязательный DNS lease до первой команды изменения DNS.
Только этот lease передаётся установленному TUN guard. Отключённый/пустой DNS-план
и отказ получить владение оставляют lease пустым: их teardown не меняет per-link DNS.
Частичное применение остаётся под владением setup guard и откатывается им. Успешная
очистка завершает lease один раз; повтор после ошибки маршрутов не использует новый
чужой маркер. Ошибки DNS сохраняются в общем отчёте и не снимают kill-switch.

Новые приватные `dns-link-v1-<boot>-<netns-device>-<netns-inode>-<ifindex>.state`
содержат версию, случайный token поколения и identity интерфейса. Это служебные записи
восстановления, не пользовательские конфиги; конфигурация остаётся INI. Стабильный
sidecar `.lock` удерживается всё время жизни lease. Конкуренция вызывает немедленный
отказ; существующий невосстановленный маркер не перезаписывается, живой lock не удаляется.
Неблокирующее получение обеспечивает `File::try_lock`
([Rust API](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock), стабилен с Rust 1.89).
Чтение маркера ограничено 2048 байтами. Linux отклоняет symlink, специальные файлы
и несколько hard links; неблокирующее открытие позволяет отказать FIFO без зависания.
Точная запись сверяется перед командой и перед удалением маркера.

**Q25-F062, P2 — сохранённое имя и отсутствие в sysfs не доказывали identity устройства.**
Переименованный/удалённый TUN мог получить замену под старым именем. Startup использовал
`Path::exists`, терял ошибки элементов каталога и превращал ошибки чтения маркеров
в пустые имена перед восстановлением. Старое имя не даёт права менять живой resolver.

Теперь каждая DNS/domain/revert операция наблюдает исходный fd через `TUNGETIFF`,
проверяет namespace самого устройства через `TUNGETDEVNETNS` и сравнивает boot/netns/ifindex
с lease. Проверки namespace выполняются до и после чтения имени/индекса. Обычный rename
сохраняет числовую цель; отключённый от удалённого устройства fd позволяет убрать
свой маркер без revert на заменившем его устройстве. Смена identity, ошибки metadata
или ioctl запрещают изменение и сохраняют запись. Семантика ioctl приведена в
[Linux tun.c](https://raw.githubusercontent.com/torvalds/linux/v6.12/drivers/net/tun.c).
`resolvectl` принимает числовой link и обращается к per-link API по индексу:
[исходник systemd](https://raw.githubusercontent.com/systemd/systemd/v256/src/resolve/resolvectl.c).

Startup больше не вызывает `resolvectl revert` только на основании файла-маркера.
Он пропускает живые locks и чужие boot/namespace, сохраняет живые/повторно использованные
индексы и удаляет маркер лишь при подтверждённом отсутствии индекса в текущем scope.
Ошибки lookup/read/iteration сообщаются; отказ проверки не считается отсутствием.
Восстановление старого resolver-файла из backup остаётся отдельным механизмом.

## Совместимость и восстановление администратором

Управление DNS на Linux теперь требует разрешённых `TUNGETIFF`/`TUNGETDEVNETNS`,
procfs metadata namespace и boot ID. Namespace ioctl требует CAP_NET_ADMIN в user
namespace владельца. Неподдерживаемая/запрещённая проверка отклоняет DNS setup;
`dns=off/system` и пустой DNS-план не получают lease и не выполняют эти DNS-проверки.

Старые `dns-resolvectl-*` не содержат namespace/generation identity. Startup сохраняет
их с диагностикой; конфликтующий legacy-маркер блокирует новое управление DNS.
Не обновляйте работающего владельца DNS на месте и не смешивайте старые/новые клиенты
для одного link. Для осиротевшего маркера остановите затронутого владельца, проверьте
реальный интерфейс и `resolvectl status`, восстановите DNS штатным сетевым менеджером
(либо явно выполните revert для проверенного Qeli-интерфейса), затем архивируйте/удалите
только этот `.state` или legacy-маркер. Не удаляйте `.lock` при работающем Qeli.
После аварии на внешнем постоянном интерфейсе может понадобиться такое восстановление;
обычный непостоянный TUN обычно исчезает, позволяя startup убрать маркер отсутствующего
индекса. См. [мануал §6.50](../../manuals/TROUBLESHOOTING.md).

## Открытые границы

Наблюдения и команда resolver не атомарны. Привилегированные внешние delete/move
и намеренный reuse ifindex после последней проверки остаются возможны. Подключённый
systemd-resolved должен обслуживать тот же namespace; identity сервиса/шины здесь
не доказана. Внешний менеджер также может заменить DNS на том же живом интерфейсе;
Qeli не сохраняет/восстанавливает его прежние per-link настройки. Locks координируют
эту реализацию Qeli, но не старые клиенты и произвольные привилегированные записи в state directory.

Route cleanup всё ещё делает flush по настроенному имени: ему нужен отдельный проход
identity с сохранением независимой очистки физических bypass-маршрутов. Выбор DNS-адресов,
sysfs при attach, имена parser/backend, общий deadline и Q14-F027 остаются открытыми.
Linux E2E, native certification и новый benchmark не выполнялись. План: 37 разделов,
19 IN_PROGRESS, 18 TODO, полного PASS нет.

Продолжение: [Q25-F063–F064](AUDIT-Q25-ROUTE-IDENTITY.md) добавляет проверки исходного
TUN и удерживаемого namespace в route cleanup с независимым physical cleanup.
Гонка после проверки и setup/roaming остаются открыты.

Продолжение: [Q25-F094/F095](AUDIT-Q25-RESOLVER-CONTEXT.md) фиксирует контекст шины/службы и адресата команд, проверяет реальный resolved и исправляет нестандартный DNS-порт. Исторические результаты выше не пересчитывались.

Продолжение: [Q25-F096/F097](AUDIT-Q25-DNS-MARKER-STORAGE.md) переводит DNS-маркеры на v2 с SO_NETNS_COOKIE и доверенным открытым каталогом, проверяет SIGKILL/restart с реальным resolved. Исторические цифры и v1-контракт выше описывают прежний снимок; актуальная эксплуатация — в §6.50 TROUBLESHOOTING.
