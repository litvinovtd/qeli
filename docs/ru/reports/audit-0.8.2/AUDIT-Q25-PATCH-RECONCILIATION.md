# Q25-F201 — сверка архива патчей и возраста свидетельств

1 октября 2026. Снимок исходников: `003405fd` (`dev`). Продуктовый код не менялся; пользовательские изменения в `CHANGELOG.md` и `qeli/src/web/templates/users.html` не затрагивались.

## Архив патчей

Read-only проверка всех 625 файлов `*.patch` в каталоге артефактов `C:/Users/litvi/OneDrive/Documents/qeli/` выполнялась против рабочего дерева с помощью `git apply --numstat`, `git apply --check` и `git apply --reverse --check`. Получено 295 невалидных или фрагментарных файлов, 265 валидных патчей, которые уже не накладываются ни в одном направлении, 39 точно обратимых (содержимое уже присутствует), 22 применимых вперёд и 4 неоднозначных. Проверка ничего не применяла. Результат классифицирует форму и контекст, но не необходимость исправления; изменённый после создания патча код часто даёт отказ в обоих направлениях.

Среди 50 датированных патчей `audit-debt-20260924/25`: 47 изменились вместе с кодом, 1 точно обратим и 2 не имеют корректного формата. Для 21 из 48 формально валидных патчей найден идентичный `git patch-id --stable` среди последующих коммитов. Это сильное свидетельство интеграции именно того diff, но не повторной runtime-проверки на `003405fd`. Два фрагментарных черновика, `server-forced-drop-phase/proposed.patch` и `tun-attach-context-phase/attach-index.patch`, не следует применять: текущие `WorkerLease`/`mark_complete` и `verify_sysfs_index` уже реализуют соответствующие изменения; их проверки описаны в [Q25-F130](AUDIT-Q25-SERVER-FORCED-DROP-LEASE.md) и [Q25-F123](AUDIT-Q25-TUN-ATTACH-CONTEXT.md).

Все 22 патча, применимые вперёд, относятся к раннему архиву. Применимость объясняется преимущественно контекстом добавления строк: уже существующие строки могут быть добавлены повторно. Например, `roaming-netns-rollout-gate.patch` предлагает буквальные `roaming.enabled = true` и `roaming = required`, а нынешний `scripts/roaming_netns_e2e.sh` намеренно параметризует оба значения и проверяет варианты. `roaming-packaged-configs.patch` предлагает `roaming.enabled = false`, тогда как текущие поставляемые серверные профили явно используют `true`, и `qeli/tests/config_examples.rs` проверяет этот контракт. Применение таких патчей изменило бы подтверждённое текущее поведение. Два ранних патча касаются пользовательского `CHANGELOG.md`; в этой сверке он не редактировался. Остальные ранние кандидаты (Android, Windows, telemetry, UDP) требуют проверки по текущему контракту при работе над соответствующим пунктом D08/D12/D13, а не пакетного `git apply`.

## Адресная сверка 22 применимых патчей и Windows selftest

После первичной классификации изучены отличающиеся строки всех 22 кандидатов. Два затрагивают `CHANGELOG.md` с пользовательскими изменениями: их не накладывали и не включали в кодовую сверку. Остальные 20 не выявили отсутствующего исправления в текущем коде: точные добавления Android path tests/поколений, UDP IPv6 batch, release sync и socket selftest уже присутствуют; Android dispatch теперь подтверждает команду через `TransportCoreEventDispatcher`, а кодек дополнительно обрабатывает `same_network_nat_failure` и строго проверяет network token. Старый rollout-патч с `roaming.enabled = false` противоречит нынешнему проверяемому контракту поставляемых примеров. Dashboard уже содержит счётчики и исключает выключенные профили; его отличающиеся строки связаны с текущими названиями и локализацией. Windows route-код сохраняет выбранный источник первым и явно сообщает о неполном rollback вместо подавления ошибки. Это статическое заключение по архивным diff и текущим unit/selftest, а не сертификат Android-эмулятора или Windows VM.

При проверке Windows обнаружена самостоятельная проблема диагностики: `dotnet build qeli-win/QeliWin/QeliWin.csproj --no-restore -v:q` проходит без предупреждений, но `selftest` прерывался исключением из `VpnTunnel.RunRoamingCapabilitySelfTest`: закоммиченная `qeli.dll` ниже ABI 1.16. Поэтому DNS/route проверки даже не начинались. `CliRunner.SelfTest` теперь изолирует группы: несовместимый native core помечается FAIL, остальные группы выполняются, общий exit остаётся 1. Повторный прогон подтвердил 3/3 DNS lifecycle и 6/6 roaming route/path проверок PASS, итог `1 FAILED` с явным сообщением ABI 1.16; Wintun probe также PASS. `python native-libs/provenance.py --check` подтверждает `STALE NATIVE CORES` (recorded `85f2f17e…`, actual `737e803d…`). Это открытый D11: native cores требуют воспроизводимой A/B пересборки и обновления provenance до полного PASS. Системные Windows route/packet сценарии по решению пользователя остаются SKIPPED.
