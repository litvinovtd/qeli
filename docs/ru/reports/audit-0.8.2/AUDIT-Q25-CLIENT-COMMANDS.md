# Q25: ограничения клиентских системных команд и проверка IPv4-защиты

Дата: 23 сентября 2026. Исходная точка: `0c5cd0f7`.
Q25-F035/F036 исправлены в описанных границах. Разделы 22/23/25 остаются **IN_PROGRESS**.

## Находки

**Q25-F035, P2 — маршрутные и firewall-команды клиента обходили ограниченный исполнитель.**
В `client/route.rs` оставались прямые `std::process::Command::output`: initial setup,
roaming, снимки маршрутов, cleanup/orphan, TUN/pushed/local routes и hook discovery.
Такой процесс мог бессрочно удерживать route operation mutex; stdout/stderr собирались
без прикладного лимита. В `killswitch.rs` тот же дефект затрагивал запуск iptables,
проверку наличия бинарника, чтение default route и инвентаризацию server allows.
Gateway делегирует firewall-команды helper `killswitch::ipt`; его WAN discovery уже
был ограничен в предыдущем проходе.

**Q25-F036, P1 — ошибка IPv4-проверки позволяла пропустить обязательную защиту.**
Если IPv4 firewall отсутствовал или не установился, проверка `ip -4 route show default`
возвращала `false` как для отсутствующего маршрута, так и для ошибки запуска/статуса.
При работающей второй семье или отсутствии требований к ней клиент мог сообщить об
установленном kill-switch, хотя IPv4-путь не был проверен и оставался незащищённым.
Новый таймаут также попадал бы в эту ветку без отдельного исправления политики.

## Исправление

Все места запуска команд в `route.rs` и `killswitch.rs` используют существующий
`system_command::Command`. Он задаёт срок **15 секунд на команду** и отдельные лимиты
**16 МиБ stdout и 16 МиБ stderr**. Частичный вывод после превышения лимита не поступает
парсеру. Общий механизм завершает дочерний процесс, на Linux также его группу, и ждёт
выхода; синхронная последовательность apply/rollback/Drop сохранена. Дублирующий
исполнитель и новые INI-параметры не добавлены. Gateway получает те же ограничения
через общий iptables-helper; алгоритм его полного rollback этим не переписывался.

Таймаут не означает отсутствия эффекта. Начальный physical add с неизвестным результатом
остаётся pending без права delete; owner закрывает admission. Провал pre-query запрещает
запись. Выполненный flush может завершиться успешно после независимого подтверждения
пустого состояния, но таймаут/overflow подтверждающего query сохраняет ошибку и требует
повтора. Очистка другой IP-family продолжается. Проверки firewall не объявляют
недоступную цепочку отсутствующей и не начинают слепой flush.

Если IPv4-часть kill-switch не установлена, только успешный пустой список default routes
позволяет обойтись без неё. Ненулевой статус, ошибка запуска, timeout, overflow и непустой
вывод требуют защиты. Существующий явный `allow_ipv4_leak = true` сохраняет своё значение;
при нём лишний IPv4 probe пропускается. IPv6-проверка через `/proc` этим этапом не менялась.

## Проверки и воспроизводимость

20 новых постоянных тестов вызывают production command boundaries с thread-local
подменой программ/ответов. Таймаут и overflow получены от реальных конечных дочерних
процессов с уменьшенными тестовыми лимитами; состояния маршрутов моделируются.
PATH и окружение родительского процесса не меняются, настоящие ip/firewall не запускаются.

Контроль чувствительности выполнен отдельно от основной матрицы:

- Возврат прежних двух выражений IPv4-политики: **3 теста FAIL**; с исправлением PASS.
- Временная замена коллектора на неограниченный std backend, только конечные fixtures:
  **9 тестов FAIL / 11 PASS**. Это mutation control общего механизма, а не прогон всего
  проекта на baseline commit. Production-файлы восстановлены после эксперимента.
- Полный набор: **1163 host unit + 52 editor/policy + 7 examples + 12 server INI =
  1234 Rust tests PASS**. Существующие проверки kill/reap, обеих труб и Linux process
  group сохранены; Linux-only проверки здесь кросс-компилируются, не исполняются.

Девять команд матрицы и RU/EN docs gate проходят. Rust 1.98.0; прежнее исключение Clippy
`chunks_exact_to_as_chunks` сохранено, новых исключений нет. Имеющиеся no-feature/

## Границы и следующий проход

15 секунд — deadline отдельной команды, не общий предел setup/cleanup/reconnect.
Команды и проверки последовательны; mutex удерживается во время операции, kill/reap
может ожидать kernel. Синхронный адаптер не превращает вызовы из async handlers в
неблокирующие. Новый benchmark не запускался, влияние дополнительных запусков runtime
на скорость setup не измерено.

Для TUN/pushed/local route paths изменён только исполнитель, не унифицированы правила
ownership и постусловий. Далее: эти операции, общий gateway rollback и изоляция
глобального состояния; Q14-F027 TUN workers/FD, общий preflight deadline, Linux E2E,
постоянный crash recovery, policy tables/VRF и native certification остаются открытыми.
Нет новых измерений throughput и заявления о завершении полного аудита.

Предыдущий этап: [начальная установка и flush](AUDIT-Q25-SETUP-FLUSH.md).

Следующий проход: [TUN/TAP и route_local](AUDIT-Q25-TUNNEL-ROUTES.md). Уточнение call graph: старые apply_pushed_routes/apply_local_networks не вызывались; активные pushed/local routes уже применялись через NetworkPlan. Неиспользуемые дубли удалены в следующем этапе.
