# Q25-F134: NAT66 не выпускает пакет через другой WAN

25 сентября 2026. База: `3a79c47a`. D06 остаётся **IN_PROGRESS**.

## Дефект и исправление

MASQUERADE и разрешающий FORWARD в режиме `nat66` были привязаны к выбранному WAN,
но не было запрета для другого выходного интерфейса. При разрешающей политике
хостового FORWARD либо чужом разрешающем правиле пакет из TUN мог выйти через
другой WAN без NAT66, сохранив ULA-адрес клиента. Проверка существования WAN при
запуске и отказ от неоднозначного auto-WAN не закрывали смену маршрута позднее.

Для `nat66` до остальных разрешений добавлен обязательный per-profile
`ip6tables -I FORWARD 1 -i <tun> ! -o <wan> -j DROP` с точным ownership tag.
Правило охватывает и аутентифицированные `client_subnet` вне pool. Если его
нельзя установить и проверить, профиль отказывается запускаться; rollback
сохраняет правила для повторной очистки. `route`/`manual` не изменены: для
LAN и site-to-site требуется их свободная маршрутизация.

## Проверки

На Linux `.11` прошли Rustfmt, 16/16 тестов `server::nat`, строгий Clippy и
сборка бинарника. Отдельный пакетный опыт в новом NET/mount/PID namespace
с политикой `FORWARD ACCEPT` подтвердил: до guard UDP-пакет `fd42::2` приходит
на чужой `wan1` без MASQUERADE; с guard не доходит, счётчик DROP равен 1;
через выбранный `wan0` пакет приходит с NAT66-адресом `2001:db8:1::2`.

Настоящий TCP worker в другом изолированном namespace установил guard выше
обоих разрешающих FORWARD, прошёл startup, отказ второго worker, rejected
reload и stop; точные IPv4/IPv6 правила, forwarding, TUN и маршруты после
остановки совпали с исходными снимками. Установленные службы `.11` и `.10`
не менялись.

## Остаток

Правило сопоставляет **имя** WAN, а не неизменный ifindex. Удаление устройства
и повторное использование имени, mixed iptables/nft backend и действия другого
root остаются границей D06/D10. IPv4 NAT44 имеет аналогичное отсутствие
запрета чужого WAN, но там одновременно допускается маршрутизация в сети за
сервером; до отдельного решения контрактов нельзя ставить безусловный DROP
без риска сломать действующую конфигурацию. Этот случай остаётся D06.

Продолжение 2 октября 2026 — Q25-F215 в [текущем реестре](../../plans/AUDIT-DEBT.md): 4 mixed IPv4/IPv6 backend, настоящие TCP NAT44/NAT66 и UDP route с изменением default/policy routes и RFC1918/CGNAT/public-LAN дали 204 checks PASS. [Packet evidence](../../../../release/certification/evidence/server-route-policy-20261002.json). Runtime-маршруты при сохранении устройств проверены в указанном объёме; непрерывная WAN identity при повторном использовании имени остаётся D06. Исторические открытые статусы выше описывают прежний снимок.
