# Q14/Q33: доверие прочитанному конфигу для Linux-команд

Дата: 23 сентября 2026. Исходный коммит: `e8a78b90`. Разделы 14 и 33: **IN_PROGRESS**.

## Находки и исправления

**Q33-F001, P1 — проверка прав другого файла, чем тот, из которого взяты команды.**
При запуске Linux конфиг сначала читался и разбирался, затем его путь открывался ещё
раз для разрешения `post_up`, `post_down` либо `auth.password_command`. O_NOFOLLOW и
fstat при втором открытии не связывали права с первым чтением. Локальный участник,
способный подменить путь, мог предоставить недоверенные команды для разбора, затем
вернуть доверенный файл до проверки. Поздний chmod также мог разрешить команды,
уже сохранённые в памяти. Находка не предполагает права панели менять shell-поля.

Общий загрузчик config_source читает и проверяет один файловый дескриптор. Для команд
требуется обычный файл без symlink, с владельцем root либо эффективным UID процесса,
без group/world write. Метаданные сравниваются до и после чтения; обнаруженное
изменение содержимого, владельца или прав отклоняет загрузку. Чтение ограничено
исходной длиной плюс один байт, поэтому непрерывное дописывание не продлевает его
бесконечно. Это не абсолютный лимит размера уже существующего большого файла.

O_NONBLOCK позволяет отклонить FIFO до чтения, не зависая в open. Для совместимости
symlink на обычный конфиг допускается для работы без команд; разрешение на команды
всегда запрещено, даже если путь изменился перед повторным открытием. Некорректный
UTF-8 отклоняется. На неподдерживаемой платформе команды запрещены; native GUI release
libraries этот загрузчик Linux runtime не включают.

Загрузчик используется при старте клиента, worker, supervisor и чтении по SIGHUP.
Hooks и password_command получают неизменяемое разрешение вместе с исходными данными.
Запрещённый hook игнорируется, запрещённый password_command останавливает запуск
клиента. Повтор профиля не получает доверие через изменённый путь. SIGHUP по-прежнему
обновляет только пользователей/brute-force settings, не команды и не разрешение hooks.
После исправления владельца/прав нужен новый запуск клиента/worker. Удалены старая
проверка по пути и разрешающая non-Linux заглушка; дублирования проверки между клиентом
и сервером больше нет.

**Q14-F019, P2 — корректная очистка зависела от позднего состояния пути конфига.**
При остановке сервер заново открывал файл, решая, можно ли выполнить сохранённый
post_down. Удаление или изменение прав могло молча пропустить очистку запущенного
поколения. Снимок готового поколения теперь хранит точную команду вместе с данными
интерфейсов/pools. Очистка забирает его однократно и использует исходное разрешение,
независимо от удаления/замены пути. Редактирование файла не отзывает уже подготовленную
очистку.

## Проверка

- Десять новых переносимых тестов: точный UTF-8/CRLF, Unix owner/mode policy, подмена
  пути до/после чтения, неизменность allow/deny при повторах, изменение содержимого
  и прав во время чтения, принудительный запрет symlink, ошибочный UTF-8, отсутствующий
  файл и каталог. В Windows race-fixtures используют внедрённый маркер readonly;
  это не исполнение проверки Linux ownership.
- Три новых Unix-теста проверяют реальные symlink, chmod и FIFO. Один новый Linux-тест
  жизненного цикла проверяет, что поздний chmod не разрешает post_down при повторе
  профиля. Существующий тест однократной очистки готового поколения теперь удаляет
  загруженный конфиг перед вызовом hook. Выполнен cross-check; **Linux-тесты не запускались**.
- **803 host unit + 52 editor/policy + 7 examples + 12 server INI = 874 Rust tests PASS.**
  Linux all-targets Clippy PASS с прежним исключением chunks_exact_to_as_chunks в
  неизменённом ndp_proxy.rs. Standalone Linux client и minimal FFI checks PASS.
  Rustfmt, diff и девять проверок документации PASS.
- Live TUN/firewall, внешние shell-команды, SSH, перезапуск служб и бенчмарк не запускались.
  Исполнены только изолированные host-fixtures; Linux marker-tests hooks ожидают
  запуска на Linux.

## Что осталось

Закрыта гонка между раздельным чтением и проверкой пути, а не вся цепочка доверия
скриптам. Скрипты, зависимости и привилегированные писатели остаются ответственностью
оператора. Сравнение метаданных не является атомарной транзакцией против любых
злонамеренных изменений на месте. Отдельных этапов требуют общие лимиты размера
конфига, installer/update/restore, загрузка notification cache и владение задачами
при запуске supervisor/клиента.

Продолжение: [аудит команды пароля](AUDIT-Q25-CREDENTIAL-COMMANDS.md) исправляет блокирующий
неограниченный password_command, раскрытие stderr и раннюю отмену по сигналу.
Следующий [аудит файла/статуса](AUDIT-Q25-PASSWORD-FILES.md) также ограничивает password_file
и дожидается клиентских фоновых задач перед final. Network rollback и Linux runtime/
signal/systemd integration ещё открыты. Разделы 14/33 и полный аудит не завершены.
