# Q25-F176: строгая загрузка Android profile store

1 октября 2026. База: ebd15feb. D08 остаётся **IN_PROGRESS**.

При загрузке Android отсутствующий либо неверного типа массив profiles подменялся пустым JSONArray. После этого Activity создавала шаблонный профиль и сохраняла его, перезаписывая исходный повреждённый store. Пустой массив и активный индекс вне диапазона также не считались ошибкой данных. Отдельно AES-GCM и legacy Tink store декодировали plaintext через заменяющий UTF-8 decoder: неверные байты внутри credentials/INI могли превратиться в U+FFFD без явного отказа.

Загрузка теперь требует 1..256 профилей и допустимый активный индекс, прежде чем менять живой список. Неверный контейнер попадает в ранее добавленный режим отказа: исходные данные не перезаписываются обычными действиями. Оба пути расшифровки используют общий строгий UTF-8 decoder; plaintext-буфер после декодирования очищается. Формат пользовательского конфига остаётся INI; JSON здесь является контейнером encrypted store.

Проверки: Android compileDebugKotlin и 156 JVM-тестов прошли с проверенной host DLL; два новых теста подтверждают отказ на неверном UTF-8 и сохранность корректного Unicode; git diff --check прошёл. UI fault-injection на Android-эмуляторе для повреждённого store не выполнен. D08 остаётся открытым для конкурентных транзакций, других адаптеров и reconnect.
