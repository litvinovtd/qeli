# Q25-F146: конкурентная запись серверного INI

1 октября 2026. База: `0bef4299`. D07 остаётся **IN_PROGRESS**.

Панель держала только внутрипроцессную блокировку на время сохранения INI. Отдельная команда `qeli set-web-password` вообще не брала блокировку: одновременные записи могли прочитать одну ревизию и последней публикацией молча стереть другую. Восстановление backup также не участвовало в межпроцессной блокировке. Дополнительно `exact` restore удалял `server.conf.lock`, а архив мог заменить lock-файл новым inode; участники `flock` после этого синхронизировались по разным файлам.

Пять путей записи INI в панели (Quick Start, форма, сырой INI, история, настройки блокировок), CLI и restore теперь держат один sidecar `FileLock` от первого чтения до публикации. Панель ждёт lock в `spawn_blocking` не дольше 5 секунд; restore ждёт в своём blocking worker в пределах общего 60-секундного бюджета. Форма и сырой редактор привязывают ревизию к каноническому пути, на который взят lock, и отказывают при его смене. Новые архивы исключают `*.lock`; старые lock-файлы из архива игнорируются при публикации, `exact` сохраняет активные lock-файлы.

Проверка на изолированной лабе `.11`: 35 тестов редактора (включая новый тест двух конкурирующих писателей), 23 теста backup, 2 штатно ignored; строгий Clippy для библиотеки и CLI, сборка CLI и проверка: удерживаемый `flock` вызывает таймаут `set-web-password` без изменения INI, после освобождения запись проходит. Логи: `configlock4.log` (тесты и Clippy), `configlockcli.log` (сборка CLI), `configlockcli2.log` (валидный INI, отказ при lock и успешная запись) в `C:/Users/litvi/OneDrive/Documents/qeli/audit-debt-20260925/server-nat44-egress-phase/`. Первую сборку CLI ограничил заполненный диск лабы; после удаления только нашего incremental-кэша повторная сборка прошла. Первая положительная CLI-проба использовала неполный тестовый INI и получила ожидаемый отказ парсера; повтор с валидным профилем прошёл. Попытка `clippy --all-targets` в частичной лабораторной копии не является PASS: тесты примеров требуют отсутствующие там файлы `release/`, а тестовый модуль TUN имеет существующие предупреждения Rust 1.97. Целевые тесты и строгий Clippy `--lib --bin qeli` выполнены отдельно.

Ограничение: обычный редактор по SSH не соблюдает advisory lock. POSIX `rename` не даёт атомарного compare-and-swap по содержимому файла; внешняя правка между последним чтением панели и публикацией ещё может быть перезаписана.
