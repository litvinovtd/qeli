# Q25: отключённый IPv6 и резервирование TUN всех Linux-клиентов

Дата: 23 сентября 2026. Исходная точка: `f5c5677c`.
Q25-F048–F049 исправлены в описанных пределах; разделы 17/18/25 остаются **IN_PROGRESS**.

## Находки и изменения

**Q25-F048, P2 — установленный ip6tables блокировал IPv4-клиент при полном отключении IPv6.**
Публичный engage требовал filter inventory обеих найденных утилит. При
`ipv6.disable=1` IPv6-утилита может присутствовать, но её таблица недоступна.
Клиент отказывал до установки IPv4-правил. Последующие refresh/cleanup также
не различали установленный бинарник и отключённую функциональность ядра.

Добавлен узкий источник положительного доказательства:
`/sys/module/ipv6/parameters/disable` должен содержать ровно `1` с необязательным
завершающим LF. Читается не более 17 байт; ошибка, включая ошибку после префикса
`1`, отсутствие, пустой/иной/избыточный вывод не подтверждают отключение.
Проверка не изменяет sysfs/sysctl. Полностью отключённая семья не участвует в
обнаружении ip6tables, адресной проверке kill-switch, refresh и cleanup.
Общий helper также используется gateway при обнаружении IPv6 firewall.

Это параметр функциональности модуля, а не интерфейсный `disable_ipv6` и не
отсутствие глобальных адресов. Официальная [документация ядра](https://www.kernel.org/doc/html/latest/networking/ipv6.html)
описывает эти режимы раздельно; [исходник ядра](https://github.com/torvalds/linux/blob/master/net/ipv6/af_inet6.c)
объявляет module parameter `disable` как integer с доступом 0444.
Ошибки неизвестного состояния по-прежнему запрещают обход проверки firewall.
IPv4-конфликты/ошибки inventory и namespace lease не обходятся этим исключением.

**Q25-F049, P2 — клиенты без kill-switch не резервировали TUN на срок сессии.**
Предыдущий lease приобретался только при включённом kill-switch. В частности,
`dev_attach` допускает открытие очереди внешнего multi-queue TUN: отдельные
процессы могут подключиться к одному имени без ветки reclaim чужого устройства.
Локальные владельцы routes/gateway/exit не координируют эти процессы; одинаковое
имя также совпадает в firewall selectors. При обычном create уже были проверки
чужого устройства, поэтому этот отчёт не утверждает, что они всегда обходились.
В reconnect gap отсутствие интерфейса также не означает отсутствие живой сессии.

Механизм перенесён из `client/killswitch/lease.rs` в общий
`client/network_lease.rs`. Старый отдельный модуль удалён.
Все Linux-клиенты сначала резервируют `qeli.client.tun:<dev>`; защищённые —
дополнительно прежнее `qeli.client.kill-switch`. Имя второго сохранено для
совместимости с предыдущей версией. Ошибка второго захвата освобождает только
временную резервацию первого, сохраняя чужие владения.

Guard объявлен раньше adapter и удерживается через reconnect, cleanup и post_down.
Оба захвата происходят до восстановления DNS и настройки сети. Разные TUN без
конфликтующих kill-switch остаются независимыми. `dev_attach` резервирует право
клиентской сессии использовать имя; внешний владелец устройства не меняется,
право удаления не возникает. Серверы Qeli, старые клиенты и внешние инструменты
не участвуют в новом TUN-протоколе; kernel-проверки сохраняются.
Новые INI-ключи и JSON-конфиги не добавлялись.

## Проверка

**17 новых host-тестов**: шесть публичных сценариев kill-switch, три проверки
чтения sysfs evidence и восемь сценариев общего координатора lease.
Три сценария полного отключения IPv6: **FAIL на исходной логике → PASS после
исправления**, тела неизменны после rustfmt. Baseline включает новый тестовый
источник evidence, который исходная production-логика ещё не использовала.

Проверены запуск/refresh/cleanup без IPv6-таблиц, отсутствие лишней адресной
проверки, сохранение отказа при неизвестном состоянии и IPv4-конфликте,
ошибки/переполнение чтения, одинаковые имена с каждой комбинацией kill-switch,
независимые имена, rollback частичного захвата и release при unwind.
Координатор тестируется через тот же production helper с моделью атомарного bind.
Это не запуск двух настоящих VPN-процессов или внешнего multi-queue TUN.

**1270 host unit + 52 editor/policy + 7 examples + 12 server INI = 1341 Rust tests PASS.**
Все девять команд матрицы PASS, включая Linux all-targets Clippy, отдельные
client/server, minimal FFI, no-roaming, no-features и rustfmt.
Шесть прежних Linux socket-тестов и ignored child fixture перенесены; они
скомпилированы, но не исполнялись. Первый прогон выявил двойное подключение
host-тестов нового модуля через FFI; Linux cfg уточнён, матрица повторена.
Тестовые firewall-модели и IPv6 command-boundary проверки явно задают состояние
модуля на каждом тестовом потоке, поэтому реальный ipv6.disable=1 не меняет fixture.
Новых warning headlines нет. Rust 1.98.0, прежнее исключение
`chunks_exact_to_as_chunks` сохранено.

## Ограничения и следующий проход

Linux runtime с ipv6.disable=1, namespaces, iptables-nft/legacy, двумя процессами,
dev_attach и reconnect ещё не проверен. Отсутствующий модуль IPv6 не считается
подтверждённым отключением. Динамическое появление IPv6 при исходно пустом inventory
остаётся открытым. Никаких сетевых настроек хоста этот прогон не изменял.

Далее: неизвестное состояние владельцев sysctl, namespace identity его журнала,
неполный /proc при поиске TUN-владельцев, DNS/carrier globals, deadlines и crash
recovery. Общий sysctl journal пока не разделён по network namespaces: изоляция
lease не является доказательством изоляции всех подсистем. Native certification,
новый benchmark и полный аудит остаются незавершёнными.

Продолжение: [Q25-F050–F051](AUDIT-Q25-SYSCTL-OWNER-EVIDENCE.md) исправляет обработку неизвестных владельцев
и сохранение записей при недостоверной проверке sysctl; namespace identity ещё открыта.

Продолжение: [Q25-F052–F053](AUDIT-Q25-SYSCTL-NAMESPACE.md) разделяет журнал по network namespace,
проверяет PID/time контекст и описывает миграцию v1 → v2. Runtime-границы сохранены.

Продолжение: [Q25-F054–F055](AUDIT-Q25-TUN-ADMISSION.md) удаляет поиск TUN-владельцев
через неполный procfs и разрушающее recovery; создание первой очереди эксклюзивно.
Attach/teardown identity и Linux runtime остаются открыты.
