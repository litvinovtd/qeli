## Q25-F084, P2 — каждая команда продлевала настройку DNS

`setup_network_plan_dns` последовательно выполняет `resolvectl dns` и `resolvectl domain`.
Общий runner ограничивал каждую команду 15 секундами, но вторая получала новый срок.
Задержка проверки исходного TUN тоже не уменьшала следующий бюджет. В результате
настройка могла продолжать менять resolver после истечения ожидаемого общего срока.

Теперь deadline создаётся один раз при входе в настройку DNS, до валидации, файловых
проверок и приобретения lease. Обе команды используют `output_until` с этим deadline.
Перед проверкой target следующего шага исчерпанный срок возвращает `DNS setup command
budget exhausted`; истечение внутри target-пробы также не разрешает запуск команды.
Вывод по-прежнему ограничен 16 МиБ отдельно для stdout/stderr, процессы завершаются
и ожидаются общим runner. Нового ключа INI и изменений ABI нет.

Частичный отказ не удаляет marker и не выдаётся за отсутствие изменений. Lease передан
поколению до первой мутации; только его guard может выполнить последующий `revert`
с отдельным сроком команды 15 секунд. Исчерпанный setup не отнимает бюджет отката.
Если revert тоже не подтверждён, marker остаётся по прежнему контракту.

## Проверки

Три новые Linux-регрессии используют существующую последовательную фикстуру подмены
`resolvectl`; настоящий resolver и сеть хоста не вызываются. Первые два шага работают
через production runner с настоящими конечными дочерними shell/sleep-процессами.

1. DNS занимает 150 мс, domain — 700 мс при общем бюджете 600 мс. Domain прерывается,
   успех не возвращается, marker остаётся побайтно прежним. Отдельный owned revert
   проходит и удаляет marker только после подтверждения.
2. Уже истёкший бюджет не запускает ни target-пробу, ни команду.
3. Задержка второй target-пробы до истечения срока не позволяет запустить domain;
   журнал команд содержит только первое применение DNS.

Контрольная проверка вернула только прежний вызов `.output()` вместо
`.output_until(until)`, сохранив новые тесты и дополнительную проверку бюджета перед
шагом. Две регрессии (общий срок и задержка target) ожидаемо упали с exit 101; исходный
файл после проверки восстановлен побайтно. Это изолированная подмена старого поведения,
а не полный запуск старого коммита. Логи: `dns-budget-counterfactual/`.

PASS. Новые DNS-тесты относятся к Linux: **1935 обычных + 29 привилегированных PASS**.
**8 worker lifecycle E2E PASS**: TCP/UDP × off/manual/route/nat66. Worker E2E подтверждают

## Что этим не закрыто

15 секунд ограничивают допуск/ожидание команд в этой последовательности, а не весь
connect/disconnect. Синхронный файловый I/O, spawn, kill/reap и непрерываемое ожидание
ядра не получают жёсткого wall-clock предела. Реальный D-Bus/systemd-resolved context,
внешние DNS-запросы и удалённый resolver остаются отдельной проверкой D06/D10.
Бюджеты всей последовательности NAT/routes/kill-switch и прочие ожидания lock остаются
D05; полный раздел этим результатом не закрывается.
