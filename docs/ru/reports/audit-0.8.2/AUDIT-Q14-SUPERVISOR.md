## Область и изменения

Проверен цикл дочернего data-plane процесса: ошибки spawn, выход, отмена ожидания,
backoff, Restart/ReloadUsers, закрытие канала, grace deadline и watch-остановка.
Этот production-цикл вынесен в `qeli/src/server/supervisor.rs` и используется тем же
Linux `run_supervisor`. Host-тесты запускают изолированный дочерний тестовый процесс,
читающий stdin; сетевых/привилегированных действий в нём нет. Unix-сигналы остаются
в Linux-адаптере. `WorkerCmd` сохраняет прежний публичный путь через re-export.
INI-параметры, JSON API, клиентские ABI и зависимости не изменены.

PID во время backoff, отмена supervisor и игнорирование graceful termination.

на владении Child и проверке исходного кода Tokio. F007 проверен по порядку кода и
Linux cross-compilation, а не отправкой Unix-сигналов в работающий сервер.

## Проверки

**741 Rust unit + 52 editor/policy + 7 examples + 12 server INI = 812**, PASS.
Новый supervisor-модуль содержит 13 поведенческих тестов и один entry point дочернего
fixture, который также учитывается libtest. Проверены:

- четыре исходных дефекта ожидания/владения;
- stop до первого spawn, закрытие пустого и заполненного канала;
- закрытие канала у активного worker без повторной рассылки stop;
- Reload без смены поколения, один restart для очереди старых команд;
- Apply во время 30-секундного backoff без ожидания таймера;
- повторный Restart без продления deadline и без параллельных поколений;
- watch: исходное true, закрытие sender, false update и отмена ожидания перед true.

При ревизии нового кода обнаружен и исправлен отдельный случай: закрытый канал с
отложенным Restart ещё разрешал retry. `review-closed-owner.log` фиксирует падение
до этой корректировки; это промежуточная ошибка реализации, не находка базы.

Параллельный полный прогон выявил `AddrInUse` в прежнем DNS-fixture: свободный
TCP-порт не обязательно свободен для UDP. Общий test-only helper резервирует оба
сокета, повторяя выбор только при конфликте и не более 64 раз. Отдельный EDNS-тест
содержимого ответа один раз истёк по секундному deadline; его запас увеличен до
5 секунд. Причина того timeout не доказана как production-дефект. Проверки самих
таймаутов и production DNS не изменены; итоговый обычный параллельный прогон проходит.

Linux all-targets Clippy проходит с прежним исключением
`clippy::chunks_exact_to_as_chunks`; строгий прогон отдельно фиксирует предупреждение
в неизменённом `qeli/src/server/ndp_proxy.rs:504` на Rust 1.98. Минимальный FFI,
rustfmt, diff и 9 проверок документации — PASS. Проверки host выполнены на Windows;
Linux runtime ими не подменяется.

## Ограничения и следующий проход

60 секунд — grace-период, не гарантия выхода процесса из неразрываемого ожидания
ядра. SIGKILL не исполняет post_down и не подтверждает полный rollback firewall;
очистка старых правил следующим worker не заменяет Linux E2E. Реальные Unix-сигналы,
systemd/procd, окно до входа в async-функцию, hooks и startup rollback ещё требуют
Linux-стенда. Принудительная отмена самого профиля также остаётся открытой из прошлого
отчёта. Производительность не измерялась.

Следующий участок: владение control.sock и правами каталога, завершение control
handlers и парность post_up/post_down. Внешние SSH-сценарии и живая сеть ОС в этом
проходе не использовались. Полный аудит Qeli не объявляется завершённым.
