# Q25-F112/F113: ограниченные файлы идентичности и безопасный TOFU

25 сентября 2026. База `e1323803`. D05/D09, Linux.

## Что исправлено

**F112 — device-id.** Прежний код читал весь файл ради первых 16 байт, мог зависнуть
на FIFO или бесконечно ждать flock. При недоступном хранилище он генерировал новый ID
на каждой попытке соединения, хотя fallback заявлялся как один ID на запуск.
Теперь читаются только 16 байт обычного файла; прежний ненулевой префикс сохраняется,
включая файл с суффиксом. Пустой/короткий/all-zero файл допускает генерацию под lock,
а ошибка чтения или специальный файл не разрешает его замену.

Linux adapter загружает ID один раз в joined network worker после получения пароля,
до сетевого lease, kill-switch и первого carrier/handshake. Результат, включая случайный
fallback, кешируется до завершения запуска клиента. Stop до admission не создаёт файл;
после admission ждёт worker, затем завершается без нового подключения. Lock contention
ограничен 15 секундами, после отказа остаётся прежняя политика временного ID. Сбой записи
не выбрасывает уже выбранный ID: он используется до конца запуска. Принудительный Drop
может синхронно ждать worker; общий жёсткий срок файлового I/O этим не задан.

**F113 — known_hosts.** `read_to_string` при ошибке UTF-8/чтения трактовался как отсутствие
пина. Поэтому повреждённый комментарий позволял проигнорировать существующий другой
ключ и принять новый. Первое совпадение также скрывало противоречивую дублирующую запись.
Append без разделителя склеивал новый пин с последней строкой без newline, а ошибка записи
или fsync могла оставить частично изменённое хранилище.

Теперь TOFU читает обычный файл объёмом не более 1 MiB (не более 1 MiB + 1 байта при
проверке границы). Ошибка чтения, UTF-8, размера, некорректный пин целевого сервера или
конфликт дубликатов останавливает проверку, включая `allow_unpinned_tofu = true`.
Отсутствующий файл остаётся допустимым первым использованием. Проверяются все записи
целевого сервера; одинаковые дубликаты и регистр hex сохраняют совместимость. Комментарии
и неизвестные строки других серверов не переинтерпретируются как ключ целевого сервера.

Под sidecar lock файл повторно читается, затем новый пин добавляется через общий
`write_atomic_private`: с разделителем строк, режимом `0600`, file/parent fsync и атомарной
заменой. Partial-write/file-fsync failure сохраняет старый файл. Ошибка parent fsync после
rename может уже оставить новый файл, но не сообщается как успешное сохранение.
`allow_unpinned_tofu` разрешает только сбой lock/сохранения нового пина после проверенного
снимка; не разрешает чтение повреждённого/недоступного старого хранилища или превышение
лимита. Явный `key` по-прежнему проверяется независимо от TOFU-файла.

Реализации вынесены из большого client module в `identity_files`; отдельных копий нет.
INI, wire protocol, публичный C ABI и файловые адаптеры других платформ не изменены.

## Проверки

- **15 новых регрессий**: 6 portable reader/pin tests, 6 Linux file tests и 3 adapter
  tests. Проверены бесконечный reader, UTF-8/размер, конфликтующие/повреждённые записи,
  sparse-файл 16 GiB с прежним ID, FIFO без писателя, lock timeout, atomic/private store,
  строка без newline, временный ID на срок adapter, stop до/после admission.
- **16 native сценариев: 8 baseline + 8 fixed**, TCP/UDP × device-lock, повреждённый
  TOFU с обоими значениями allow_unpinned_tofu, отказ TOFU fsync. Baseline при lock даёт
  0 heartbeat тиков; fixed — **8** за около 800 мс и ждёт освобождения lock перед
  выходом. После принятого stop fixed не создаёт carrier/TUN и не начинает TOFU.
- **4 baseline corrupted-store случая подключаются с другим ключом**, дописывая файл;
  все 4 fixed отказывают без post_up и изменения файла. Это воспроизведение последствий
  локальной порчи хранилища, а не доказательство удалённой возможности изменить файл.
- **2 baseline fsync faults** изменяют старый файл, хотя клиент завершается ошибкой;
  **2 fixed faults** сохраняют исходные байты и удаляют временный файл. Все случаи
  восстанавливают исходные маршруты/firewall и не оставляют клиентский TUN.
- Дополнительно **6 established TCP/UDP teardown cases** (2 baseline + 4 fixed) и
  **2 явных recovery** проверяют успешный новый TOFU, последующие соединения, `stopped`,
  sticky `failed` при cleanup fault и восстановление сохранённого kill-switch.
- **1575 host + 71 config; 2148 Linux + 48 privileged + 8 lifecycle PASS**.
  Все 9 host/cross/feature/lint/format команд PASS. RU/EN docs и diff проверены.
