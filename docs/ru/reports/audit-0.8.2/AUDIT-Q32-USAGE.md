# Q32: сброс usage на границе атомарной публикации

<!-- normative-sync: q32-usage-v1 -->

8 октября 2026. F384 / Q32-F005. Проверены `server/usage.rs`, связь с
регистрацией TCP/UDP-счётчиков, quota sweep, shutdown и API сброса.
Q32 остаётся IN_PROGRESS: логи, trace, roaming metrics и доверие уведомлениям
ещё требуют проверки.

## Ошибка и исправление

`write_atomic` сначала синхронизирует временный файл, затем делает rename,
затем fsync каталога. Ошибка последнего шага возвращает `PublishedWriteError`:
новые данные уже видны, но их сохранность после сбоя питания не подтверждена.
`reset_and_flush` восстанавливал старые значения в памяти при любой ошибке,
хотя файл уже содержал нули. Дополнительно строковое оборачивание ошибки
теряло её тип. Control API ошибочно сообщал, что сброс не произошёл.

Теперь ошибка сохраняет цепочку причин через `anyhow::Context`. Ошибка до
публикации восстанавливает прежние значения. После успешного rename память
сохраняет опубликованный сброс; ответ остаётся `ok=false`, но явно сообщает
о публикации с неподтверждённой сохранностью. Следующий успешный flush
подтверждает запись и учитывает только новый трафик. API-схема не меняется.

## Воспроизведение

В Linux-harness использованы настоящий `UsageStore`, production-часть
atomic writer и `atomic_file.rs`. Добавлен writer seam, который проходит
создание, запись, fsync файла и rename и возвращает ошибку только на последнем
шаге синхронизации каталога. Ошибка fsync инъецируется; аппаратный сбой питания
этот тест не моделирует. В baseline изменена только точка вызова writer,
старый rollback и строковое оборачивание сохранены.

Старое поведение воспроизведено: файл после rename содержит ноль, память —
700 байт. Исправленный harness проходит 16 тестов: 15 usage и один atomic-file.
Новый тест проверяет цепочку типизированной ошибки, обе стороны счётчика,
сохранность другого пользователя, новые 20+5 байт, повторный flush и retirement.
Существующий негативный тест подтверждает rollback при ошибке до публикации.
Отдельный тест control проверяет текст обеих ветвей ответа через настоящий writer.

Первый исправленный harness остановился на неверном предположении теста,
что `Error::to_string()` выводит всю цепочку `anyhow::Context`; проверка
исправлена на `{error:#}`. Исходный неуспешный лог сохранён. В небольшом
harness есть предупреждение о неиспользуемом импорте полного writer;
результат строгого Clippy относится к полному crate, а не этому harness.

## Границы проверенного поведения

Supervisor открывает read-only store и reload перед выдачей API. Worker
получает исключительное владение до загрузки writable store. Нечитаемый или
повреждённый существующий sidecar блокирует его запуск, не стирая файл.
Миграция старого общего счётчика относит его к download и идемпотентна.
Monotonic folding, насыщение сумм, короткие сессии, хвост последнего writer,
сброс активной сессии и конкурентное накопление покрыты существующими тестами.

Квота download проверяется периодическим sweep; это не точный лимит каждого
пакета. Hard SIGKILL пропускает финальный flush: несохранённый трафик после
последней успешной периодической записи может потеряться. Проверка не
заявляет power-loss durability, точную обработку дискового зависания или VPN E2E.
`usage.json` — служебное состояние, конфиги остаются только INI.

## Полная Linux-квалификация

Неизменяемый снимок `49d20c01`: 2426 library tests PASS, 60 ранее ignored
сохранены; Clippy all-targets с `-D warnings` и debug daemon build PASS.
Тесты выполнялись в отдельных net/mount/PID namespaces с временными
`/run`, `/var/lib`, `/var/log` и `/tmp`. Host/service baseline `.11` совпал.
Тот же исправленный harness16 прошёл от UID/GID65534 без дополнительных
привилегий. Снимок и подготовительные ошибки остаются в raw evidence.

## Evidence

Пакет: `audit-debt-20260924/q32-usage-20261008`. Исходный и исправленный
harness, архив неизменяемого Git-снимка и все логи сохраняются отдельно.
В первом baseline появились три legacy-правила host firewall; harness не
запускает network-policy команд, источник изменения не установлен.
Снимок первого прогона не объявляется неизменным. Повторный исправленный
harness сохранил network/service baseline; чужие правила не удалялись.

Windows/macOS и Android arm64/x86_64 прошли независимые A/B из снимка
`49d20c01`; все 317 переданных входов проверены до и после сборки. Экспорты,
macOS load commands и структура ADHOC-подписей проверены. Windows ABI22 и
Android ART JNI23 прошли на точных новых байтах; оригинальные AVD userdata,
список пакетов и интерфейсы сохранены. Это не managed-app rebuild, ARM runtime,
Mac/iOS/роутерный/Windows VPN E2E или power-loss тест. Предупреждения cross-Mac
об отсутствующем Xcode SDK сохранены. Разные приватные Cargo roots могут менять
байты относительно прошлого пакета; межпутевая герметичность не заявляется.

Первый native-preparation остановился на опечатке path-verifier до компиляции;
исправленный retry использовал те же 317 проверенных входов и независимые
A/B targets. На `.10` снова наблюдались только те же три legacy-правила.
В guard retry исключены только эти точные строки, исходные snapshots сохранены;
это не подтверждение полного совпадения host firewall. Все остальные snapshot
поля и сервисы совпали. На `.11` полный Linux, Android native и JNI snapshots
проверяются отдельно. Никакие чужие правила не удалялись.

Полные результаты: `release/certification/evidence/q32-usage-20261008.json`.
Общий план пока 28/37 DONE (75,7%), девять пунктов остаются открытыми.
