## Q14-F034, P2 — очистка обновляла сроки для каждого правила и семейства

Серверная очистка ожидала firewall-programming mutex без ограничения срока. Затем
каждый inventory, точная проверка, удаление и fallback-проба получали свои 15 секунд.
Большой набор правил или задержанный backend могли расходовать много последовательных
бюджетов: срок отдельной команды не ограничивал одну попытку очистки.

`cleanup(profile)`, стартовый `cleanup_all()` и финальный `finish_owned_cleanup()` теперь
каждый получают 15 секунд на входе. Firewall mutex, блокировки реестров точных правил,
DNS и IPv6 leases, поиск утилит, обход тегов, точные правила IPv4/IPv6 и retired DNS
UDP/TCP делят оставшееся время попытки. После срока команды не запускаются, позднее
подтверждение не признаётся успешной очисткой. `--wait 5` для xtables остаётся внутри
общего срока; прежние лимиты вывода сохраняются.

Только подтверждённое отсутствие удаляет точное правило или retired DNS generation
из реестра. Удаление могло уже примениться до timeout подтверждения: запись остаётся
до отдельной попытки с проверкой фактического состояния. Ранее подтверждённые удаления
освобождают свои записи. Отдельные ошибки не мешают другой работе, пока остаётся бюджет;
истечение срока запрещает новые внешние операции, сохраняя неподтверждённые записи.
Новый вызов получает новый бюджет.

Sysctl recovery/release проверяются до и после синхронного вызова. Истёкшая попытка
не начинает следующий шаг sysctl и не принимает поздний ответ за успех. Начатая
операция sysctl не прерывается: внутренние journal/lock/I/O сохраняют свою семантику.
Уже освобождённый IPv6 scope может оставить запись для retry в памяти после позднего
ответа; повторный no-op release подтвердит очистку и удалит её.

Исторический обход тегов сохраняет best-effort политику для mixed nft при ошибках,
не связанных со сроком. Deadline отдельно фатален, даже если точных записей больше нет.
Это не подтверждает неперечисляемые исторические правила и не добавляет устойчивое
владение firewall. Отдельный callback очистки DNS lease теперь делит 15 секунд между
двумя транспортами, но предшествующие ему ожидания mutex в Drop/setup в этот срок не входят.

## Проверки

Восемь Linux-тестов используют production collector и приватные shell-модели правил,
thread-local пути утилит без изменения PATH и без мутаций firewall/sysctl хоста:

- Истёкший срок/занятая блокировка при profile/startup/final cleanup не запускают команды или callbacks.
- Занятые реестры точных правил, DNS и IPv6 исчерпывают срок без потери ownership.
- Очередь firewall расходует остаток срока первой команды обхода.
- Точные IPv4/IPv6 делят срок; применённое, но не подтверждённое удаление остаётся pending, отдельная очистка успешна.
- Retired DNS UDP/TCP делят срок; частичное поколение запрещает замену до проверенного retry.
- Финальная очистка NAT и DNS делит срок; после истечения не начинается IPv4 sysctl release, новая попытка его выполняет.
- Стартовые обходы делят срок; поздние синхронные recovery/release callbacks не дают успеха и не запускают новые команды.
- Задержанная fallback-проба ограничена оставшимся сроком.

## Оставшиеся границы

Это срок очереди/команд одной попытки очистки, не жёсткий предел 15 секунд для всей
остановки или перезапуска worker. Очистка каждого профиля и финальный проход — отдельные
вызовы. Filesystem metadata, внутренний sysctl, spawn, kill/reap и kernel waits не
прерываются этим таймером. API остаются синхронными.

Установка NAT и её прежние rollback-обходы, admission DNS lease в Drop/setup,
клиентские routes и gateway остаются D05. Crash persistence, namespace/backend identity
между worker и неперечисляемые mixed nft ресурсы остаются D04/D06/D10. Очистка не атомарна
при сторонних root-изменениях; после выхода процесса реестры в памяти не доказывают
принадлежность оставшихся правил старому worker. D05/D09 целиком не закрыты.
