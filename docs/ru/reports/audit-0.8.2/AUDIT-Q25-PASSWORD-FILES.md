## Находки и исправления

**Q25-F002, P2 — синхронный password_file без лимита и незащищённая временная копия.**
Проверка размера AUTH выполнялась после read_to_string, который читал весь файл на потоке
async-runtime. FIFO мог заблокировать запуск до проверки stop token. Trim копировал пароль
в Zeroizing, оставляя исходную String-аллокацию без обнуления.

Файл и команда теперь используют общий SecretBuffer: заранее выделенные 16 KiB сырого
ввода, отказ при превышении, строгий UTF-8 и обрезка пробелов по краям. Сырой буфер,
4 KiB scratch и итоговая строка обнуляются при Drop. Нет роста/reallocation Vec и усечения
пароля. Лимит AUTH, приоритет источников и поведение пустого/пробельного ввода сохранены.
Возможности GUI и INI-ключи не изменились.

Файл открывается один раз, fstat проверяет этот дескриптор; принимается только обычный
файл. Symlink сохранён для ротации secret stores. Политика владельца конфига для shell
не переносится на файл данных. O_NONBLOCK позволяет отклонить FIFO до чтения. Размер
проверяется до и во время чтения; общий с config_source снимок метаданных и число байт
отклоняют обнаруженные изменения на месте. Подмена пути не добавляет данные другого
файла. Это не атомарная защита от любых действий привилегированного писателя.

На процесс допускается одна блокирующая I/O-задача вне потоков async-runtime. Бюджет
30 секунд включает очередь; отмена/deadline проверяются между файловыми операциями.
Штатный stop/timeout отменяет ещё не начатую работу и дожидается активной задачи,
отбрасывая поздно полученный секрет. Слот и буферы принадлежат самой задаче, поэтому
принудительная отмена caller не разрешает дополнительные чтения до её завершения.

Файловый syscall не всегда можно прервать. Read/open/fstat на зависшей файловой системе
может продолжаться дольше 30 секунд; штатная остановка ждёт. При принудительном Drop
вызывающей стороны остаётся максимум одна активная задача до возврата I/O и проверки
отмены. Это явно ограниченная остаточная работа, а не жёсткий I/O timeout или join в Drop.

**Q14-F021, P2 — гонка финального статуса с текущей записью sampler.** Drop клиентского
JoinSet только запрашивал abort. Sampler, уже взявший старый снимок, мог закончить
синхронную запись после публикации stopped/failed основным путём. Ранние ошибки источника
пароля/startup также пропускали терминальную публикацию, используемую поздними выходами.

run_client теперь содержит внешнюю обёртку для всех возвратов startup/retry. Она отменяет
и дожидается watchers/sampler, затем выставляет и публикует терминальный статус. Четыре
дублирующих блока финальной публикации удалены. Ошибки после инициализации reporter,
включая источники пароля, проходят тот же путь. Ошибки parser/adapter до этой инициализации
по-прежнему не имеют reporter. Принудительная отмена всей future не гарантирует финальный
статус; синхронная диагностика может задержать join.
