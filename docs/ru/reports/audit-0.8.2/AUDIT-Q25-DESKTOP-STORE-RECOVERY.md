# Q25-F172: отказоустойчивость desktop-хранилищ профилей

1 октября 2026. База: 6d24736f. D08 остаётся **IN_PROGRESS**.

В Windows и macOS повреждённый profiles.json ранее пытались переименовать в .corrupt-*, но ошибку File.Move игнорировали и возвращали пустой список. При следующем сохранении пустое хранилище могло заменить исходный файл с восстанавливаемыми профилями. Кроме того, запись миграции legacy/Id находилась внутри общего try: сбой записи ошибочно классифицировал читаемый файл как повреждённый и перемещал его. На macOS ошибка записи восстановленного .bak также скрывалась внутри обработчика ошибки backup.

Общий ProfileStoreRecovery.PreserveUnreadable теперь выдаёт уникальное имя с GUID и требует успешного переноса файла перед открытием пустого хранилища или восстановлением .bak. При ошибке переноса загрузка завершается с IOException; исходный файл остаётся на месте. Миграционная запись вынесена за пределы обработки ошибок чтения. На macOS ошибка записи восстановленного backup также передаётся вызывающему коду. Формат клиентского конфига остаётся только INI; JSON в этом коде является внутренним контейнером локального profile store.

Проверки: conformance selftest прошёл, включая сохранение точных байтов повреждённого файла и отказ при неудачном переносе; dotnet build QeliWin и QeliMac с --no-restore прошёл без предупреждений и ошибок; git diff --check прошёл. UI-загрузка на Mac и Windows VM не проверялась из-за отсутствия согласованных стендов. Транзакционность редактирования профилей и reconnect остаются в D08.
