# Q25-F158: согласование сохранённой и действующей политики блокировок

1 октября 2026. База: `7e4e5238`. D07 остаётся **IN_PROGRESS**.

Аудит пути `POST /api/blocked/settings` показал, что сохранение `[web] brute_force.*` меняло лимитер входа напрямую, не обновляя `live_web.brute_force`. Другие сохранения INI используют `reload_web_settings`, который обновляет оба состояния вместе и сохраняет прежнюю политику при ошибке. Вкладка блокировок читала сохранённый INI и не могла отличить его от действующей политики после неудачного применения. Новый тест также выявил ложный отказ live reload при выключенной на старте панели без пароля: пароль требовался даже при отсутствии слушателя.

Теперь API блокировок применяет панельную политику через общий live reload. Ответ сохранения содержит `panel_applied`; при отказе явно сообщает, что INI записан, но перезагрузка панели не состоялась. `GET /api/blocked/settings` возвращает `panel_applied` по сравнению сохранённой и действующей политики и `live_panel` для диагностики. Вкладка показывает предупреждение о расхождении; при неизменных порогах существующие блокировки сохраняются. Проверка пароля при live reload теперь применяется только к включённой при старте панели; для работающей панели запрет пустого пароля сохраняется. VPN-политика по-прежнему сигнализируется worker и честно помечается как ожидающая рестарта при недоступности worker. Формат файла остаётся INI; JSON используется только для служебного API.
