# Q25-F190 — ошибки истории серверного INI

Статус: исправление в коде, адресная Linux-проверка ожидает доступ к VM .11.

GET /config/history возвращал ok: true с пустым или частичным списком, когда read_dir, перечисление или чтение снимка завершались ошибкой. При сохранении snapshot_config использовал flatten() и игнорировал ошибки удаления старых снимков. Администратор мог принять неполную историю за полную; ротация могла нарушить лимит 10 снимков.

Список считает пустую отсутствующую директорию нормальным начальным состоянием, а остальные ошибки метаданных, перечисления, типа и чтения возвращает вызывающему API. Ротация прерывает сохранение до замены действующего INI, если перечисление или удаление не удалось. Добавлен тест отсутствующей директории, корректного и повреждённого снимка.

rustfmt --edition 2021 --check qeli/src/web/api/config.rs — PASS. cargo test --manifest-path qeli/Cargo.toml --lib --quiet на Windows — 1551 PASS, 1 ignored; этот набор НЕ компилирует серверный web-модуль и не запускает новый тест. SSH на .11 после сброса снова отклонил root с ранее предоставленным паролем; повторных попыток не было. До Linux cargo test и адресного API-прогона D07 остаётся IN_PROGRESS. Пользовательские изменения CHANGELOG.md и users.html не затрагивались.

Исторические числа выше не являются новым прогоном. Сетевые комбинации и итоговая сертификация остаются D10/D15.
