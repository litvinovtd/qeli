## Q25-F086, P2 — refresh продлевал срок на каждой команде

Обновление адресов сервера перед reconnect ожидало operation mutex без срока и
давало каждой проверке/мутации собственные 15 секунд. Очередь, IPv4 и IPv6 не делили
срок. Исправление `disengage` из предыдущей фазы этот путь не покрывало.

Теперь `refresh_server_ips` получает 15 секунд при входе. Разрешение имени, ожидание
operation mutex, обе семьи и все команды используют один абсолютный deadline.
Системный resolver остаётся синхронным: таймер не прерывает зависший DNS/NSS вызов,
но после его возврата просроченный результат не допускает firewall-команды.
Общий `Budget` используется также очисткой; её прежние гарантии сохранены.

Контекст проверяет срок перед запуском и после ответа команды, а refresh — перед
возвратом успеха. Таймаут не освобождает owner и не снимает DROP/OUTPUT/FORWARD.
Если добавление успело выполниться, но не подтверждено до срока, предыдущий адрес
не удаляется. Отдельный вызов получает новый срок и проверяет фактические правила.
Linux connect-loop обрабатывает ошибку refresh остановкой reconnect с сохранением
защиты; автоматический повтор в той же сессии этим изменением не добавлен.

## Q25-F087, P2 — unknown ошибочно разрешал вставку

Начальная проверка `-C <chain> -d <server> -j ACCEPT` использовала bool-helper:
permission/backend/timeout превращались в `false`, после чего выполнялась вставка.
Наличие правила и ошибка его проверки не различались. Новый вызов `present_checked`
возвращает три исхода: present — пропуск; confirmed absent — вставка; unknown — ошибка
без вставки этого правила. Неподтверждённая замена сохраняет прежние разрешения.
Независимые успешно проверенные адреса могут быть добавлены до обнаружения другого
отказа; обновление не является атомарной транзакцией всего набора.

## Проверки

Шесть новых Linux-регрессий проверяют:

- Истечение срока до/внутри resolver: ни одной firewall-команды после позднего ответа.
- Занятый operation mutex: timeout без запуска команды.
- Очередь расходует срок первой команды, не выдавая ей новый budget.
- IPv4/IPv6 делят срок; после timeout owner позволяет отдельный проверенный повтор.
- Фактическую вставку в private fixture с задержкой ответа: прежний адрес и DROP
  не удаляются, вторая семья не запускается; повтор подтверждает новый адрес и убирает старый.
- Unknown при начальной проверке: нет вставки/удаления, затем успешный отдельный повтор.

Это настоящие shell-child и production collector, реальные pinned namespaces и
частные файлы модели правил; firewall хоста не изменяется. PATH/environment не
подменяются. Смена адреса и kernel firewall дополнительно покрываются прежними
privileged tests; новые fixtures не являются измерением задержанного kernel backend.

Контрольная подмена вернула только независимые командные сроки и bool-проверку,
сохранив ownership и ограниченный admission. Три целевых сценария ожидаемо упали
(exit 101): общий срок семей, неподтверждённая вставка, unknown → мутация. Затем оба
исходника восстановлены побайтно. После очистки только пакета qeli в private target
выполнена чистая пересборка: **6 refresh + 5 cleanup tests PASS**.

## Оставшиеся границы

Это общий срок admission/команд с учётом времени resolver, не жёсткий wall-clock
предел reconnect. DNS/NSS, короткие registry mutex, filesystem/namespace inspection,
spawn и kill/reap не получают принудительного прерывания таймером. API синхронный.
При ошибке возможны частичные добавления или уже подтверждённые удаления устаревших
адресов. Process-local owner не заменяет persistent crash recovery; после выхода
процесса требуется проверка оставшихся правил. Параметры INI и ABI не менялись.
[Установка и откат](AUDIT-Q25-KILL-SWITCH-SETUP.md) рассмотрены следующей фазой.
NAT/routes/gateway, прочие lock waits и полные D04/D05/D09 остаются открытыми.

Продолжение: [Q25-F098](AUDIT-Q25-KILL-SWITCH-REBUILD.md) устраняет окно утечки при перестройке после аварии. Точные временные DROP guards сохраняются при отказе/повторном SIGKILL и снимаются после готовности замены; ограничения выше относятся к прежнему снимку. Общие сроки, внешние firewall writers и остальной D04 остаются отдельными критериями.

Продолжение D05: [Q25-F103 — общий системный resolver](AUDIT-Q25-SYSTEM-RESOLVER.md) ограничивает ожидание DNS/NSS и число вызовов, поддерживает отмену и исключает ожидание blocking pool при уничтожении runtime. Утверждения выше о синхронном ожидании DNS относятся к прежнему снимку; сетевые мутации и D05 целиком остаются открытыми.
