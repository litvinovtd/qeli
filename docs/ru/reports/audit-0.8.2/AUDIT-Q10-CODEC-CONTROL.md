# Q10: PacketCodec, replay и подтверждения CONTROL_V2

Дата: **3 октября 2026**. **Q10 DONE** в согласованных границах платформенного аудита.
Исправления: `2d6d1b73`. Evidence: `release/certification/evidence/q10-codec-20261003.json`.

## Исправления

- **Q10-F001, P2:** повтор уже полученного фрагмента незавершённого KICK считался доставкой всего сообщения. Клиент мог отправить ACK до сборки и публикации события. Такой повтор теперь возвращает Pending; ACK появляется только после полного корректного сообщения.
- **Q10-F002, P2:** некорректный KICK попадал в completed cache до семантического разбора. Первый экземпляр отклонялся, повтор получал ACK. Общий management-приёмник проверяет payload под тем же session lock; отказ удаляет запись. Исправленное сообщение с тем же ID принимается. Неподдерживаемые типы не получают management receipt.
- **Q10-F003, P2:** совпадения одного message ID хватало для Duplicate, даже при другом типе, флагах, числе частей или содержимом. Кэш теперь хранит эти метаданные и SHA-256 каждого фрагмента; конфликт отклоняется. Точный повтор принятого сообщения получает ACK повторно, чтобы пережить потерю первого ACK.

Три client regression checks воспроизвели прежнее поведение до исправления. Разделение
фрагментов проверено на аутентифицированных plaintext fixtures общего обработчика;
нынешний серверный генератор с лимитом текста 512 байт выдаёт KICK одной частью.
Это дефект контракта подтверждений; удалённая эксплуатация без аутентификации не заявляется.

## Разбор слоя

PacketCodec проверяет точную длину TLS/raw frame, предел record до выделения памяти,
nonce/tag и минимальную длину plaintext. Ошибки очищают caller-owned buffer, сохраняя
capacity. AEAD и padding проверяются до изменения replay window. Шифрование отказывает
до переполнения counter. Новых подтверждённых дефектов этого пути не найдено.

Replay window сопоставлено с независимой моделью HashSet на **98 304 последовательностях**,
включая сдвиги 63/64/65, край 2047/2048/2049, 2^63 и u64::MAX. Аутентифицированный
пакет с неверным padding не сжигает слот: корректный пакет с тем же counter принимается,
затем его повтор отклоняется. Проверены TLS и raw.

Legacy CTRL требует точную длину и отдельную magic; ClientInfo ограничивает UTF-8,
длину и алфавит. Самоотчёт platform/version остаётся диагностикой. CONTROL_V2 ограничивает
часть 4096 байтами, сообщение 16 частями/64 KiB, inflight восемью сообщениями и исходным
дедлайном 5 секунд. Completed cache ограничен 64 сообщениями: максимум **32 KiB дайджестов**
плюс ограниченные метаданные и allocations. Поколение задают session AEAD key и lifecycle;
нового поля generation в CONTROL_V2 не добавлено. Экспортированный C ABI и wire format прежние.

Общий обработчик используется Linux и native clients, inline/pipeline и после recordizer.
Семантическая проверка и запись receipt выполняются под общим lock bonded streams.
Публичные conformance helpers и generic reassembler сохранены как совместимые Rust API;
нового подтверждённого мёртвого production-кода в этом слое не выявлено.
