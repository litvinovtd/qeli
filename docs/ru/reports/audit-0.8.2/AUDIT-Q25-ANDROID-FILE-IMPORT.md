# Q25-F167: точное чтение клиентского INI на Android

1 октября 2026. База: b902ffcf. D08 остаётся **IN_PROGRESS**.

При файловом импорте Android декодировал UTF-8 с заменой ошибочных байтов на U+FFFD и применял `trim()` ко всему документу до общего парсера. Это могло сохранить профиль с изменённым паролем или иным значением без указания ошибки кодировки. Предварительное удаление конца документа также нарушало принцип точного разбора входного INI.

Теперь файловый импорт использует строгое UTF-8 декодирование и передаёт полный текст в общий config core. Для определения типа и чтения начального комментария отдельно используется вид без допустимого начального пробела/BOM; сам сохраняемый INI не меняется. Файловый диалог больше не рекламирует `application/json` как тип конфигурации. Действие Restore по-прежнему принимает служебный JSON-контейнер бэкапа.

Проверки: `:app:compileDebugKotlin --offline` и 34 адресных `ConfigImportRangesTest` с ранее проверенной host DLL (ABI 1.16) прошли на Windows. Первоначальная попытка тестов без настройки DLL закономерно завершилась ошибкой загрузки native core; после задания `QELI_CONFIG_NATIVE_LIBRARY` прогон успешен. Потоковый ContentResolver E2E на эмуляторе в этом пакете не запускался; iOS/desktop и полный D08 остаются открытыми.
