# Q25: HTTP/2 workers и завершение клиентского поколения

Дата: 23 сентября 2026. Исходный коммит: `e4605d2e`.
Разделы 22–25: **IN_PROGRESS**; полный аудит остаётся открытым.

## Замечание

**Q25-F015, P2 — join внешних TCP-задач не ждал освобождения вложенного H2 transport.**
HTTP/2 carrier хранил AbortHandle для bridge и connection driver. Drop carrier запрашивал
отмену этих задач, однако группа клиентского поколения владела только внешними TCP-задачами.
Их finish мог завершиться, пока driver ещё освобождал внешний поток. Штатная очистка
DNS/TUN могла начаться раньше. Основной H2 driver создавался ещё до группы TCP-туннеля,
поэтому одной регистрации в уже запущенном data loop было бы недостаточно.

Воспроизводитель использует настоящий H2 поверх duplex и задерживает destructor внешнего
I/O. Он подтвердил завершение родительской группы до окончания destructor. Это проверка
порядка владения, не доказательство постоянной утечки, передачи трафика вне туннеля или
поломки ОС. Прежние тесты подтверждали освобождение позднее, после работы планировщика.

## Исправление

Linux CLI и общий native runner создают TaskGroup до подключения. Основной, дополнительный
и мигрирующий H2 carrier получают слабую ссылку Spawner и регистрируют driver/bridge
через connect_owned. Та же группа затем владеет TCP reader/writer, producers и Linux path
workers. Индивидуальный AbortHandle сохраняет отмену одного carrier без остановки других;
обязанность join остаётся у поколения. Закрытый владелец отвергает новую задачу.

В штатном teardown, включая ошибку управляющего события, группа завершается до DNS/TUN
cleanup. Ошибки раннего connect/handshake проходят финальный join перед возвратом Linux
TCP-попытки. В native runner внешний владелец переживает отмену run_attempt и завершает
TCP-задачи до finish_generation. Это также охватывает ожидание H2 response до запуска TUN.

TaskScope сначала закрывает admission и запрашивает abort, затем уничтожает отменённую
future с её сетевыми guards. Внешний TaskGroup сохраняет handles для async join. Это
сохраняет порядок отмены при переносе владельца наружу; синхронного ожидания async-задач
в Drop нет. Отмена ожидания finish не теряет handles и допускает повтор.

Общая реализация находится в `qeli/src/transport_core/tasks.rs` и
`qeli/src/protocol/h2_carrier.rs`; отдельные клиентские H2 pumps не добавлены. Clean
half-close, ответ в обратную сторону, END_STREAM, batching и flow control сохранены.
Обработка серверного accept и public standalone connect сохраняет прежний cancellation
контракт; ограниченный одной секундой flush ошибочного server response не изменён.
INI, wire format и ABI 1.16 не меняются; release native-библиотеки не пересобраны.

## Проверка

Восемь новых H2-тестов проверяют: join задержанного I/O destructor с отменой/повтором
ожидания; отмену connect при отсутствии response; ошибку построения запроса; закрытого
владельца; Drop владельца при живом carrier; half-close с ответом; заблокированный bridge
при нулевом H2 window; отмену одного carrier при работающем другом в той же группе.
Девятый тест проверяет закрытие admission до уничтожения сетевого guard попытки.

Регрессия join отдельно запущена на исходном h2_carrier из `e4605d2e`. Для совместимости
новой сигнатуры добавлен тестовый connect_owned, делегирующий прежнему connect без
регистрации задач. Тест падает на преждевременном finish. С исправлением он проходит.
Новые fixtures работают в памяти, без драйверов и настройки сети. Существующий H2/REALITY
round-trip также проходит, но это тестовый duplex, не реальный TLS/TCP сеанс с сервером.

## Что осталось

Отмена всего владельца/runtime по-прежнему не позволяет гарантировать async join; Drop
запрашивает остановку. Синхронный rollback частично применённого сетевого плана может
выполняться в локальном guard до финального внешнего join при ранней ошибке setup.
Изменение не подтверждает все платформенные ACK/rollback или публикацию UI-статусов.
UDP использует свою группу; его принудительная отмена этим проходом не исправляется.

Далее: владение H2-задачами серверного профиля и standalone API, deadlines системных
команд, platform fault injection и актуальные native builds с проверкой на устройствах.

Продолжение от 23 сентября: [Q14-F022/F023](AUDIT-Q14-H2-TASKS.md) добавляет join
серверных H2 driver/bridge и flush отказа в профиль, а также удержание pre-auth permit
до освобождения отклонённого соединения. Standalone API и остальные ограничения остаются.
