# Q25: изоляция маршрутов по владельцу подключения

Дата: 23 сентября 2026. Baseline: `1f857209`.
Q25-F027/F028 исправлены в описанных границах. Разделы 22, 23 и 25 — **IN_PROGRESS**.

## Находки

**Q25-F027, P2 — очистка и roaming использовали общий журнал без владельца.**
`cleanup_routes(ifname, ...)` забирал все записи процесса, хотя flush ограничивался
переданным интерфейсом. Одна очистка могла удалить carrier/exclude/blackhole другого
подключения. Запись по destination также позволяла roaming считать чужой Qeli route своим.
Просто разнести списки недостаточно: второе подключение могло принять совпадающий маршрут
за внешний и зависеть от него без удержания владельца.

**Q25-F028, P2 — подготовленный маршрутный commit переживал начало очистки.**
У проекции были generation/candidate ID, но не проверяемый срок жизни владельца.
Прямой вызов адаптера после cleanup снова устанавливал маршруты. Сопоставления только
имени TUN и номера generation недостаточно при повторном использовании этих значений.

Оба сценария воспроизведены на baseline двумя целевыми тестами, оба завершились отказом.
Это проверки границы route adapter; поддержка нескольких полных Linux-клиентов в одном
процессе этим не утверждается.

## Исправление

`route/journal.rs` хранит отдельные записи по уникальному процессному идентификатору
`RouteOwner`, имени интерфейса и generation. Владелец создаётся до reclaim/create TUN.
Один lease передаётся setup, частичному rollback, TunGuard и TCP/UDP cleanup.
Roaming-controller и подготовленный план получают слабую ссылку, которая не продлевает
жизнь завершённого подключения. Перед prepare/commit проверяются активность и generation.

Очистка закрывает приём новых операций до первой команды, даже если потом завершается
ошибкой. Она забирает и возвращает для retry только записи своего владельца. Внутрипроцессные
setup/prepare/commit/cleanup сериализованы. Имя интерфейса нельзя занять повторно, пока
жив прежний guard; после успешной очистки и освобождения последнего lease оно доступно.
Старый план не оживает даже при повторении имени и номера generation.

Перед add/replace проверяется отсутствие другого владельца того же route key. Carrier,
exclude и blackhole другого Qeli owner не заимствуются: конфликт отклоняется. Записи
оператора по-прежнему не присваиваются. Эквивалентные host-префиксы `IP` и `IP/32` либо
`IP/128` не обходят проверку. Это отказ от неподдерживаемого совместного владения, а не
reference counting общих маршрутов.

Если последний lease освобождён с оставшимися записями или неуспешным flush, reservation
сохраняется в памяти: новая попытка не присваивает остатки. Повтор очистки доступен живому
guard. Автоматическое восстановление осиротевшего владельца не реализовано.

Gateway refresh теперь вызывается внутри commit только после проверки живого owner,
под той же блокировкой операций. Поздний commit не вызывает даже этот callback.
Отдельная регрессия проверяет рабочий и остановленный owner.

Linux `dev_attach=true` больше не объявляет `ROAMING_PATH` и не получает managed route scope:
внешний управляющий отвечает за маршруты, `auto` использует reconnect. `required` не имеет
необходимого платформенного контракта. Legacy IPv4 setup и его вспомогательные функции
оставлены только в тестовой сборке; удалён лишний `pin_target` и неиспользуемые cleanup-аргументы.
Пользовательский INI и C ABI не менялись; внутренний Rust route API теперь требует owner.

## Проверки

**1090 host unit + 52 editor/policy + 7 examples + 12 server INI = 1161 Rust tests PASS.**
17 новых постоянных регрессий: два владельца на одном WAN, обе IP-family, изоляция cleanup/
retirement/rollback, неудачная очистка и retry, поздний commit, повтор имени и generation,
истёкший lease, потерянный владелец с остатками, ошибка flush, эквивалентные host-префиксы,
blackhole и реальный setup exclude. Отдельный тест запускает cleanup и поздний commit
в разных потоках через управляемую границу команды.

На baseline запуск фильтра `scope_` дал **2 целевых ожидаемых отказа**; четыре других теста
с таким фрагментом имени прошли и не считаются новыми controls. После исправления все
17 новых сценариев проходят в основном host suite. Прямые ip/firewall команды не запускаются.

Все девять команд матрицы прошли: host/config, Linux all-targets Clippy, client-only,
server-only, client без roaming, minimal FFI, compatibility без features и rustfmt.
В client без roaming осталось прежнее предупреждение `terminal_sender`; новые предупреждения
этого изменения устранены. Существующее исключение Clippy `chunks_exact_to_as_chunks` сохранено.
Linux guards/capability test/shell fixtures кросс-компилированы, не исполнялись на Linux.

## Границы и следующий проход

Registry остаётся процессным и непостоянным. Другие процессы Qeli/оператор, неизвестный
результат add, полная kernel identity, multipath/VRF и crash/restart recovery не покрыты.
Это не сертификация нескольких параллельных клиентов: другие глобальные состояния клиента
и firewall/DNS ещё требуют проверки. Незавершённые TUN workers и reuse файловых дескрипторов
также остаются частью Q14-F027, а не закрываются одним route lease.

Следующий пункт — подтверждение результата retirement/restore и контракт pending operations.
Команды всё ещё без срока; общий operation mutex означает, что зависшая команда задержит
другие route-операции процесса. Реальные Linux TUN/firewall/handover, native release,
устройства и новый benchmark здесь не запускались.
Предыдущий этап: [селекторы и подтверждённая очистка](AUDIT-Q25-ROUTE-OWNERSHIP.md).

Продолжение: [Q25-F029/F030](AUDIT-Q25-ROUTE-POSTCONDITIONS.md) проверяет результат
retirement/restore. Подтверждённое отсутствие или точное восстановление теперь принимается
даже при отрицательном/потерянном результате команды; ложный успех не считается доказательством.
Pending unknown/orphan recovery и сроки команд остаются открытыми.

Продолжение: [Q25-F031/F032](AUDIT-Q25-ROUTE-PENDING.md) сохраняет отдельные pending
reservations для неопределённых roaming-операций и закрывает admission при любом
неизвестном исходе commit. После подтверждения отсутствия остатков возможно read-only
освобождение orphan в пределах процесса; постоянный crash recovery остаётся открытым.

Продолжение D04: [Q25-F100](AUDIT-Q25-ROUTE-JOURNAL.md) добавляет постоянное владение физическими маршрутами и recovery после аварии. Описанный здесь process-local контракт дополнен durable intent/confirmed state; неопределённые операции по-прежнему не дают права удалить маршрут.
