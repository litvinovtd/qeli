# Q25: сохранение DNS-снимка при ошибке восстановления

Дата: 23 сентября 2026. Исходный коммит: `95f4bce6`. Разделы 19/25: **IN_PROGRESS**.

**Q25-F006, P2 — восстановление старого resolver могло ложно сообщать об успехе.**
Ветка отсутствующего оригинала игнорировала ошибки remove_file и использовала exists(),
следующий по symlink. Неудаляемый resolver или битая ссылка могли остаться, а операция
считалась успешной и удаляла backup. Ветка обычного файла игнорировала ошибку восстановления
прав и трактовала отсутствие содержимого в снимке как явно пустой исходный файл.

Восстановление файлов вынесено в один модуль, который непосредственно использует Linux DNS
и который проверяется на хосте. Теперь проверяются удаление и восстановление прав; только
NotFound считается успешным повторным удалением. Содержимое файла обязательно; цель symlink
валидируется до удаления текущего resolver. Снимок удаляется только после успешного
восстановления, ошибка удаления самого снимка сообщается отдельно. Явно пустые файлы,
относительные Unix symlink и прежний fallback managed-no-original остаются совместимыми.

Это обработка существующих снимков старых версий. Новые подключения продолжают применять
DNS через systemd-resolved для интерфейса и не перезаписывают /etc/resolv.conf напрямую.
Конфигурация клиента остаётся INI; прежняя служебная запись восстановления не является
форматом конфигурации. Неподдерживаемое восстановление Unix symlink в host-тестах завершается
ошибкой до изменения файлов.

## Проверка

Восемь Windows host-тестов используют реальные временные файлы: успешное восстановление,
пустой файл, отсутствие оригинала, отказ unlink (каталог с контрольным файлом), неполные/
неверные данные, отказ атомарной замены, повреждённый снимок, прежний fallback и отказ от
неподдерживаемого symlink. При отказах проверяется сохранение точных байтов backup.
Три дополнительных Unix-теста проверяют битую ссылку, относительную цель и исходные права;
они только cross-compiled, не запускались. Прежние Linux DNS-тесты используют тот же модуль.

## Что осталось

Сроки выполнения синхронных DNS/firewall-команд и конкуренция старого восстановления
требуют дальнейшего аудита. У symlink остаётся окно unlink/recreate: при поздней ошибке
снимок сохранится, но неизменность resolver не гарантируется. Ошибки отката TunGuard/
NetworkPlan и штатной очистки data plane ещё нужно довести до retry loop. Этот проход
не закрывает перечисленные проблемы жизненного цикла и полный системный аудит.

Продолжение: [аудит очистки TUN](AUDIT-Q25-TUN-CLEANUP.md) передаёт ошибки явной очистки и guards отката в политику остановки клиента. Live Linux E2E и полное завершение задач ещё открыты.

Продолжение: [Q25-F101](AUDIT-Q25-LEGACY-DNS.md) закрывает legacy global DNS безопасным отказом от автоматического replay и ручной миграцией. Старый snapshot не доказывает владение текущим resolver; автоматический restore/refcount и его тестовые реализации удалены. Исторические результаты выше относятся к прежнему поведению.
