# Q14: владение DNS-правилами после неудачной очистки

Дата: 23 сентября 2026. Исходный коммит: `de7a395f`.
Разделы 14, 17, 18 и 19: **IN_PROGRESS**; полный аудит остаётся открытым.

## Исправленное замечание

**Q14-F028, P2 — неудачная очистка уничтожала точное описание DNS INPUT правил.**
`DnsInputLease::drop` пытался удалить UDP/TCP permits и только записывал ошибку.
Затем lease вместе с profile/interface/pool/resolver/port уничтожался. Последующий
`nat::cleanup(profile)` знал tag, но на mixed native nft-цепочке `iptables-nft -S`
может быть недоступен. Повторить прежние точные `-C`/`-D` было уже невозможно.

Неудачный rollback установки имел тот же дефект: lease создавался только после
успешной установки, а описание частично созданных правил оставалось лишь в локальных
переменных. Исчезнувшая firewall-утилита также приводила к потере описания.
Подтверждено ревью и сравнением извлечённых production adapters; живой Linux не запускался.

## Исправление

`qeli/src/server/nat/dns_input.rs` хранит полные UDP/TCP rule specs и семейство адресов
в реестре worker. Владение регистрируется до первого `-I`, включая путь частичного
setup. Общая функция построения `dns_input_rule` перенесена туда без отдельной копии.
Lease содержит уникальный token; записи различают активного владельца и ожидающую
очистку запись. Перед cleanup запись помечается ожидающей: отказ или unwind сохраняет
описание. Только успешная проверенная очистка удаляет запись.

Повторные попытки выполняются при `nat::cleanup(profile)`, `cleanup_all()` и перед
новой установкой DNS permits того же профиля. Отказ повторной очистки не разрешает
новую DNS-установку этого профиля. Остальные ожидающие записи выбранного профиля
проверяются и после первой ошибки. Точный retry не трогает активные записи и другие
профили. Старый lease после успешного retry не может удалить новый набор: tokens не
переиспользуются, проверяется идентичность записи, а не совпадение имени профиля.
Это гарантия точечного retry; прежний общий tag sweep сохраняет отдельный контракт.

Реестр ограничен 4096 активными/ожидающими наборами (каждый — UDP+TCP одного resolver).
При заполнении новая установка отказывается до изменения firewall; старые сведения
не вытесняются. Очистка освобождает место. IPv4 и IPv6 учитываются отдельными наборами.
Новых INI-параметров нет. Набор аргументов правил, manual IPv6, ABI и wire format прежние.

В `enable_dns_input` lease принадлежит внешней области, а firewall mutex — внутренней.
При ошибке установки mutex освобождается до Drop lease. Это предотвращает повторный
захват тем же потоком при rollback. Вся работа с реестром и firewall по-прежнему проходит
под общим firewall mutex; callback очистки не захватывает реестр рекурсивно.

## Открытые границы

Реестр находится **только в памяти текущего worker**. SIGKILL, crash и перезапуск теряют
эти сведения; надёжное восстановление exact permits после них требует защищённого
persistent journal. Generic startup sweep остаётся полезен на перечисляемых цепочках,
но не заменяет такой журнал на mixed native nft. Автономного фонового retry нет:
повторение привязано к перечисленным cleanup/setup вызовам.

**Q14-F027 исправлена частично:** последующие [итоговые проверки](AUDIT-Q14-OWNED-SHUTDOWN.md)
передают неустранённые DNS/sysctl ошибки через worker и внешний supervisor; ошибки
задач и TUN текущего поколения также учитываются. Generic NAT и старые поколения ещё открыты. [Q14-F032](AUDIT-Q14-NAT-COMMANDS.md) позднее ограничивает каждую команду server NAT.
Общий срок операции, удержание mutex и чужие изменения правил требуют отдельных проверок.

Linux runtime, реальные firewall/TUN/DNS, устройства, native release-сборки,
SSH/systemd/Actions и бенчмарки не запускались. Остаются generic NAT outcome,
старые поколения и отдельный проект безопасного журнала восстановления.
