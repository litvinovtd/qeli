# Q25-F138: единый предел серверного INI

25 сентября 2026. База: `f996209c`. D07 остаётся **IN_PROGRESS**.

До исправления worker читал серверный INI через стабильный дескриптор без
ограничения размера; `check-config` и несколько CLI/панельных путей использовали
неограниченный `read_to_string`. Панель ограничивала HTTP body 16 МиБ, но
сериализация формы и восстановление из архива могли создать больший INI.
При ошибке чтения активного файла два редактора иногда подставляли стартовый
снимок для проверки revision, что позволяло принять устаревший запрос.

Теперь `config_source` ограничивает серверный INI **16 МиБ** до чтения.
Тот же loader используют worker, серверные команды CLI, панель, Quick Start,
история, preflight и восстановление архива. Все записи серверного INI в панели
проверяют размер сериализованного результата до создания rollback snapshot и
публикации; `set-web-password` также проверяет результат. Ошибка чтения
активного файла прекращает редактирование. Путь настройки brute-force в панели
проверяет, что файл не изменился между исходным чтением и созданием снимка.
Служебный JSON HTTP API сохранён; конфигурационный формат остаётся flat-INI.

Проверки на изолированной Linux-лабе `.11`: 16 тестов `config_source`, 33
теста редактора и Quick Start, тест отказа восстановления из архива,
`cargo fmt --check`, строгий `cargo clippy --lib --bins -- -D warnings`,
сборка бинарника и реальный `check-config` на sparse INI размером 16 МиБ + 1
байт. Тесты подтверждают отказ до разбора и отсутствие rollback snapshot при
превышении предела. Логи: `C:/Users/litvi/OneDrive/Documents/qeli/audit-debt-20260925/server-nat44-egress-phase/serverinilimitv3.log` и `serverinicliruntime.log` в том же каталоге.
