## Q14-F035, P2 — ожидания DNS lease и установка не имели общего срока

Предыдущая фаза NAT cleanup ограничила callback очистки DNS, но Drop lease и установка
по-прежнему ожидали firewall/registry mutex без срока. UDP, TCP и команды проверки при
установке получали отдельные бюджеты. Один набор DNS INPUT мог расходовать несколько
командных сроков после неограниченной очереди.

Установка одного набора теперь делит 15 секунд от входа между ожиданием mutex, поиском
утилиты, очисткой ранее завершённых поколений, вставкой/проверкой UDP/TCP и fallback для
пустой INPUT/ACCEPT. Поздний ответ команды не разрешает успех или следующий шаг установки.
При ошибке активированный lease уничтожается после освобождения блокировки setup;
откат получает отдельный бюджет очистки 15 секунд.

Очистка lease делит 15 секунд между обеими блокировками, поиском утилиты, проверками и
удалениями UDP/TCP. При истечении срока точные неподтверждённые записи сохраняются.
Отдельная очистка профиля/worker проверяет фактическое отсутствие; применённое, но поздно
подтверждённое удаление не доказывает успех истёкшей попытки. Общий NAT Budget теперь
указывает операцию в ошибке. Удалён прежний helper INPUT policy с отдельным сроком.
Параметры INI, API/ABI и wire-формат не менялись.

## Завершение поколения должно отмечаться до блокировки

Простая замена blocking lock на ограниченное ожидание оставила бы активную запись
после timeout до захвата mutex. Активные записи намеренно исключены из retry.
Теперь lease держит уникальный токен поколения с общим атомарным флагом retirement
в записи реестра. Очистка отмечает retirement до любой очереди; Drop самого токена
тоже делает это без блокировок и I/O. Реестр хранит точные правила до подтверждённой
очистки, в том числе после timeout/unwind. Старый токен не может завершить новое
поколение: флаг у каждого поколения свой.

Отметка может поступить во время callback очистки, уже после snapshot для retry.
Для новой модели нужны две проверки: перед регистрацией поколения повторно проверяются
наблюдаемые pending-записи; финальная очистка сообщает обо всех оставшихся записях,
активных или только что завершённых. Позднее retirement не теряется между snapshot
и проверкой лишь активных owner. Это необходимые защиты новой модели, а не утверждение,
что прежний bool под mutex уже имел такие гонки.

## Проверки

Четыре переносимые регрессии проверяют Drop токена при занятом реестре, старые токены,
retirement во время финальной очистки и во время регистрации замены. Семь новых
Linux-тестов покрывают expired/busy admission установки и очистки, настоящий Drop за
занятым firewall mutex, расход срока команды очередью, общий срок UDP/TCP, расход
setup-бюджета очисткой прежнего поколения, отдельное время отката после expiry и
запрет замены после неудачного отката до проверенного retry.

Тесты задержек используют реальные процессы/production collector, приватные файлы
правил и thread-local пути утилит. Короткие внедрённые сроки — 0–650 мс; production
использует 15 секунд. NAT/DNS timing-тесты используют общую модель и сериализацию.
PATH и firewall/sysctl хоста не меняются.

Одна новая privileged-регрессия ставит и снимает реальные DNS UDP/TCP правила для
IPv4 и IPv6 при INPUT DROP, сохраняя чужое правило администратора. Она проверяет

## Оставшиеся границы

Это сроки установки/очистки одного INPUT ruleset. Общая настройка DNS также может
ставить NAT redirect порта 53: его последовательность setup/rollback остаётся D05,
как и прочая установка NAT, клиентские routes и gateway. Разные ruleset и вызовы
очистки получают свои бюджеты; это не жёсткий предел 15/30 секунд для всей остановки
worker или подключения. Синхронные metadata, allocation/logging, spawn и kill/reap
не прерываются этим таймером. API и Drop синхронны; изоляция async scheduler не добавлена.

Retirement живёт в памяти процесса; отдельного фонового retry и persistent crash journal
нет. Повтор выполняется на явных границах profile/setup/final cleanup. После выхода
процесса точное владение требуется проверять отдельно. Backend/namespace identity,
mixed nft, внешние изменения и crash recovery сохраняют ограничения D04/D06/D10.
D05/D09 целиком не закрыты.
