# Q25-F130: допуск server worker после принудительной отмены

25 сентября 2026. Базовый коммит: `1d12549d`. D05 остаётся **IN_PROGRESS**.

`run_worker` хранил абстрактный сокет network namespace как обычную локальную переменную. При отмене future после начала сетевой работы сокет закрывался, хотя дочерние задачи профиля ещё могли завершаться, а синхронная запасная очистка — оставаться неполной. Второй worker в той же сети мог получить допуск внутри всё ещё работающего процесса. Штатный systemd worker выходит, а не отменяет этот future намеренно: находка относится к границе принудительной отмены/встраивания, а не к доказанной утечке при обычном SIGTERM.

Новый `WorkerLease` вооружается непосредственно перед первой мутацией NAT recovery. Ранние ошибки валидации по-прежнему освобождают его. Успешная окончательная остановка снимает защиту, а прежний порядок уничтожения Rust удерживает сокет до остальных ресурсов worker. Если future принудительно уничтожен или результат после допуска не подтверждён как успешный, дескриптор с close-on-exec остаётся занятым до выхода процесса. Это намеренный безопасный отказ: повтор в том же процессе запрещён; новый процесс выполняет имеющееся восстановление точных правил. INI/API/ABI не менялись.

Исправление исключает **повторный допуск** поверх старого worker. Оно не превращает синхронный `Drop` в async join и не даёт жёсткого стеночного срока shutdown. При принудительной отмене async-дети всё ещё могут получать abort во время запасной очистки; произвольный kernel/filesystem I/O и завершение процесса сохраняют прежние границы. Старые бинарники не участвуют в lease.

На изолированной .11 матрица реального worker TCP/UDP × off/manual/route/nat66 прошла 8/8 с сохранёнными снимками firewall, маршрутов, интерфейсов и forwarding до/после.
