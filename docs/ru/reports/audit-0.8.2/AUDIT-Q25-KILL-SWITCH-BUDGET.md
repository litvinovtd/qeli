## Q25-F085, P2 — таймаут выдавался заново на каждую команду

`disengage` ждал общий operation mutex без ограничения. Затем каждая проверка/удаление
jump и цепочки получала отдельные 15 секунд. IPv4 и IPv6 также не делили срок.
При медленном backend даже конечное число попыток удаления давало длительную остановку:
ограничение одной команды не ограничивало последовательность. Owner/namespace были
сохранены, но ограниченного срока этой операции не было.

## Исправление

Одна попытка `disengage` получает 15 секунд при входе. Ожидание operation mutex через
`try_lock`, все проверки и изменения обеих семей используют один абсолютный deadline.
Срок проверяется до/после admission, перед запуском и после завершения команды, а также
перед удалением owner из registry. После его истечения новый child не запускается;
поздний успешный ответ не превращает операцию в успешную.

Deadline хранится в контексте попытки, не в owner. При ошибке сохраняются обе исходные
семьи, пути инструментов и закреплённый namespace. Повторный `disengage` получает новый
срок, заново проверяет фактические jump/chain и освобождает owner только после успеха.
Уже применённая мутация могла состояться до timeout: это частичная очистка, не обещание
сохранения всех firewall-правил. Прежние проверки identity и точных целей сохраняются.

Не менялись INI-параметры, ABI, формат состояния и правила допуска подключения.
Речь о Linux standalone kill-switch; budgets engage/refresh и gateway/NAT/routes
этим изменением не закрыты. Установка/refresh сохраняют прежние командные сроки.

## Проверки

Пять новых регрессий:

- Истёкший deadline не принимает свободный mutex; занятый mutex возвращает timeout.
- Просроченный контекст не запускает ни одной команды очистки.
- Ответ об успехе, пришедший после срока, отклоняется.
- Обе семьи делят общий срок; после его истечения новые проверки второй семьи
  не стартуют, owner сохраняется и отдельная попытка завершается успешно.
- Fixture-команда реально удаляет частный файл jump и затем задерживает ответ.
  Timeout сохраняет owner и цепочку, не запускает вторую семью; повтор проверяет
  остатки, завершает очистку обеих семей и освобождает owner.

Три проверки portable, две используют настоящие shell-child/collector в Linux,
private fixture-файлы и реальный pinned namespace. Они не изменяют firewall хоста.
Подмена команд не меняет PATH или environment. Это подтверждение orchestration и
командной границы; работу с kernel firewall покрывают существующие privileged tests.

## Оставшиеся границы

Это общий deadline команд и ожидания operation mutex, не жёсткий wall-clock предел
всей остановки клиента. Проверка namespace, короткие registry mutex, filesystem I/O,
spawn и kill/reap не получают принудительного прерывания таймером. Этот API синхронный.
Остановка cleanup по сроку не делает уже выполненные удаления атомарными и не заменяет
persistent crash recovery. После выхода процесса его registry недоступен: восстановление
оставшихся правил требует проверки администратором. D04/D05/D09 целиком не закрыты.
