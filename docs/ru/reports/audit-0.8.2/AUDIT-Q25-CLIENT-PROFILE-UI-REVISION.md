# Q25-F177: ревизия клиентского UI и применение активного профиля

1 октября 2026. База: dfa4f022. D08 остаётся **IN_PROGRESS**.

Android-редактор, per-app picker, popup-меню и подтверждение удаления запоминали индекс профиля. Пока окно открыто или ожидается список приложений, другой результат импорта/сохранения мог изменить порядок: правка или удаление попадали в другую строку. Windows/macOS Edit/Delete ожидали модальное окно и асинхронную остановку туннеля; сохранение после изменения списка тоже могло применить устаревший результат. Android при изменении INI/per-app активного профиля сохранял новую версию, но работающий VpnService продолжал использовать прежний снимок без явного сообщения пользователю.

Android теперь повышает ревизию при каждом успешном сохранении и проверяет её перед отложенными действиями. Desktop-клиенты проверяют ревизию до остановки и повторно после неё; при конфликте после остановки пытаются восстановить прежний туннель, если профиль ещё существует и туннель не запущен. Общая EN/RU строка объясняет отказ. Android показывает EN/RU напоминание о ручном переподключении при изменении конфигурации активного профиля; это поведение описано в README.

Проверки: Android compileDebugKotlin и 156 JVM-тестов прошли с проверенной host DLL; dotnet build QeliWin и QeliMac с --no-restore прошёл без предупреждений и ошибок; git diff --check прошёл. UI fault-injection на Android, Windows VM и Mac не выполнен. Ревизии защищают только операции одного окна/процесса; внешняя правка desktop store, межпроцессное разрешение конфликтов и полное runtime-подтверждение reconnect остаются открытыми в D08.
