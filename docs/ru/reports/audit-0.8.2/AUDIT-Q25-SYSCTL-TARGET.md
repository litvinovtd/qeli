## Q25-F083, P1 — восстановление по имени меняло чужой интерфейс или теряло оригинал

Реальный worker на базе `1b466a83` изменял WAN `accept_ra` с 1 на 2. При остановке
после rename `wan0 → wan-old` журнал исчезал, а исходный интерфейс оставался с 2.
После delete/recreate `wan0` старое значение 1 записывалось в новый интерфейс,
у которого до остановки было 2. Принудительное повторное использование исходного
ifindex давало тот же результат. Все три дефекта воспроизведены на `.11` в отдельных
network/mount/PID namespaces; работающий сервер `.10` не изменялся. Нулевые коды
baseline-проб означают успешное воспроизведение дефекта, а не корректность старого кода.

Имя, наличие интерфейса и ifindex не доказывают непрерывность жизни объекта. Отсутствие
старого пути также недостаточно: при rename исходный интерфейс остаётся жив.

## Исправление и границы

Журнал `sysctls.state` переведён на версию 3. Для именованных per-interface
`rp_filter`/`accept_ra` запись содержит случайный идентификатор lease и stamp открытого
procfs-файла `dev:inode:ctime_sec:ctime_nsec`. Захват read/write fd происходит до чтения
original и публикации владельца. Чтение, запись, проверка результата и восстановление
работают через этот fd с offset 0. Проверяются procfs, тип файла, ошибки/короткая запись,
лимит чтения и namespace Guard вокруг I/O. `all`/`default` и глобальные параметры
не получают per-interface identity.

Fd живёт в ограниченном process-local registry вместе с удерживаемым namespace Context.
Записи удаляются по проверенному загруженному/сохранённому журналу; лимит — 256 объектов
на процесс, а не 256 всех fd. Свидетельства неопределённой публикации сохраняются до
следующей проверки журнала. Служебный state не является пользовательским конфигом:
конфиги остаются INI, новых параметров и изменений ABI нет.

Другой процесс может разделить lease только при совпадении stamp и подтверждённом
живом владельце v3. Владелец проверяется **после** открытия кандидата: иначе смерть
между проверкой PID и open могла бы освободить старый inode. Stamp включает ctime,
поскольку procfs использует циклический счётчик inode. Это свидетельство при живом
владельце, а не durable generation интерфейса. Соответствующие механизмы находятся в
[Linux v6.12 proc_sysctl.c](https://github.com/torvalds/linux/blob/v6.12/fs/proc/proc_sysctl.c).

Восстановление не открывает имя заново. После rename/delete/recreate старый fd может
вернуть ENOENT; Qeli сохраняет original, сообщает ошибку и продолжает независимую
очистку. После потери всех живых дескрипторов, включая SIGKILL, даже совпадение текущего
stamp не разрешает автоматический replay. Startup recovery отказывает до запуска
профиля. Если `original == managed`, записывать нечего и запись можно освободить без
обращения к интерфейсу. Подтверждённое внешнее изменение исходного объекта сохраняется.

Таким образом, ошибочная запись в новый интерфейс и молчаливая потеря original закрыты
отказом при неопределённости. Прозрачное восстановление после rename/crash не заявлено:
потребуется ручная проверка или плановый reboot. Durable namespace generation глобальных
записей после уничтожения namespace остаётся D02. Конкурентная подмена привилегированным
администратором не получает атомарной kernel-транзакции. Persistent firewall/DNS/routes
и корректность нескольких независимых worker firewall остаются D04/D10.

## Переход v2 → v3

Непустые v1/v2 текущего boot-id сохраняются без автоматической миграции. V2 возвращает
`legacy v2 host sysctl journal lacks live descriptor ownership`. До обновления нужно
остановить старых участников и завершить восстановление, пока исходные интерфейсы
подтверждены. После rename/replacement нельзя вслепую запускать прежнее восстановление
по имени. Альтернатива — плановая перезагрузка хоста. Пустые v1/v2 и валидное состояние
предыдущего boot-id принимаются без replay старых значений. Повреждённый журнал и
неизвестная версия не обходят проверку через старый boot-id. Одновременная работа
разных версий журнала не поддерживается. Ручное изменение version/boot-id или удаление
записи ради запуска теряет исходные сведения. [Диагностика](../../manuals/TROUBLESHOOTING.md).

## Проверки окончательного снимка

- 11 новых portable регрессий: последний владелец, замена/rename/delete,
  замена между original-read и записью, потеря cache при crash, отсутствие изменений,
  разделение между cache, смерть свидетеля во время open, миграция, лимит registry,
  одинаковый inode с другим ctime. Удалена устаревшая проверка, разрешавшая забыть
  original после исчезновения имени; inventory probe больше не используется.
- Native Linux: production fd исходного dummy-интерфейса не читает и не меняет новый
  интерфейс с тем же именем и принудительно повторённым ifindex 42. Старый fd возвращает
  ENOENT, новое значение 2 сохраняется.
- **1468 host unit + 71 config integration PASS**. Все девять host/feature/cross/lint
  команд PASS; Windows Rust 1.98, Linux target Clippy с единственным прежним исключением
  `chunks_exact_to_as_chunks`.
- Linux Rust 1.97: **1932 обычных + 29 привилегированных PASS**. Два служебных child-теста
  не запускаются отдельно; родительские тесты вызывают их. **8 worker lifecycle E2E PASS**:
  TCP/UDP × off/manual/route/nat66, setup, отклонённый reload, control lease, stop/cleanup.
- **5 дополнительных worker E2E PASS**: rename, replacement, reused ifindex, SIGKILL/restart,
  два отдельных процесса с общим sysctl. Первые три сохраняют original и отказывают cleanup,
  не меняя replacement; после SIGKILL новый профиль не запускается, независимые global
  значения восстановлены. Два процесса держат 2 → 1 → 0 владельцев и возвращают RA 1
  только после последнего stop. Эта проверка подтверждает совместное владение sysctl,
  а не изоляцию firewall независимых worker.
