# Q25-F161: ошибки перечисления при восстановлении архива

1 октября 2026. База: 5ceeb390. D07 остаётся **IN_PROGRESS**.

При разборе импорта архива обнаружены четыре перечисления каталогов через flatten(). Если read_dir успешно открывал каталог, но возвращал ошибку для отдельной записи, код молча пропускал её. В staging это могло исключить файл из проверки или списка файлов архива, при публикации — дать неполное восстановление с ответом об успехе, при exact cleanup — скрыть непросмотренный live-файл.

Теперь ошибка чтения записи в staging останавливает восстановление до публикации, а ошибка при публикации возвращает серверный отказ. Ошибка просмотра live-каталога в exact cleanup попадает в предупреждение о неполной очистке. Ошибка проверки staging получает HTTP 500, как и другие серверные I/O отказы. Служебный формат архива и INI не менялись.

На изолированной лабе .11 прошли форматирование, 26 обычных backup-тестов, строгий Clippy и два native root-теста: backup → overlay/exact restore в отдельном mount/network namespace и отказ snapshot при нечитаемом файле. Работающая служба .10 не затронута. Логи: archivels1.log, archivenative1.log в C:/Users/litvi/OneDrive/Documents/qeli/audit-debt-20260925/server-nat44-egress-phase. Пофайловую ошибку итератора read_dir искусственно не вводили; этот редкий отказ проверен по веткам кода, а существующие тесты подтверждают штатный путь.
