## F300: бесконечное ожидание, устаревшие ответы и пересечение snapshot-опросов

Запрос настроек использовал continuation без предела ожидания. Потерянный ответ
удерживал вызывающую задачу бесконечно; отмена не завершала ожидание. Ответ прежнего
туннеля мог вернуть успех после переподключения. Опрос snapshot отправлял запрос
каждую секунду, даже если предыдущий callback ещё не пришёл; несколько путей также
сразу запрашивали snapshot при переходе Connected.

ProviderMessageRequest использует существующий exactly-once helper, отменяемое
ожидание и deadline вызывающей задачи 20 секунд (15 секунд провайдера плюс 5 секунд
для IPC). Синхронный ответ/ошибка отправки, отмена до park, timeout и повторный/поздний
callback сохраняют один результат. Ответ или ошибка обрабатываются только при
актуальных поколении подключения, session и эпохе статуса; устаревший timeout тоже
превращается в отмену и не показывает ошибку настроек прежнего подключения.

Опрос snapshot допускает один незавершённый запрос на эпоху статуса. Ответ, включая
nil/невалидные данные, и синхронная ошибка освобождают только свой запрос. Повторный
или старый callback не освобождает запрос новой эпохи. Если ответ не приходит, опрос
в этой эпохе прекращается; переход статуса сбрасывает владение для нового опроса.
Это не глобальный предел callback ОС при произвольном числе переходов статуса.

Timeout/отмена завершают только Swift-ожидание. Уже отправленное сообщение ОС или
применение настроек провайдером не отменяется и не откатывается; OS lease из F297
по-прежнему освобождает реальный callback. Завершение реальных IPC callback — OPEN.

## F301: изменяемый пароль пересекал точки ожидания backup UI

Задача экспорта читала passphrase при фактическом старте, а имя файла повторно
читало живое поле после шифрования. Изменение поля могло дать зашифрованному файлу
имя JSON или незашифрованному — имя encrypted backup. Восстановление читало пароль
после асинхронного чтения файла, поэтому редактирование меняло пароль уже начатого
импорта.

Экспорт фиксирует пароль в событии кнопки; BackupDocument определяет имя по готовым
байтам через существующий discriminator envelope. Восстановление фиксирует пароль
до чтения выбранного файла и занимает один preparation slot до окончания decode.
Кнопки исключают параллельную подготовку; pending confirmation исключает второй
restore, заменяющий ожидающий подтверждения payload.

Профили INI, совместимый с Android JSON-контейнер backup и QELI-ENC-1 сохранены.
Поддержка конфигураций JSON не возвращается. Реальные presentation/dismissal SwiftUI,
FileDocument/FileImporter не runtime-проверены; остановка/ожидание detached crypto
при закрытии экрана не объявляются реализованными или подтверждёнными.

## F302: неиспользуемая Swift wire-crypto оставалась в сборке приложения

Приложение уже исключало Protocol, но компилировало Crypto/PacketCipher и
Crypto/KeyDerivation, вызовы которых есть только в conformance-тестах.
X25519KeyPair не имел вызовов даже в тестах; handshakeTranscript,
serverAuthenticationProof и clientKeyProof также не имели вызовов.

App target исключает Crypto вместе с Protocol; XCTest явно включает оба каталога.
Удалены неиспользуемый файл key-pair и три auth-helper. Classic/hybrid HKDF и
PacketCipher сохранены без изменения как conformance support в test target.
Storage/BackupCrypto напрямую использует CryptoKit. Production Rust crypto, ABI,
native-библиотеки и форматы шифрования/backup сохранены. По membership исходников
не объявляются подтверждёнными размер бинарника или компиляция Xcode.
