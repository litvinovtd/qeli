# Q25-F145: SIGHUP и рестарт при смене users_file

1 октября 2026. База: `28e07945`. D07 остаётся **IN_PROGRESS**.

После Q25-F144 повторная загрузка по SIGHUP всё ещё отбрасывала признак доверия открытого INI. Она могла принять нестандартный `auth.users_file` из файла с правами `0666` и заменить живую VPN-auth базу, хотя startup и `check-config` такой файл отвергают. При смене пути SIGHUP загружал новых пользователей, но панель и control socket продолжали записывать в путь из startup-снимка. Это рассогласовывало источник чтения и записи.

SIGHUP теперь сохраняет решение о доверии того же inode и отвергает новый `users_file`, если изменился путь либо нестандартный путь пришёл из недоверенного INI. При отказе живые пользователи и brute-force состояние остаются прежними. Полный перезапуск применяет смену пути. Все ответы редактора INI/формы/истории выставляют `needs_full_restart` также для смены `auth.users_file` и `web.persist_session_key`. Прямой endpoint worker-only restart отказывает до остановки работающего worker. Preflight полного и worker-рестарта заново читает один файловый снимок и проверяет `users_file` и явные `identity_key` до отправки команды рестарта; иначе рестарт мог оставить сервер без нового процесса.
