# Q25-F175: защита мобильных профилей после отказа загрузки

1 октября 2026. База: a6a93c35. D08 остаётся **IN_PROGRESS**.

Android читал encrypted profile store до блока обработки ошибок. Повреждённый шифртекст или ошибка Keystore могли аварийно завершить Activity. Если содержимое расшифровывалось, но не проходило проверку, Activity показывала временный шаблон и не записывала его при старте, однако последующий Add/Edit/Import мог заменить исходное хранилище. iOS при любой ошибке ProfileStore.load показывал временный начальный архив; обычная операция сохранения могла записать его поверх нечитаемой записи. Кроме того, UserDefaults.string(forKey:) трактовал значение другого типа как отсутствие ключа и инициализировал новый архив.

Android теперь ловит ошибки чтения, сохраняет флаг отказа, показывает локализованное предупреждение и запрещает все обычные записи до успешного повторного запуска. Подтверждённый пользователем restore backup остаётся явным путём замены. Отказ первой записи пустого хранилища также попадает в этот режим. iOS отличает отсутствие ключа от значения неверного типа; AppModel блокирует сохранение и экспорт временного архива после ошибки чтения. Только подтверждённый restore может заменить нечитаемый store. Добавлен iOS-тест, который проверяет сохранность значения UserDefaults неверного типа после неудачной загрузки. Пользовательский конфиг остаётся INI; JSON используется лишь как служебный контейнер и формат backup.

Проверки: Android compileDebugKotlin и 154 JVM-теста прошли с проверенной host DLL; git diff --check прошёл. iOS-тест и сборку не запускали: Mac/Xcode отсутствуют по согласованному ограничению стенда. Android UI fault-injection также не выполнен. Долговечность iOS UserDefaults.set и конкурентные сценарии profile store остаются в D08.
