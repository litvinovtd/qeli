# Q05: сроки и лимиты чтения сетевого состояния preflight

Дата: 23 сентября 2026. База: `fd03a292`.
Разделы 05 и 14: **IN_PROGRESS**. Q05-F001 исправлена; полная проверка транзакций открыта.

## Подтверждённая проблема

**Q05-F001, P2 — четыре команды preflight не имели срока и лимита вывода.**
В `qeli/src/server/preflight.rs` прямой `std::process::Command::output` запускал
IPv4/IPv6 `ip ... addr show` и `ip ... route show`. Зависание backend/pipe могло
удерживать вызов без ограничения, stdout/stderr целиком накапливались в памяти.

Preflight используется до запуска панели и worker, в check-config, Quick Start,
сохранении Form/INI, восстановлении history и backup. В изменяющих конфигурацию
обработчиках он выполняется при удержанном `config_write_lock`: задержка мешает
следующим транзакциям. Вызывающие места проверены по исходникам, HTTP E2E не запускался.

## Исправление

Все четыре команды используют существующий `crate::system_command::Command`:
15 секунд на команду, по 16 МиБ для stdout и stderr. Обе трубы читаются одновременно;
при превышении лимита частичный результат не поступает в парсер. Runner запрашивает
завершение процесса и ожидает его, сохраняя существующее владение Linux process group.
Нового runner, shell или INI-параметров нет; argv и порядок наблюдений сохранены.

Сборка snapshot выделена в функцию с передаваемым исполнителем для тестирования
ошибок без обращения к сети хоста. Действующая политика сохранена:

- Ошибка запуска/чтения, timeout, превышение лимита или ненулевой exit любого IPv4
  probe дают `None`. `run()` предупреждает о недоступном состоянии и допускает запуск.
- Ошибки IPv6 адресов и маршрутов обрабатываются независимо. Успешный IPv4 snapshot
  и доступная часть IPv6 сохраняются; недоступная часть пуста.
- Пустой вывод с успешным exit остаётся допустимым наблюдением. Это не отказ команды.
- Наблюдаемая коллизия по-прежнему приводит к отказу. Tentative IPv6 адреса учитываются
  при поиске коллизий, но не считаются готовыми для egress.

Политика fail-open не означает, что отсутствие коллизий доказано при недоступном
состоянии. Частичный отказ IPv6 по-прежнему не получает отдельного предупреждения.

## Открытые границы

Срок относится к отдельной команде. Четыре последовательных probe и несколько вызовов
preflight внутри одной операции могут занять дольше 15 секунд. Общего срока транзакции
нет. Синхронный вызов из async handler по-прежнему занимает поток executor и удерживает
блокировку записи; перенос на runner сам по себе не исправляет это.

Spawn/kill/reap и непрерываемые kernel waits не имеют жёсткой общей верхней границы.
Linux process-group сигналы здесь не исполнялись; потомок, покинувший группу, не покрыт
гарантией её завершения. Snapshot из нескольких команд не атомарен к изменениям сети.

Read-only path monitor позднее перенесён в [Q25-F020](AUDIT-Q25-PATH-MONITOR.md).
Остальные команды клиентских routes/kill-switch/gateway ещё требуют переноса с проверкой ownership при неизвестном результате мутации. Старые поколения
профилей/TUN, Linux API/restart/restore, реальные firewall/sysctl/systemd, устройства,
native release и новый бенчмарк не закрыты этим проходом.
