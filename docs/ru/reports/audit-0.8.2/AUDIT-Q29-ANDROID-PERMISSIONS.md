# Q29: владение запросом разрешений при подключении Android

<!-- normative-sync: q29-android-permission-flow-v1 -->

F280 исправляет три ошибки Activity: позднее разрешение могло запустить VPN после
отмены, использовать изменённый/переключённый профиль либо потерять запрос после
пересоздания Activity. Q29 остаётся IN_PROGRESS; общий план 28/37 разделов (75.7%).
Здесь подтверждён этот фикс, а не весь Android gate.

## Поведение и исправление

MainActivity хранит первоначально разобранный и проверенный VpnConfig в ViewModel.
Ответы на разрешения уведомлений и VPN должны принадлежать ожидаемой стадии.
Отключение отменяет конфигурацию; старый callback обрабатывается до того, как новый
запрос сможет использовать тот же launcher. Отказ и ошибка запуска освобождают
запрос. Сервис получает конфигурацию однократно.

Пересоздание Activity сохраняет запрос в памяти. Он не записывается в Bundle или
настройки: смерть процесса теряет запрос и требует явного повторного подключения.
Восстановление сервиса и Android always-on этим не изменяются.

## Проверки

Один итоговый тестовый APK и корректный зашифрованный архив INI-профиля применены
к старому и исправленному debug APK в изолированном API34 x86_64 AVD лабы .11.
Три теста используют реальные ActivityScenario, callback ActivityResultRegistry,
сервис и JNI. Ожидаемая стадия разрешения уведомлений и её результат инъецируются;
показ системного диалога и поворот при открытом диалоге этот набор не подтверждает.

| Сценарий | Старый APK | Исправленный APK |
|---|---|---|
| Отмена, ожидание остановки сервиса, затем позднее разрешение | FAIL: отменённый VPN запускается | PASS |
| Изменение профиля во время ожидания | FAIL: ClientHello получает новый адрес | PASS: исходный адрес |
| Пересоздание Activity с запросом | FAIL: запрос потерян | PASS |

Свежие JVM-тесты: 179 PASS, семь новых тестов владения запросом; lint: 0 ошибок,
55 предупреждений. Пересобран обычный production R8 Release с подписью лабы.
Реальный импорт INI и включение Android lockdown предшествуют отключению и повторному
подключению обычной кнопкой Activity. При отключении проба обычного UID блокируется;
после подключения четыре полных ответа IPv4/IPv6 TCP/UDP подтверждены размером,
SHA и источником TUN.

Этот же TCP-прогон проверяет strict DoT: недоверенный CA, доверенный CA, несовпадение
SAN и восстановление; 16 полных payload-проб, 192 burst-пробы (48 после stop заблокированы),
13 DNS-операций/ответов, включая четыре доверенных A/AAAA. Независимый capture:
0 новых физических запросов в проверенном защищённом окне, 0 kernel drops.
Пауза через UI проверена одной IPv4 UDP-пробой, а не полной матрицей утечек на границе.
Универсальной гарантии первого пакета сразу после перехода нет. Четыре теста обвязки
и два отклонения некорректных CLI проходят до изменения стенда.

Release не debuggable. Повторно использован неизменённый framework Java probe APK
предыдущего DoT-пакета с той же подписью лабы; matching Release instrumentation
NOT RUN. Product JNI/сервер/managed не менялись; прежние проверки всех транспортов
сохранены, но заново на новом APK не выполнялись.

## Доказательства и ограничения

Четыре предварительных запуска не засчитаны: отзыв разрешения тестируемого приложения
во время instrumentation завершил тот запуск; модальный диалог задерживал
инъецированный результат; три последующие предварительные фикстуры использовали
неверное поле архива. Итоговый A/B использует `cfg`, как ProfileStore. Ошибки фикстур
не становятся регрессиями продукта или PASS. Все семь запусков восстановили
host/service, настройки и постоянный userdata AVD; Release также восстановил CA stores.
Сервер .10 не затронут.
