# Q25-F120: повторная проверка IPv6 WAN при обновлении exit-node

Дата: 25 сентября 2026. Исходный коммит: `842890d0`. D06: частичное закрытие.

## Проблема и исправление

На границе platform COMMIT `refresh_exit_paths_if_active` проверял IPv4 default route после установки правил, но для IPv6 повторял проверку только после включения forwarding, **до** команд `ip6tables`. При смене IPv6 default route во время firewall batch функция могла вернуть успех с NAT66/FORWARD для уже неактивного WAN.

После IPv6 rule batch добавлена такая же проверка, как для IPv4. При исчезновении или смене default route обновление завершается ошибкой; имена старого и нового WAN остаются в памяти для проверяемой очистки. Отмена установки правил на старом WAN в этом месте не выполняется: она могла бы нарушить активные потоки и принадлежит teardown текущего поколения.

## Проверки и границы

Модель firewall переключает IPv6 default route во время `TCPMSS` команды, уже после программирования NAT66. Регрессия требует ошибки COMMIT, сохранения обоих WAN targets и успешного удаления их правил. Локально прошли 108 gateway-тестов. Linux `.11`: 1/1 адресная регрессия, 109/109 gateway-тестов и scoped `cargo clippy --lib --bins -- -D warnings` PASS; сверены 362 исходных файла (SHA256 архива `801f41e64e30a7fd8a5cb2d56e648ecf7a96bd14dbf8a61d8c2b58283af6c73c`). Первый слишком узкий фильтр выполнил 0 тестов; результаты приведены только после исправления фильтра. Исходники и логи: `C:/Users/litvi/OneDrive/Documents/qeli/audit-debt-20260925/gateway-ipv6-roam-phase/`.

Проверка устраняет наблюдаемое окно между rule batch и COMMIT, но не делает выбор WAN атомарным с изменением таблицы маршрутизации после последнего запроса. Firewall selector пока привязан к имени; rename/reuse и динамическое появление IPv6 после admission остаются D06/D10. INI, API и ABI не менялись; пользовательский синтаксис не затронут.
