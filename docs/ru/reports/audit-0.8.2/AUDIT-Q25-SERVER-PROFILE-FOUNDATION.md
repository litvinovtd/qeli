# D07: базовые поля серверного профиля

1 октября 2026. Сверены 63 записи профильного fixture вне семейства `obf.*` (включая по одному примеру двух динамических семейств `pool.*.reservation.<user>`). Перечень взят из [генератора](../../../../scripts/gen_roundtrip_fixture.py), чтение/запись — из [INI-кодека](../../../../qeli/src/config/server_ini.rs). Это статическая трассировка применения; полный round-trip уже проверен в Q25-F152. Функции `obf.*` и смешанные сценарии сохранения/перезапуска выделены в оставшуюся часть D07.

| Ключи INI | Проверка и runtime-потребитель |
|---|---|
| `enabled`; имя секции `[profile:*]` | [Общий валидатор](../../../../qeli/src/server/mod.rs) требует хотя бы один включённый профиль; выключенные профили не запускаются и их остальные поля намеренно не валидируются. Имя участвует в выборе identity, регистрах профилей и ресурсах хоста. |
| `identity_key` | Проверка доверенного пути и чтение приватного ключа перед запуском worker; при отсутствии ключа применяется профильный путь по имени. |
| `bind.address`, `bind.port`, `bind.transport`, повторяемый `listen` | Проверка транспортов и пересечений listener адресов; TCP/UDP listeners создаются до объявления профиля готовым. Дополнительные listeners используют тот же TUN, пул и identity. |
| `roaming.enabled`, `grace_secs`, `max_orphaned`, `max_orphan_bytes` | Проверка feature flag и границ; политика передаётся TCP/UDP обработчикам и менеджеру сессий. Неактивная функция не начинает roaming сама по себе. |
| `tun.ip_mode`, `name`, `address`, `ipv6_address`, `mtu`, `device_type`, `tx_queue_len`, `queues` | Проверка семейств, адресов, MTU и интерфейса; [установка TUN](../../../../qeli/src/server/mod.rs) создаёт очереди, адреса и длину TX-очереди. `queues=0` — auto; явное значение сверх 256 теперь отклоняется до запуска вместо скрытого ограничения. |
| `pool.cidr`, `pool.exclude`, `pool.ipv6.cidr`, `pool.ipv6.exclude`, оба `pool.*.reservation.<user>` | Проверка диапазона, конфликтов между профилями и адресов пользователей; allocator выдаёт IPv4/IPv6 и резервирует указанные адреса. IPv4-настройки не действуют в IPv6-only профиле, IPv6-настройки — в IPv4-only. |
| `routing.client_to_client`, `forward_private`, `nat.enabled`, `nat.interface` | Проверка совместимости и интерфейса; ACL/прямой путь между клиентами, IPv4 forwarding и NAT44 выбираются при установке профиля. NAT44 имеет приоритет над `forward_private`. |
| `routing.ipv6.mode`, `interface`, `ndp_proxy`, `ndp_proxy_interface` | Проверка сочетаний `off/manual/route/nat66`; IPv6 firewall/forwarding и NDP запускаются раздельно. При `manual` внешний firewall и forwarding принадлежат администратору. |
| `routing.post_up`, `post_down` | Выполняются с root-правами только из доверенного файла; панель не может задать или изменить их. `post_down` требует штатной остановки. |
| Повторяемый `route` с CIDR/gateway/metric/description | Проверка лимита и семейства, затем выбор профильных или пользовательских маршрутов при ответе аутентификации. `description` — метаданные панели/INI, не часть сетевого правила. |
| `dns.enabled`, `listen`, `listen_ipv6`, `port`, `upstream`, `upstream_protocol`, `cache_size`, `timeout_secs`, `blocklist`, `push_servers` | Проверка listener, upstream и ресурсных лимитов; [DNS proxy](../../../../qeli/src/server/dns.rs) получает конфиг при запуске. `push_servers` независимо отправляется клиенту; для tunnel DNS клиент применяет первый адрес. При выключенном proxy его поля сохраняются, но proxy не запускается. |
| `dhcp.enabled`, `listen`, `pool_start`, `pool_end`, `lease_time_secs`, `domain_name` | Проверка IPv4-пула и безопасного bind; [DHCP](../../../../qeli/src/server/dhcp.rs) получает границы lease и опции. При выключенном DHCP остальные поля не запускают сервис. |
| `perf.tcp.*`, `perf.udp.*`, `perf.tun.read_buffer_size`, `perf.connection.*` | Проверка размеров/лимитов, настройка сокетов TCP/UDP, TUN reader, допуска сессий и idle/handshake таймеров. TCP-поля в UDP профиле и наоборот остаются в INI для смены транспорта, но не действуют на другой транспорт. |

Все действующие профильные поля применяются при создании **worker поколения профиля**, а не через live reload панели. `check-config`, старт и записи панели используют общий `validate_profiles`; SIGHUP без рестарта worker не переустанавливает изменённый профиль. На изолированной Linux-лабе `.11` прошли 78 серверных тестов (включая новую границу `0/256/257`), `cargo fmt --check` и строгий Clippy. Сервисы лабы не изменялись. Проверка 63 записей по исходникам не заменяет пакетный runtime-прогон каждой комбинации. Остались `obf.*`, смешанная матрица save/reload/import и гонка с внешним редактором без advisory lock.

Продолжение 2 октября: [Q25-F209 в реестре](../../plans/AUDIT-DEBT.md) закрывает смешанные API save/INI/history/Quick Start/archive/restart проверки D07 и фиксирует обязательный sidecar lock внешнего писателя. Исторические числа выше не являются новым прогоном. Сетевые комбинации и итоговая сертификация остаются D10/D15.
