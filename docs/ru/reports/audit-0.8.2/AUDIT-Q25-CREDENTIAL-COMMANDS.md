# Q25/Q33: ограниченное выполнение команд пароля и ранняя остановка клиента

Дата: 23 сентября 2026. Исходный коммит: `965fdcc8`. Полный аудит: **IN_PROGRESS**.

## Находки и исправления

**Q25-F001, P2 — блокирующий поставщик пароля без ограничений.** Linux-клиент вызывал
std::process::Command::output внутри async startup. Зависший поставщик мог бесконечно
занимать поток runtime, а stdout/stderr полностью накапливались до проверки размера
готового пароля. Длинный токен отклонялся слишком поздно для ограничения памяти.

Новый сборщик использует тот же OwnedProcess, что и hooks: закрытый stdin, Linux process
group, резервное завершение shell и kill-on-drop. Shell задан как `/bin/sh`, без поиска
через PATH. Выполнение, EOF stdout и ожидание shell имеют общий срок 30 секунд. В памяти
сохраняется до 16 KiB сырого stdout до trim; превышение завершает процесс и отклоняет
весь результат. UTF-8 проверяется строго. Лимит AUTH и приоритет pass/password_file/
password_command сохранены. Новых INI-ключей нет. GUI по-прежнему сохраняют эти поля,
но не исполняют команды.

Для пароля не используется диагностический хвост hooks: потеря начала вывода не должна
создавать другой допустимый пароль. Буфер чтения 4 KiB, заранее выделенный буфер вывода
16 KiB и итоговая строка обнуляются при Drop. Сырой Vec не перераспределяется с оставлением
ранних копий в освобождённой памяти. Это не гарантия удаления всех копий из shell, ОС или
всего клиента.

**Q33-F002, P1 — раскрытие stderr через ошибку запуска.** При ошибке поставщика весь
stderr попадал в anyhow error, включая возможные секреты или раскрытые shell-аргументы.
Теперь stderr сразу перенаправляется в null: pipe не заполняется, данные не сохраняются
для журнала. Ошибки содержат только категорию/ошибку ОС/статус выхода, без вывода или
команды. Debug типизированных ошибок также не содержит полей с секретными байтами.

**Q14-F020, P2 — обработка остановки регистрировалась после получения пароля.** Поставщик
запускался до регистрации SIGINT/SIGTERM. При изолированной process group обычное
завершение Qeli в этот момент могло оставить поставщика живым. Signal streams теперь
регистрируются синхронно до его запуска и используют тот же токен отмены, что активный
carrier и reconnect backoff. Уже запрошенная остановка не допускает spawn; остановка
во время чтения завершает группу и дожидается shell до штатного выхода из startup.

SIGUSR1 watcher, diagnostic sampler и stop watcher теперь принадлежат клиентскому JoinSet.
Его Drop отменяет их при ошибке запуска, возврате или отмене. Это владение задачами,
но не асинхронный финальный drain и не гарантия отмены синхронного диагностического I/O.
Дополнительный разбор клиентской очистки/мониторинга задач ещё нужен.

**Q34-F001, P2 — не собиралась библиотека только с server feature.** Дополнительный
прогон `--no-default-features --features server --lib` выявил шесть отсутствующих импортов
TUN. В исходном коде Linux TUN был доступен только при client, хотя нужен и серверу.
Теперь он собирается при любой из этих опций. В CI добавлены server library без client
и standalone client без server, рядом с полными/FFI проверками. Новый server executable
не вводится: существующий бинарник qeli всё ещё требует обе опции.

## Проверка

- Девять новых переносимых тестов: точный лимит/превышение, строгий decode и trim,
  полный stdout реального процесса с шумным stderr, отсутствие секретов в ошибках/Debug,
  ошибки spawn/read, overflow реального потомка, timeout без блокировки runtime,
  принудительная отмена, кооперативная остановка и запрет spawn при заранее заданном stop.
  Часть проверок объединена в одном сценарии.
- Четыре новых Linux-теста: `/bin/sh` с закрытым stdin, deadline после закрытия stdout,
  timeout/отмена при потомке с открытым stdout после выхода shell. Выполнен только
  cross-check, без запуска на Linux. Тесты кооперативной остановки внедряют локальный
  stop event; это не проверка сигналов ОС и не полный клиентский E2E.
- **812 host unit + 52 editor/policy + 7 examples + 12 server INI = 883 Rust tests PASS.**
  Linux all-targets Clippy PASS с прежним исключением chunks_exact_to_as_chunks в
  неизменённом ndp_proxy.rs. Standalone client, server-only library и minimal FFI PASS.
  Server-only выдаёт 23 dead-code warnings в неизменённом общем transport-коде;
  это успешная сборочная проверка, а не Clippy без предупреждений.
- Rustfmt, staged diff и девять docs checks PASS. Команды CI проверены локальной
  кросс-компиляцией; GitHub Actions не запускался. Использованы изолированные дочерние
  executables и loopback witnesses. Реальный VPN, firewall, рестарт служб, SSH, внешние
  команды поставщиков, уведомления и бенчмарк не запускались.

## Ограничения и следующие шаги

Timeout/overflow/кооперативный stop дожидаются очистки shell; принудительная отмена future
поручает сбор Tokio. Неотменяемое ожидание ядра не позволяет гарантировать жёсткое время
возврата. Потомок может намеренно выйти из группы. Успешные фоновые службы с явным
перенаправлением потоков сохраняют поведение hooks. Shell фиксирован, но команды внутри
него используют PATH и цепочку доверия оператора. Helper не является sandbox для чужих команд.

Продолжение: [файл пароля и финальный статус](AUDIT-Q25-PASSWORD-FILES.md) добавляет
ограниченное чтение обычных файлов, общий zeroizing-буфер и join до финальной публикации.
Открыты network rollback клиента, мониторинг фоновых ошибок, задачи supervisor, реальные
Linux SIGINT/SIGTERM/systemd, release provenance и более широкая feature-матрица.
