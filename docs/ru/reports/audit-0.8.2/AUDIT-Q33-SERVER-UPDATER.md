# Q33: транзакции обновления и отката серверного пакета

<!-- normative-sync: q33-server-updater-v1 -->

8 октября 2026. F404–F411 / Q33-F007–F014. Q33 остаётся IN_PROGRESS. Этот пакет проверяет решения полного updater при установке/откате Debian-пакетов в изолированных сценариях. Production maintainer scripts, полный installer, настоящий systemd/VPN и Docker image/recreation остаются открытыми.

## Находки и исправления

- **F404 / Q33-F007:** отсутствующий файл при непустом QELI_DEB переводил выполнение на удалённую загрузку, но отключал её проверки. Installer и updater теперь отклоняют такой путь до загрузки и изменения зависимостей. Локальному updater-пакету curl и jq не нужны.
- **F405 / Q33-F008:** выбирался первый .deb независимо от архитектуры сервера. Теперь выбирается архитектура dpkg хоста; реальные метаданные dpkg-deb должны содержать Package=qeli, непустую версию и архитектуру хоста либо all. Чужой пакет, неподходящая архитектура и повреждённый архив отклоняются до установки/изменения кэша.
- **F406 / Q33-F009:** CRLF в SHA256SUMS мешал сопоставить имя; ошибка загрузки оставляла временный пакет. CR удаляется из поля суммы; EXIT/INT/TERM очищают только временные загрузки updater. Переданный локальный пакет сохраняется. Сумма подтверждает соответствие метаданным релиза, а не независимое происхождение. Опциональная обязательная gh attestation сохранена.
- **F407 / Q33-F010:** блокировки отдельных apt/dpkg не защищали всю последовательность backup/install/health/rollback. Неблокирующий flock теперь охватывает транзакцию целиком в root-owned0700 /run/qeli-updater, вне каталогов сервисного пользователя. Symlink и нештатные типы lock отклоняются. Это координация участвующих updater, а не защита от других пакетных менеджеров/изменений администратора.
- **F408 / Q33-F011:** проглоченная ошибка установки и успешный repair зависимостей могли объявить успех со старым пакетом и сохранить неверные байты под его версией. Успех требует точных dpkg status/version/architecture; кэш root-owned0600 заполняется только после подтверждённой установки. Ошибка ведёт к откату.
- **F409 / Q33-F012:** неудачный restart завершал set-e раньше rollback; пустой успешный ответ MainPID мог пройти проверку. Restart теперь условный; после обновления и отката нужен положительный числовой MainPID, стабильный между замерами, и is-active.
- **F410 / Q33-F013:** версия бинарника теряла Debian revision при поиске прошлого пакета; exit0 apt считался доказательством downgrade, а проверка после отката была слабее. Поиск использует установленную Debian-версию, метаданные кэша проверяются, downgrade требует точного configured dpkg identity и той же проверки здоровья. Binary-only fallback явно сообщает рассогласование dpkg. Даже успешное восстановление возвращает ненулевой код: запрошенное обновление не удалось.
- **F411 / Q33-F014:** /var/lib/qeli/packages контролируется сервисным пользователем; root-владелец отдельного файла не подтверждает байты и не исключает подмену при миграции. Updater теперь игнорирует и сохраняет legacy-кэш, не импортирует его в кэш пакетов, исполняемых от root.

## Выполненные проверки

`scripts/test_server_updater.py` требует Linux root/chroot, настоящие dpkg/dpkg-deb/dpkg-query, jq, flock и стандартные утилиты. Команда: `sudo unshare --mount --net --pid --fork python3 -B scripts/test_server_updater.py`. QELI_UPDATER_SOURCE и QELI_INSTALLER_SOURCE выбирают baseline, QELI_UPDATER_FIXTURE_RECORDS сохраняет пакеты стенда. Linux CI теперь выполняет эту команду и обеспечивает наличие jq.

На .11 после полноценной подготовки стенда14 сценариев старой версии завершаются ожидаемым FAIL; это14 регрессионных сценариев, а не14 отдельных находок. Исправленная версия:21 метод PASS без skips,24 запуска updater и один installer. Шесть настоящих инертных .deb собираются и устанавливаются/понижаются через реальный dpkg с отдельной базой. Байты конфигов/users/identity/client links сохраняются. Дополнительно проверены Architecture all, SHA mismatch, обязательная attestation без gh, настоящий удерживаемый flock и успех после освобождения, symlink lock/cache, crash loops и ложный успех apt. Точная команда CI, от root без sudo, отдельно проходит21 метод. Это проверка команды локально, а не успешный запуск Actions.

Явные подмены: решение apt о допуске команды (пакеты устанавливает настоящий dpkg), HTTP/байты релиза, systemctl/PID/is-active и сокращённые sleep. Инертный qeli только печатает версию. Production maintainer scripts, daemon, реальные5 секунд, HTTPS/OIDC, рабочий firewall/VPN и Docker runtime не запускались. Стабильный MainPID проверяет supervisor службы, а не готовность worker или туннеля.

ShellCheck0.10.0 на уровне warning и bash syntax проходят для обоих скриптов. Начальные ошибки syntax driver/неполный набор dpkg-утилит/dpkg-split сохранены как ошибки подготовки, не вердикты продукта. Итоговые SHA исходников совпадают с переданными файлами. Перед удалением обоих собственных каталогов получены и проверены SHA резервных архивов; process/fd/mount/path guards пройдены. MainPID777 и worker845 рабочей службы сохранены.
