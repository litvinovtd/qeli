## Q25-F080, P2 — доверие к конечному файлу не защищало родительский путь

Проверка `sysctls.state` запрещала symlink/hardlink и неподходящий режим файла,
но `create_dir_all` и следующие операции повторно проходили родительский путь.
Замена каталога могла направить lock, чтение и запись в разные деревья; владелец
самого журнала отдельно не проверялся.

Каталог состояния теперь открывается от `/` по компонентам через `openat` с
`O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC`. Абсолютный путь не должен содержать `..`
или symlink; глубина ограничена 64 компонентами. Права/владелец проверяются до
создания вложенного каталога. Недостающие каталоги создаются 0700; создание
синхронизируется через родительский fd.

Конечный каталог не может быть group/world-writable. Промежуточный root-owned
sticky-каталог допустим, но его следующий компонент должен принадлежать root
или вызывающему UID: root не принимает чужой заранее созданный `/tmp/qeli`.
Цепочка допускает root, текущего пользователя и одного владельца, которому
root передал защищённый дочерний каталог (например, `/var/lib/qeli`). Это сохраняет
совместную работу root CLI и `User=qeli`; чужая смена владельца в цепочке отвергается.

В течение транзакции каталог удерживается открытым; lock, journal, temp, rename и
unlink используют `/proc/self/fd/<fd>/...`. Переименование исходного каталога не
переводит операцию в его замену. Журнал и строгий sysctl lock принимают владельца
root либо владельца каталога, режим без group/world write и один hardlink.
Lock наследует владельца проверенного каталога, а не ещё не прочитанного журнала.
Формат journal v2, INI и ABI не меняются.

## Q25-F081, P2 — ожидание flock могло завершиться в старой группе блокировок

Открытый lock мог быть переименован/заменён, пока процесс ждал flock. После
получения старого inode процесс продолжал работу, хотя соседний процесс уже
мог владеть новым lock по прежнему имени.

Общий `FileLock` теперь после flock повторно проверяет regular/single-link и
совпадение dev/inode открытого fd с текущим путём без следования конечному symlink.
Строгая политика sysctl дополнительно проверяет владельца и режим до и после
ожидания. Защита от подмены применяется и к обычным пользователям общего FileLock.
При несовпадении возвращается `lock changed while waiting`; чужой lock не удаляется.

## Проверки

Две portable-регрессии политики владельцев/прав. Linux-регрессии проверяют symlink,
опасный родитель, относительный путь/`..`, удержание исходного дерева после rename,
неподходящий lock mode, изменение прав каталога и замену lock во время ожидания
для обеих политик. Последний тест ждёт фактического открытия fd вторым потоком.

Привилегированная проверка создаёт каталог служебного UID 65534 под защищённым
root-каталогом: root создаёт journal/lock с правильными uid/0600, отдельный процесс
под UID 65534 читает, блокирует и перезаписывает их. Файлы с чужим UID 65533
отвергаются; их владельцы и данные не нормализуются молча. Используются временные
фикстуры; реальные service credentials или конфиги не подменяются.

## Границы

Проверенный владелец каталога остаётся доверенным участником общей координации.
Произвольная смена mount/прав другим привилегированным процессом между проверкой и
syscall не становится атомарной транзакцией. Нужен корректный procfs с доступом к
своим fd; symlink-варианты `STATE_DIRECTORY` теперь следует заменить реальным
доверенным путём у всех участников. Поставляемый unit использует `StateDirectory=qeli`
без DynamicUser и не требует изменения. Новый private-каталог root сам по себе
не делегирует доступ будущему сервису: каталог сервиса должен принадлежать его UID.

Parent trust закрыт в этих границах. Durable namespace identity и исходное
поколение интерфейса при восстановлении per-link sysctl остаются D02; вся группа
ещё IN_PROGRESS. Остальные network budgets и persistent recovery также открыты.
