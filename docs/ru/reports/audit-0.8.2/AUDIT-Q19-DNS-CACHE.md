16 МиБ — лимит сохранённых пакетов, **не RSS процесса**. Накладные расходы
таблицы/аллокатора, буферы текущих запросов и число профилей учитываются отдельно.
Удаление просроченных записей отложенное; при нехватке места они удаляются прежде
свежих. Вытеснение пакетное, с произвольным выбором записей; это не LRU.

## Контракт подписанной пересылки

[TSIG, RFC 8945, разделы 4.1 и 5.5](https://www.rfc-editor.org/rfc/rfc8945.html)
описывает аутентификацию отдельного обмена и прозрачную пересылку.
[SIG(0), RFC 2931](https://www.rfc-editor.org/rfc/rfc2931.html) отличается от
подписи RRset в DNSSEC. Qeli распознаёт TSIG типа 250 и SIG типа 24 с covered type=0.
Обычный RRSIG типа 46 и SIG для RRset сохраняют обычные условия кеширования.
Проверка ключей, MAC, времени подписи и цепочек доверия DNSSEC не реализуется.

Тесты используют структурно оформленные **непроверяемые подписи** и сравнивают
байты. Криптографическая совместимость с внешним сервером ими не подтверждается.
Для большого подписанного ответа клиенту нужен TCP или достаточный EDNS-лимит.
Подписанный ответ на неподписанный запрос не поддерживается и не переписывается.
Blocklist и проверка заголовков сохраняются; локальные ошибки/NXDOMAIN выдаются
без подписи и могут быть отклонены клиентом, проверяющим аутентичность.

[Несколько вопросов, RFC 9619, раздел 4](https://www.rfc-editor.org/rfc/rfc9619.html)
требует FORMERR для обычного QUERY с несколькими вопросами и сохраняет сценарии
без вопросов. Прокси обслуживает QUERY; UPDATE, NOTIFY и DSO не поддерживаются.

## Проверки и доказательства

Пять новых регрессий упали до исправлений: лимит байтов, кеширование подписанного
ответа, изменение подписанного запроса, несколько вопросов и входящий QR=1.
После исправлений проходят **36 DNS-тестов**: реальные loopback UDP/TCP-обмены,
failover при неожиданной подписи, неизменность подписанных пакетов, COOKIE без
вопроса, граница 16 МиБ/большие ключи, учёт замены, истечение и лимиты 1/2/10 записей.
Стресс вставки использует синтетические буферы и не является сетевым бенчмарком.

**697 Rust unit + 52 editor/policy + 7 examples + 12 server INI = 768**, PASS.
Проходят 3 Python-теста DNS-стенда и 1 тест безопасности импорта. Linux all-targets
Clippy проходит с прежним исключением NDP `chunks_exact_to_as_chunks`; минимальный
клиентский FFI и документация проверены. Обновлены руководства RU/EN, реестр аудита,
индексы, подсказка и максимальное значение размера кеша в панели.

Внешний сценарий панели остановился на SSH-авторизации до операций изменения
стенда. Его E2E **не подтверждён**; безопасный импорт после исправления не означает
успех сетевого сценария. Живые DNS, маршруты и firewall ОС не изменялись.
C#/JVM/Apple не прогонялись повторно: клиентские интерфейсы не менялись.
