# Q25: подтверждение владельцев sysctl и сохранение восстановления

Дата: 23 сентября 2026. Исходная точка: `67e02ba8`.
Q25-F050–F051 исправлены в описанных пределах. Разделы 14/17/18/25 остаются **IN_PROGRESS**.

## Находки и изменения

**Q25-F050, P2 — недоступный процесс считался погибшим владельцем.**
Общий журнал server/client проверял `PID + process-start-time + scope` через чтение
`/proc/<pid>/stat`. Любая ошибка превращалась в false: отказ доступа, ошибка чтения,
повреждённая запись или скрытый procfs могли удалить живого владельца. Если он был
последним, очередной acquire/release/recovery восстанавливал исходный forwarding,
`rp_filter` или `accept_ra` под работающим компонентом.

Проверка теперь различает живого, подтверждённо завершившегося и неизвестного владельца.
Читаемое другое start-time подтверждает смену поколения PID. Отсутствующий stat требует
дополнительной проверки существования процесса: `kill(pid, 0)` не отправляет сигнал;
`ESRCH` подтверждает отсутствие в текущем PID namespace, `EPERM` или успех — наличие.
Если процесс существует, но start-time недоступен, владелец остаётся неизвестным.
Другие ошибки также сохраняют запись. PID из stat сверяется с запрошенным; нулевые,
выходящие за диапазон положительного pid_t PID и некорректные start-time отклоняются.

Неизвестные владельцы сохраняются и перечисляются в диагностике. Acquire и startup
recovery возвращают `cannot verify host sysctl owner(s)` до получения нового lease.
Предварительная очистка других подтверждённых stale-записей может уже выполниться;
её результат сохраняется до возврата ошибки. Release освобождает свой проверенный scope,
продолжает независимую очистку, сохраняет неизвестных совладельцев и возвращает общую ошибку.

**Q25-F051, P2 — неудачная проверка sysctl могла потерять исходное значение для retry.**
`Path::exists` скрывал ошибки metadata как отсутствие, после чего recovery удалял запись.
Пустой или некорректный прочитанный текст принимался за изменение администратора.
Отсутствие любого пути, включая глобальный forwarding, также считалось завершённой очисткой.

Теперь читается само значение и проверяется допустимое `0`/`1`/`2`. Ошибка чтения или
некорректное значение сохраняют запись для повторной попытки. Отсутствующий sysctl
можно забыть только для именованного интерфейса, отсутствие которого подтверждено полным
успешным перечислением `/sys/class/net`. Это исключение не относится к `all`/`default`,
глобальным параметрам, существующему интерфейсу и ошибкам получения списка устройств.
Действительное изменение администратора сохраняется; неудачная запись восстановления
также оставляет исходное значение в журнале.

## Проверка

Добавлены **20 host-тестов** реальных helpers prune/restore/release и политики допуска
с изолированной моделью process/sysctl I/O. Ещё один существующий тест валидации sysctl
теперь выполняется на Windows. Тестовый backend обязателен и не обращается к настоящему
procfs/sysfs, не пишет sysctl и не выполняет системный probe процессов.

Восемь регрессий: ошибки и некорректный stat; скрытый существующий процесс; неизвестное
существование; ошибка наблюдения sysctl; пустое/неправильное значение; отсутствующий
глобальный параметр; неподтверждённое исчезновение интерфейса.

## Границы и следующий проход

Версия и служебный формат журнала, INI-ключи, API/ABI не изменились. Нового формата
пользовательских конфигов нет. Межпроцессный flock, атомарная запись журнала и целая
публичная транзакция journal не исполнялись в новых тестах. Linux syscall-ветки
скомпилированы; это не реальный Linux E2E, reboot/SIGKILL или запуск контейнеров.

**Журнал пока не содержит идентичность PID/network namespace.** Проверки процесса имеют
смысл в том же PID namespace и согласованном procfs, а sysctl относятся к соответствующему
network namespace. Этот проход не делает общий state directory безопасным для разных
namespace. Их изоляция — следующий этап, вместе с неполным /proc при поиске владельцев TUN.
DNS/carrier globals, deadlines, постоянный crash recovery, Q14-F027 workers/FD,
native certification и новый benchmark остаются открыты. Из 37 разделов плана
19 IN_PROGRESS, 18 TODO, полного PASS нет; подготовительный этап 00 завершён.
