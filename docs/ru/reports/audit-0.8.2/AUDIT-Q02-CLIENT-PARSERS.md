## Как воспроизводился первый URI-проход

В общий существующий корпус сначала добавлены 18 invalid и 5 valid случаев.
До исправлений Rust принимал все 18 invalid, а положительная проверка выявила AWG
0/0 вместо 40/300. C# принимал 17 invalid; Android/JVM упал на reject-наборе.
После исправлений добавлены ещё граничные значения: unsigned -0, trailing NUL,
пробел в числе, максимальный u32 AWG count и обратный диапазон размеров.

Итоговый корпус содержит **21 valid + 29 reject** случаев. Формат корпуса — тестовые
данные существующего conformance-runner, не формат конфигурационного файла; профили
по-прежнему хранятся в INI.

Для Q02-F006 выполнен отдельный эксперимент. До исправления изменение корпуса дало
`testDebugUnitTest UP-TO-DATE`. После объявления inputs изменён только комментарий
того же файла; Gradle сообщил:

```text
Input property 'sharedConformanceFixtures' file .../conformance/qeli-links.json has changed.
```

Задача действительно исполнилась и прошла. Это проверяет инвалидацию, а не только
наличие новой строки в build.gradle.kts.

## Состояние общей библиотеки

Document/schema API реализован в существующем Rust core (ABI 1.16). Клиенты вызывают
его через C ABI/JNI; отдельные конфигурационные парсеры удалены, проекции генерируются.
Сохранение всех 84 полей через модели и исправления этого прохода проверены локально.
Подробности: [общий модуль и границы платформ](../../plans/CLIENT-CONFIG-CORE.md).
Конфигурационные документы остаются INI; служебный DTO не является форматом профиля.

## Завершение раздела — 3 октября 2026

**Q02: PASS в согласованном объёме.** Проверены входы INI/editor/URI, прямой импорт
панели перед persist, native runtime, generated projections и C ABI/JNI. Отдельных
локальных INI/URI-парсеров и тихого fallback при отсутствии native core не найдено.
Черновик может сохранять ошибки, но runtime/validate/share требуют строгого допуска.
URI переносит параметры соединения; file-only и OS-политики в него не входят.
Допустимое числовое MTU вне рабочего диапазона ссылки по прежнему контракту даёт auto;
неверный синтаксис/overflow — отказ. PIN не исправляется в TOFU молча.

Свежий запуск через упакованную Windows DLL SHA `653522e6bade8fce705a12ec1566c4c119d49b27d55cb7ba088c018b2bd1dd92`:
восемь групп PASS — 84 поля с явными значениями в runtime-тексте; 21 valid + 29 reject
URI с проверкой ожидаемых полей и round-trip; 15 независимых INI boundary; 1000 seeded
вариантов черновиков с сохранением values/raw и решения о допуске; unrelated edits,
лимиты документа/ABI; 128 параллельных сценариев с 16 workers для изоляции и маскирования.
Это 5630 вызовов сервиса, не 5630 независимых тестов. Сессии/сеть не создавались.

[Машинная сверка](../../../../release/certification/evidence/q02-reconciliation-20261003.json)
содержит хеши DLL, fixtures, review inputs и локального driver. `cargo` в текущем
Windows PATH отсутствует: попытка адресного Rust-теста не запустила тестов;
свежий результат относится к настоящему C ABI, не к компиляции Rust.
