## Исправленные замечания

**Q14-F024, P2 — успешное удаление без изменения правил зацикливало cleanup.**
После каждого `iptables -D` прежний алгоритм заново выбирал первое правило из `-S`.
Если backend возвращал успех, сохраняя правило, цикл не заканчивался и удерживал
общий firewall mutex. Возможность успешного no-op уже учитывается при установке правил
в `nat.rs`, но не учитывалась при их удалении. Это воспроизведено command fixture;
поведение конкретной версии iptables/nft на живом Linux здесь не проверялось.

**Q14-F025, P2 — обход скрывал ошибки и пропускал остальные правила цепочки.**
Ошибка чтения выглядела как отсутствие правил; ошибка удаления прекращала обработку
всей цепочки без диагностики. Остальные цепочки проверялись, но следующие правила
той же цепочки оставались до следующего cleanup. Теперь ошибки запуска, exit status,
разбора и проверки результата возвращаются из алгоритма, а Linux adapter пишет
`NAT cleanup via ... for '...' incomplete: ...` с контекстом таблицы/цепочки.

## Изменение

Общий код в `qeli/src/server/nat/cleanup.rs` используется сервером и host-тестами.
Прежняя копия парсера и алгоритма из `nat.rs` удалена. Один снимок каждой цепочки
полностью разбирается до удаления; затем выполняется одна попытка удаления на каждое
найденное вхождение. Повторный `-S` проверяет, что собственных правил не осталось.
Это конечное число вызовов для конечного снимка, без ограничения в 64 правила.

Ошибка удаления не пропускает остальные правила или цепочки. Некорректные UTF-8,
кавычки или неожиданные строки делают снимок непригодным для удаления; отсутствие
правил по таким данным не подтверждается. Диагностика ограничивает число и длину
сообщений. Перечень цепочек сохранён: nat POSTROUTING/PREROUTING, filter INPUT/FORWARD,
mangle FORWARD. Точный tag профиля, startup prefix `qeli-nat:` и аргументы в кавычках
сохраняются; правила администратора и похожего имени другого профиля не удаляются.

Внешний best-effort контракт cleanup сохранён: предупреждение не меняет exit status
worker. Некоторые native nft-цепочки недоступны для `iptables-nft -S`, хотя точные
`-C`/`-D` работают; DNS lease обслуживает этот отдельный путь. Автоматически делать
любую ошибку общего listing фатальной до проверки этого сценария нельзя.
INI, режимы IPv6, ABI, DNS lease, supervisor и порядок teardown не меняются.

## Открытые замечания и следующие проверки

**Q14-F026, P2 — точечная очистка DNS INPUT не различает отсутствие и отказ проверки.**
`delete_exact_rule` использует bool `rule_present`: любой отказ запуска/ненулевой
статус `-C` превращается в false и успешный cleanup. Кроме того, после удаления ровно
1024 копий возвращается ошибка лимита без последней проверки отсутствия. Подтверждено
ревью; в этом коммите не исправлено. Следующий шаг: переносимые negative fixtures,
отдельные исходы present/absent/unknown и проверка смешанной native nft-цепочки.

Продолжение от 23 сентября: Q14-F026 исправлена в [отдельном проходе](AUDIT-Q14-Q25-FIREWALL-CHECKS.md).
Точечная очистка использует общий разбор результата с Linux kill-switch; новая граница
1024 подтверждается финальным check. Реальный mixed native nft пока проверен только fixture.

**Q14-F027, P2 — ошибки освобождения ресурсов не передаются результату остановки.**
`cleanup(profile)` возвращает `()`, DNS lease очищается из Drop, supervisor при остановке
не собирает ошибки профилей. Worker при сигнале выбирает код выхода по flush учёта,
поэтому успешный exit не подтверждает очистку firewall/TUN. В этом проходе добавлена
диагностика общего sweep, но изменение Result-контракта и lifecycle ещё не выполнено.
Нужны тесты продолжения всех cleanup-шагов, объединения ошибок и совместимости native nft.

`--wait 5` ограничивает ожидание xtables lock. Последующий
[Q14-F032](AUDIT-Q14-NAT-COMMANDS.md) добавляет общий runner и срок каждой команды NAT;
единый deadline всей последовательности cleanup по-прежнему отсутствует. Чтение и удаление не атомарны
относительно внешнего администратора; изменение после последней проверки также возможно.
Linux runtime, реальные TUN/firewall/DNS, release-библиотеки, приложения на устройствах,
SSH/systemd/Actions и новые бенчмарки не запускались.
