# Q25-F115: серверная очистка без блокировки async executor

Дата: 25 сентября 2026. Исходный коммит: `db4e8969`. D05/D09: частичное закрытие.

## Подтверждённая проблема

`run_worker` вызывал `nat::cleanup_all` на async-пути до запуска служб. Штатный
`run_profile` после остановки дочерних задач вызывал синхронный
`drop(ProfileTeardown)` на том же пути: он удаляет DNS INPUT lease и NAT,
останавливает TUN-потоки и освобождает очереди. Финальные NAT sweep,
`finish_owned_cleanup` и `usage.flush` тоже блокировали executor. Каждый
компонент мог иметь собственный срок, но это не делало однопоточный runtime
отзывчивым во время операции.

## Исправление и границы

`profile_teardown::blocking` запускает синхронную операцию в отдельном потоке и
ждёт завершения без блокировки executor. Guard присоединяет поток даже при отмене
ожидания, прежде чем внешний scope сможет освободить network namespace lease или
владение профилем. Штатный профиль сначала завершает listeners/services/children,
потом удаляет запись из registry и только затем передаёт guard рабочему потоку.
При отказе запуска или панике ошибка попадает в итог cleanup; старые NAT/TUN
ошибки остаются в общем `Report`. Начальная очистка и финальные sweep/flush
используют тот же механизм. Формат INI, wire/API и политика маршрутизации не менялись.

Это не перенос `run_profile_generation`: создание TUN, NAT setup, NDP startup и
часть аварийных Drop всё ещё синхронны. Отмена во время принудительного Drop
может блокировать вызывающий поток; непрерываемые kernel/fs syscalls не получают
жёсткую границу. Составной deadline всей server setup/cleanup ещё открыт в D05.
