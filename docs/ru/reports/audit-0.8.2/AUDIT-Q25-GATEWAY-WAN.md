## Находки и изменения

**Q25-F021, P2 — неограниченные WAN-запросы могли задерживать запуск и очистку gateway.**
Четыре read-only запуска `ip` в `client/gateway.rs` использовали
`std::process::Command::output` без срока выполнения и ограничения вывода.
Зависший child удерживал engage, проверку/reconnect или cleanup; чрезмерный вывод принимался.

Выбор WAN вынесен в `client/gateway/wan.rs` и использует существующий общий runner:
15 секунд на команду, отдельные лимиты stdout/stderr по 16 МиБ, одновременное чтение
потоков, запрос остановки и ожидание child после timeout/overflow. Семейства сохраняют
свои запросы: сначала default route, затем route-get для `1.1.1.1` или
`2606:4700:4700::1111`. Выбирается первый пригодный dev из default route.
Это локальные запросы таблицы маршрутизации, пакеты по этим адресам не отправляются.

Ошибка, ненулевой exit, пустой или непригодный первый результат сохраняют переход к
fallback. Если route-get тоже неуспешен или не содержит пригодного dev, возвращается
`None`. Вывод после timeout/overflow отбрасывается, а не разбирается частично.
Обработка `None` вызывающим кодом не изменена; отдельной диагностики каждого probe
этот проход не добавляет.

**Q25-F022, P2 — cleanup искал текущий WAN даже при сохранённых интерфейсах.**
`remove_exit_rules` заранее вычислял оба discovery-запроса перед `remove_family`,
хотя результат использовался только при пустом ownership. Зависший запрос задерживал
удаление правил с уже известными интерфейсами. Теперь discovery вычисляется лениво,
только для семейства без сохранённых WAN. Все старые и новые WAN этого TUN остаются
целями очистки.

Ownership семейства по-прежнему сбрасывается только после успешной очистки.
Ошибка IPv4 не отменяет очистку IPv6 и сохраняет IPv4 targets для повторной попытки.
Записи соседнего TUN не затрагиваются. При пустом ownership и недоступном fallback
сохраняется прежний best-effort успех; это не постоянный журнал recovery после crash.

## Границы и продолжение

INI-поля, API и ABI не изменены. Срок относится к отдельному запросу, не ко всему
discovery, gateway или shutdown: fallback последователен, spawn/kill/reap и непрерываемый
kernel wait могут продлить вызов. Потомки, покинувшие Linux process group, не покрыты
групповой остановкой; Linux signals здесь не проверялись.

Изменяющие маршруты команды клиента и firewall-команды gateway/kill-switch ещё требуют
сроков и проверки ownership при неизвестном результате мутации. Этот read-only перенос
их не меняет. Реальные Linux TUN/firewall, смена сети, systemd, приложения на устройствах,
native release и новый benchmark не запускались. Полный аудит остаётся открытым.
