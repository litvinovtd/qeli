# Q25: задачи UDP и порядок отката пути

Дата: 23 сентября 2026. Исходный коммит: `2fb468f4`. Разделы 22–25: **IN_PROGRESS**.

## Замечания

**Q25-F012, P1 — ранний выход UDP оставлял receive-задачу без владельца.**
Основной receive pump, подключение кандидата и приём со старого пути хранили отдельные
JoinHandle. Ошибка core.management_event выходила через `?`, минуя штатное ожидание задач
и явную очистку. Drop JoinHandle не отменяет задачу: pump на тихом сокете мог продолжать
ожидание, удерживая сокет и буферы, пока внешний цикл уже очищал или пересоздавал сеть.
Штатное завершение основного и последнего draining pump уже использовало abort + await;
дефект относился к обходящим этот путь выходам и промежуточному владению задачами.

Теперь один TaskGroup общего Rust-ядра владеет активным UDP receive, candidate-connect,
candidate receive, draining receive и Linux path monitor вместе с его blocking-работами.
Ошибка управляющего события сохраняется и проходит тот же teardown, что обычная остановка.
Типизированный terminal kick и объединение ошибок очистки сохранены. Drop владельца
закрывает создание задач и запрашивает отмену; штатный finish ждёт все принятые задачи.
Это общий UDP loop Linux/Android/Windows/macOS/iOS, а не отдельная реализация Linux.

**Q25-F013, P1 — откат пути мог обогнать остановку candidate-connect.**
При остановке candidate-connect только получал abort, после чего код сразу запрашивал
prepared_candidate и запускал ABORT_PATH. Выполняемый синхронный участок задачи мог ещё
публиковать результат привязки пути. При завершении подключения handle также отбрасывался
сразу после получения сообщения. Истёкшие draining pumps и отвергнутые кандидаты отменялись
без ожидания освобождения ресурсов. Abort является запросом, а не подтверждением завершения.

Группа теперь завершается до проверки и отката платформенного кандидата. Отдельный путь
получает TaskHandle: при передаче candidate → active → draining он перемещается вместе с
путём; его Drop отменяет задачу, но JoinSet группы сохраняет обязанность её дождаться.
Ожидание TaskHandle завершается после уничтожения захваченной future и её ресурсов, в том
числе у ещё не опрошенной или паниковавшей задачи. Отмена этого ожидания не теряет владение
и допускает повтор. Отдельные ветки отказа/истечения кандидата и замены/истечения draining
теперь ждут receive pump перед продолжением. После получения результата candidate-connect
его задача также завершается до обработки результата. Рабочий active путь при отмене
другого кандидата продолжает принимать данные; протокол commit/epoch и окно drain сохранены.

Для этого расширен transport_core::tasks из предыдущего TCP-прохода. Отдельный Drop у
UdpClientLiveCandidate и прямые JoinHandle/spawn в UDP-помпе удалены; правило отмены находится
в общем TaskHandle. Старый отдельный TaskGroup Linux-монитора UDP объединён с группой
соединения. INI, wire format и ABI 1.16 не менялись; release native-библиотеки не пересобирались.

## Проверка

Пять новых тестов общего владельца проверяют никогда не опрошенную/отвергнутую задачу,
порядок освобождения ресурса с задержанным Drop, отмену ожидания и удаление TaskHandle,
обычное завершение/panic, Drop поколения при сохранённом handle пути.
Четыре loopback-теста запускают настоящий UDP receive pump: полная выходная очередь,
отмена кандидата при живом active пути, передача candidate → active с приёмом/окончанием
drain старого пути, ранний Drop владельца. Проверяются epoch, доставка, закрытие канала и
освобождение ссылок на сокет. Тесты используют только 127.0.0.1; системные маршруты и TUN
не меняются. Проверка порядка отката моделирует синхронную работу; это не live ABORT_PATH.

## Что осталось

Принудительная отмена всей future не гарантирует async join или rollback; Drop только
запрашивает остановку. Уже начатые blocking-операции не прерываются abort. Сроки выполнения
ip/iptables/resolvectl, rollback платформенных ACK, вложенные H2/transport workers и отмена
TUN shutdown остаются отдельными проверками. Перед release нужны актуальные native builds
и реальные платформенные сценарии. Полный аудит остаётся открытым.
