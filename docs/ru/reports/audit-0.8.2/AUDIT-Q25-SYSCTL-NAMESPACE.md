# Q25: изоляция журнала sysctl по namespace

Дата: 23 сентября 2026. База: `fa883796`.
Q25-F052–F053 исправлены в указанных пределах; разделы 14/17/18/25 остаются **IN_PROGRESS**.

## Подтверждённые проблемы

**Q25-F052, P2 — восстановление записей чужого network namespace.**
Один `sysctls.state` был индексирован только путём sysctl. При общем state directory
два network namespace имеют одинаковые пути, но разные параметры ядра. Recovery
мог вернуть чужое original в текущую сеть и удалить запись, ещё нужную другой сети.
При acquire также смешивались исходные значения и владельцы независимых параметров.

Служебный журнал переведён на версию 2: группы индексируются идентичностью network
namespace, каждая сохраняет собственные entries. Общие путь и файловая блокировка
сохранены. Acquire, release и recovery обрабатывают только текущую группу; чужие
владельцы не проверяются. Перезапись всего журнала сохраняет остальные группы.
Пустая группа удаляется из сохраняемого снимка, пустой журнал — с диска.
Перед записью проверяется общий лимит размера, чтобы не сохранить нечитаемый журнал.

**Q25-F053, P2 — PID и start-time могли проверяться в другой системе координат.**
При одном network namespace разные PID namespaces могут давать одному числу PID
разные значения. Кроме того, унаследованный procfs может показывать PID предка,
тогда как `kill(pid, 0)` использует текущую нумерацию. Ошибочная проверка могла
признать чужого владельца погибшим. Различный time namespace тоже влияет на наблюдаемое
start-time: ядро применяет time offset при формировании поля в
[proc/array.c](https://raw.githubusercontent.com/torvalds/linux/master/fs/proc/array.c).

Каждая группа теперь сохраняет PID и, когда доступен, time namespace. Несовпадение
останавливает транзакцию **до prune, изменения sysctl и перезаписи журнала**. Отдельные
журналы для разных PID namespaces одной сети не создаются: они потеряли бы общее владение.
Для procfs требуется единственное значение `NStgid`, совпадающее с текущим PID;
отсутствие, несколько значений, дубликат, иной PID и ошибка чтения отклоняются.
Порядок значений описан в [proc_pid_status(5)](https://man7.org/linux/man-pages/man5/proc_pid_status.5.html).

Namespace определяется по `st_dev:st_ino` объекта, на который указывает
`/proc/thread-self/ns/{net,pid,time}`. Это идентичность namespace, а не inode самой ссылки;
используется вызывающий поток, потому что setns действует на него.
См. [namespaces(7)](https://man7.org/linux/man-pages/man7/namespaces.7.html) и
[setns(2)](https://man7.org/linux/man-pages/man2/setns.2.html).
Отсутствие `ns/time` допускает ядро без этой возможности; другие ошибки останавливают
операцию. Переход между сохранённым наличием и отсутствием time identity не допускается.

## Миграция и совместимость

Непустой журнал v1 текущего boot-id не содержит доказательств namespace даже без
владельцев. Автоматическое присвоение текущего контекста было бы предположением.
Поэтому он сохраняется побайтно, операция возвращает `legacy host sysctl journal has
no namespace identity`. Требуется завершить восстановление прежней версией в исходных
namespace до обновления. Если это невозможно, переход можно совместить с плановой
перезагрузкой хоста и запуском новой версии после неё: значения прошлого boot-id не
воспроизводятся. Один restart Qeli не меняет boot-id. Остановка старого server worker
сама по себе не гарантирует пустой журнал: IPv4 lease мог остаться до следующего recovery.

Пустой v1 и валидный журнал предыдущей загрузки допускают переход без воспроизведения
старых параметров. Неизвестная версия или повреждённый журнал не удаляются даже при
другом boot-id. Старые бинарники не понимают v2; совместное использование журнала
старой и новой версиями и downgrade с непустым v2 не поддерживаются.
Новых INI-ключей, JSON-конфигов, изменений API/ABI нет; меняются служебные recovery metadata.

## Границы и следующий этап

Реальные namespace/sysctl, межпроцессный flock, SIGKILL/reboot и crash durability
не запускались: Windows filesystem tests и Linux cross-compilation не заменяют E2E.
Нужны доступные `NStgid` и net/pid namespace metadata; неподдерживаемые/ограниченные
procfs отклоняются. Минимальные ядра/OpenWrt без этих возможностей ещё требуют проверки.
Предполагаются согласованные procfs/sysfs mounts. Подмена mount и несовпадающий sysfs
inventory здесь не решены. Namespace объекты не удерживаются постоянно: повторное
использование inode после уничтожения namespace требует отдельного решения; текущий
ключ не является вечным идентификатором. Чужие stale-группы автоматически не очищаются.

Далее — полнота /proc при поиске владельцев TUN, устойчивость namespace identity,
доверие к файлам/срок блокировки, DNS/carrier globals, crash recovery и Q14-F027 workers/FD.
Native certification и новый benchmark не выполнены. План: 37 разделов, 19 IN_PROGRESS,
18 TODO, 0 полного PASS; этап 00 завершён.
