# Q25-F186: индекс активного профиля Android

1 октября 2026. База: b0ca3824. D08 остаётся **IN_PROGRESS**.

Три пути Android читали служебный индекс active через JSONObject.optInt. При неверном типе значения этот метод подставлял ноль; сервис/плитка дополнительно сбрасывали на ноль индекс вне диапазона. Повреждённое хранилище или backup с несколькими профилями могло незаметно выбрать первый сервер и его учётные данные. JSON здесь служит только контейнером списка профилей и backup; пользовательские конфиги остаются INI.

ProfileStore.readActiveProfileIndex теперь проверяет тип, целочисленность, переполнение и диапазон в одном месте. Отсутствующее поле сохраняет прежний default 0 для старых архивов; null, boolean, строка, дробное и индекс вне диапазона отвергаются. Числовые формы 1, 1.0 и 1e0 принимаются, если их математическое значение целое: org.json может нормализовать запись числа до проверки. Import и Activity load используют этот разбор; сервис/плитка при ошибке не получают конфиг. Для прямого чтения сервисом добавлены те же пределы 8 МиБ и 256 профилей, что у Activity; константы теперь общие.

Проверки: 160 JVM-тестов PASS, включая 4 новых теста индекса; assembleDebug и assembleDebugAndroidTest PASS, git diff --check PASS. Инструментальные тесты на эмуляторе не запущены: SSH к лабораторному серверу .11 отклоняет доступ. iOS importer имеет отдельное приведение NSNumber.intValue; его согласование остаётся следующим пунктом D08 и не считается закрытым этой проверкой.
