Если две вкладки читали один notify.ini, более позднее сохранение старой вкладки перезаписывало изменения другой, включая выключение канала и выбор событий. Общая блокировка сериализовала одновременные запросы, но не обнаруживала устаревшую страницу. Ручная правка файла между чтением и записью также могла быть потеряна.

GET /api/notify теперь возвращает ревизию точных байтов того же INI-снимка, из которого прочитаны настройки. PUT требует expected_revision и сравнивает его до слияния. Перед атомарной публикацией конфиг повторно читается под файловой блокировкой: если байты изменились, запись отклоняется, а cache уведомлений остаётся прежним. Успешный PUT возвращает новую ревизию. Панель передаёт и обновляет токен; при конфликте показывает отказ и предлагает перечитать настройки. Тестовая отправка продолжает брать текущий INI без сохранения. На диске используется только INI; JSON — служебный API.
