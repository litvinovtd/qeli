# Q14: частичный acquire IPv6 sysctl и повторный rollback

Дата: 23 сентября 2026. Исходный коммит: `44049922`.
Разделы 14, 17, 18 и 19: **IN_PROGRESS**. Q14-F031 исправлена; Q14-F027 остаётся частичной.

## Подтверждённая проблема

**Q14-F031, P2 — частично полученные IPv6 sysctl не попадали в итоговую очистку.**
`acquire_ipv6_sysctls` регистрировал профильный lease только после успешного получения
`accept_ra=2` и глобального IPv6 forwarding. При отказе второго acquire rollback вызывался,
но его ошибка только журналировалась: профиль ещё отсутствовал в реестре, поэтому
`finish_owned_cleanup` не мог повторить освобождение его scope.

Отказ первого acquire вообще выходил через `?` без rollback. Это не доказывает отсутствие
изменения: запись sysctl могла выполниться, а последующая проверка значения или журнала —
завершиться ошибкой. Низкоуровневый sysctl journal сохранял сведения, но текущий worker
не учитывал их как ожидающую профильную очистку.

## Исправление

Переносимый `qeli/src/server/nat/ipv6_sysctl.rs` хранит профильный реестр и алгоритм
acquire/release. Linux NAT-адаптер использует этот же алгоритм с настоящими journal API;
отдельной реализации владения в `nat.rs` больше нет.

Scope регистрируется после проверки параметров, **до первой попытки acquire**.
Любой отказ, включая первую настройку accept_ra, вызывает release scope. Успешный rollback
удаляет запись; неуспешный сохраняет её для обычной очистки профиля и итогового worker retry.
Возвращаемая ошибка включает исходную причину и `rollback incomplete`, когда отказал и откат.
Даже паника после начала изменения оставляет scope доступным последующей очистке.

Порядок accept_ra → forwarding сохранён. Повтор с теми же WAN/TUN заново применяет обе
настройки; другое WAN/TUN не заменяет ещё удерживаемый lease. Успешный release удаляет
запись и допускает последующие настройки. Итоговый проход обходит профили в стабильном
порядке и продолжает после ошибок DNS или другого профиля.

`off` и `manual`, правила firewall, алгоритмы sysctl journal, INI-ключи, ABI и wire format
не менялись. Частичный acquire теперь включён в существующую категорию
`owned network cleanup`: при неустранённом отказе итоговый worker shutdown не считается
успешным. Успешный финальный retry снимает именно сетевую ошибку; исходная ошибка текущего
поколения может независимо оставаться в категории `profile/worker task cleanup`.

## Открытые границы

Q14-F027 остаётся открытой для generic NAT cleanup и неполной очистки старых поколений
TUN/queues после retry/replacement. [Q14-F032](AUDIT-Q14-NAT-COMMANDS.md) позднее ограничивает
каждую команду server NAT. Общий срок сетевой операции и постоянный DNS journal остаются открытыми. Низкоуровневое восстановление sysctl зависит
от сохранённого журнала; этот проход не доказывает поведение при его утрате или при
ошибке сохранения самой записи. IPv4 forwarding с владением на время worker не менялся.

Реальные Linux kernel/sysctl/firewall/TUN/systemd, межпроцессные права и блокировки,
устройства, native release и бенчмарки не запускались.
