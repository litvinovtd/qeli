# Q25-F139: живое состояние панели после сохранения INI

25 сентября 2026. База: `a410ae9c`. D07 остаётся **IN_PROGRESS**.

Горячая перезагрузка `[web]` целиком заменяла `live_web`, хотя listener,
TLS-транспорт и роутер панели продолжают работать с параметрами старта.
После сохранения нового `web.port` проверка CSRF уже ожидала новый порт, а
панель всё ещё слушала прежний. Кроме того, изменение `[web] brute_force` в
общей форме обновляло INI и `live_web`, но не `FailedAuthTracker`: реально
продолжали действовать старые пороги. Отдельный endpoint настроек применял
tracker, поэтому два пути сохранения расходились.

Теперь горячая перезагрузка сохраняет стартовые `enabled`, `bind`, `port`,
`tls`, пути сертификата, `base_path` и источник session key в живом представлении.
Кандидат проверяется по фактически работающей панели до изменения состояния;
невалидные dormant-значения отключаемой панели не попадают в ещё работающую
панель. Новые пороги входа применяются к tracker только после успешной
проверки; при неизменных порогах прежние IP-lockout сохраняются.

Прямой async-тест на изолированной Linux-лабе `.11` проверяет смену startup-only
полей, обновление горячего `public_host`, сохранение накопленного IP-состояния
при прежних порогах, применение новых порогов и полный отказ от невалидного
кандидата. `cargo fmt --check` и строгий `cargo clippy --lib --bins -- -D warnings`
прошли. Лог: `C:/Users/litvi/OneDrive/Documents/qeli/audit-debt-20260925/server-nat44-egress-phase/webreloadchecksv2.log`.
