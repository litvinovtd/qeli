# Q25-F189: стабильность ID профилей desktop

1 октября 2026. База: 780bfc3a. D08 остаётся **IN_PROGRESS**.

Windows/macOS profile store определял необходимость миграции старого JSON одним поиском текста Id по всему контейнеру. В смешанном списке, где один профиль уже содержал Id, а другой ещё нет, миграция не запускалась. Десериализатор назначал второму новый GUID при каждой загрузке. Настройки авто-/service-профиля и буферы логов ссылаются именно на Id, поэтому выбор мог терять стабильность. Это внутренний зашифрованный контейнер списка; пользовательские конфиги остаются INI.

Общий ProfileStorePayload теперь осматривает каждый объект JSON до десериализации. Отсутствующий Id в любой записи запускает однократную запись мигрированного списка. Явные null/пустые и повторяющиеся Id отвергаются до попадания в UI; общий Encode не позволяет самим клиентам записать такой контейнер. macOS восстановление из .bak использует тот же Decode и затем сохраняет восстановленный список. Пустой массив по-прежнему допустим.

Проверки: общий QeliConformance selftest ALL PASS, включая смешанный список, стабильный повторный decode, отказ на трёх видах неверного Id и запрет записи дубля; QeliWin и QeliMac build --no-restore — 0 предупреждений и 0 ошибок; git diff --check PASS. Первый selftest загрузил старую DLL из bin и не достиг проверки профилей; повтор после замены только локальной сборочной копии на ABI 1.16 завершился PASS. Реальный desktop UI runtime не проверен: Windows VM и Mac недоступны по решению пользователя.
