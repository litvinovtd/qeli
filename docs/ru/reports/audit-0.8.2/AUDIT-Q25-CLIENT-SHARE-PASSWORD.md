# Q25-F194 — переносимый пароль в ссылке и сборка редактора

Статус: исправлено 1 октября 2026; общий Rust-контракт проверен на Windows. UI/runtime Android и iOS остаются в ограничениях D12.

Общий редактор экспортировал профиль с `password_file` или `password_command`, но без `pass`, в корректно выглядящую `qeli://`-ссылку без пароля. Локальный клиент мог прочитать секрет из файла/команды, получатель ссылки — нет; отказ появлялся только при подключении. Операция `uri` теперь требует непустой inline `pass` и сообщает, почему ссылку нельзя выдать. Валидация и сохранение локального INI не меняются. Если inline `pass` задан наряду с внешним источником, он имеет тот же приоритет, что и при подключении, и попадает в ссылку.

При проверке интеграционного теста обнаружилась независимая ошибка Windows-сборки: `config::notify` всегда использует ограниченный загрузчик INI `config_source`, но модуль был доступен только под Linux или `cfg(test)`. Убрана внешняя platform-gate; проверка доверия shell-команд на Windows по-прежнему отказывает, а загрузчик доступен для уведомлений. Интеграционный тест запускается с `--no-default-features`, поскольку binary `qeli` намеренно Linux-only.

Адресная регрессия покрывает отсутствие пароля, `password_file`, `password_command` и inline `pass` с внешним источником. Полный `config_editor`: 52/52 PASS на Windows. Портативный `cargo test --lib`: 1551 PASS, 1 ignored; rustfmt PASS. Проверка документации сохранила исходный baseline 61 замечание (32 index, 3 links, 26 parity), новых нет. Действующие Linux-серверы и мобильные приложения не заменялись.
