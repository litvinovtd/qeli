# Q25: срок владения kill-switch и доказательства IPv6-защиты

Дата: 23 сентября 2026. Исходная точка: `c528d6b5`.
Q25-F046–F047 исправлены в коде; Linux runtime lease требует отдельного прогона.
Разделы 17/18/25 остаются **IN_PROGRESS**.

## Находки

**Q25-F046, P2 — межпроцессная гонка и перехват цепочки с тем же TUN.**
Mutex предыдущего прохода защищал только один процесс. Два клиента могли проверить
пустой firewall одновременно и установить несовместимые DROP-политики. Кроме того,
новый процесс с тем же `dev` считал совпадающую цепочку своей и перестраивал её
до обнаружения занятого TUN. Проверка имён цепочек не доказывала живое владение.

**Q25-F047, P2 — ошибка наблюдения IPv6 разрешала запуск без защиты.**
`host_has_global_ipv6` превращал любую ошибку чтения `/proc/net/if_inet6` в `false`.
При недоступной или неустановленной IPv6-части это разрешало сообщить успешный
kill-switch, хотя отсутствие глобального IPv6 не было доказано. Тот же путь
не возвращал отказ и не откатывал уже установленную IPv4-часть.

## Исправления

Linux-клиент резервирует фиксированное abstract AF_UNIX имя
`qeli.client.kill-switch` до восстановления DNS и первого engage.
Резервирование атомарно в network namespace и немедленно возвращает ошибку,
если другой участник уже владеет именем. Имя одинаково для всех TUN, конфигов,
версий и state directories: смена имени профиля не обходит защиту.

Дескриптор удерживается на протяжении reconnect и terminal cleanup/post_down.
Guard объявлен раньше adapter, чтобы при cancellation/unwind сетевые объекты
освобождались до lease. Сокет close-on-exec; запускаемые команды не удерживают его
после exec. При завершении процесса ядро освобождает имя. Это не очистка firewall:
оставшиеся после краша правила по-прежнему требуют восстановления. Lock-файлы,
поиск PID и удаление старых inode не нужны. Lease не изменяет forwarding/sysctl.

Основание выбора механизма: [Linux network namespaces](https://man7.org/linux/man-pages/man7/network_namespaces.7.html),
[abstract UNIX sockets](https://man7.org/linux/man-pages/man7/unix.7.html),
[Rust UnixDatagram::bind_addr](https://doc.rust-lang.org/std/os/unix/net/struct.UnixDatagram.html#method.bind_addr).

Lease кооперативный: старые версии и сторонние firewall-команды его не соблюдают.
Поэтому сохранены проверки обеих filter-таблиц и отказ при чужих/legacy цепочках.
Все ошибки резервирования запрещают startup, включая ограничения sandbox и нехватку
ресурсов; leak overrides не обходят этот отказ. Gateway/exit без kill-switch
новым lease не охвачены.

Проверка IPv6 теперь использует общий ограниченный исполнитель для
`ip -6 address show scope global`. Только успешный пустой ответ позволяет пропустить
IPv6-защиту без `allow_ipv6_leak = true`. Непустой, неизвестный и невалидный ответ,
ошибка процесса, timeout и переполнение требуют защиты. Новый парсер формата не нужен:
содержимое непустого ответа консервативно означает необходимость защиты.
Удалён прежний best-effort procfs-парсер. Сохранён rollback IPv4 и сообщение его ошибки.

Ключи INI, служебный JSON и политика разрешений firewall не менялись.

## Проверка

**9 новых host-тестов**: семь через публичный engage и два на границе исполнителя.
Проверены ошибки наблюдения, неуспешный статус, наличие IPv6, невалидный UTF-8,
ошибка rollback IPv4, успешный пустой ответ, явное разрешение утечки, реальные
ограничения времени/размера вывода изолированных дочерних команд.

Пять регрессий: **FAIL на исходной логике → PASS после исправления**.
Исходный procfs-пробник исполнялся на Windows, где файл отсутствует; это модель
неизвестного состояния, а не наблюдение Linux-хоста. Контрольная версия сохраняет
исходную логику, меняя только имя private helper для компиляции новых тестов.
Firewall-команды и адресный inventory подменяются; реальная сеть не изменяется.

Модель ядра уточнена: удаление непустой или используемой цепочки возвращает ошибку.
Первый полный прогон выявил неверное ожидание старой модели при оставшемся hook;
это исправлено, затем исходная и новая логика повторно проверены на одной модели.
Тела пяти регрессий не изменялись, кроме форматирования.

Добавлены **6 Linux-тестов lease и один ignored child fixture**: повторный/параллельный
захват, независимые тестовые имена, release после drop/unwind, close-on-exec,
отказ другому процессу и освобождение при process exit без Rust-деструкторов.
Они **скомпилированы Clippy all-targets, но не исполнялись** в этой Windows-среде.
Тесты используют уникальные имена, не production lease; разделение настоящих
network namespaces ещё не проверено runtime.

**1253 host unit + 52 editor/policy + 7 examples + 12 server INI = 1324 Rust tests PASS.**
Все девять команд матрицы PASS: Linux all-targets Clippy, раздельные client/server,
minimal FFI, no-roaming, no-features, rustfmt и host-регрессии.
Rust 1.98.0; прежнее исключение `chunks_exact_to_as_chunks` сохранено.

## Открыто

Linux runtime lease, два реальных процесса/отдельные namespaces, iptables-nft/legacy,
IPv6-disabled при установленном ip6tables, общий deadline firewall-операции,
появление IPv6 после исходного пустого inventory, gateway/exit TUN generation ownership.
Снимок IPv6 не является постоянным мониторингом; наличие link-local без global
разрешает пропуск защиты согласно текущему контракту. Журнал sysctl не менялся.
Остальной план, DNS/carrier globals, native certification и новый benchmark открыты.
Этот проход не сертифицирует отсутствие утечек на реальном Linux.

Продолжение: [Q25-F048–F049](AUDIT-Q25-CLIENT-NAMESPACE.md) добавляет проверку
полного отключения модуля IPv6 и переносит lease в общий модуль для всех Linux-клиентов.
Gateway/exit без kill-switch и dev_attach теперь также резервируют настроенное имя TUN.
Ограничения выше описывают исходную точку этого отчёта.
