Чтение статуса намеренно отклоняет промежуточные 1xx и не является универсальным HTTP
парсером. Редиректов нет. Каждый кандидат DNS проверяется перед использованием;
соединение открывается непосредственно с допустимым адресом. Смешанный ответ DNS не
приводит к соединению с непроверенным адресом. Это политика приложения, а не точная
классификация глобальной доступности IANA: некоторые специальные глобально доступные
исключения, внутренние webhook и NAT64 не поддерживаются. Первичные источники:
[реестр IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry) и
[реестр IPv6](https://www.iana.org/assignments/iana-ipv6-special-registry).

## Проверки

Точные извлечённые production helpers: старая версия 3 PASS / 3 ожидаемых FAIL,
исправленная 6 PASS с отдельными свежими target. Это проверка helpers, не TLS,
очереди или конфигов. Полная библиотека также проверяет отказ недоверенному INI,
сохранность байтов/прав при попытке panel save, восстановление после безопасных прав,
отказ симлинку и некорректные HTTP/URL/адреса.

Производный example использует настоящую публичную библиотеку и очередь в отдельных
network/mount/PID namespaces Linux. `8.8.8.8` назначен только namespace loopback,
внешнего uplink нет. Проверяются реальные тело/target запроса, успех 204/201, отказ
302, фрагментация, отсутствие fixture-секрета в ошибке, запрет специальных адресов,
отказ TLS на plain endpoint и отказ после shutdown. Ловушка редиректа использует
свой фактический порт.

Отдельный тестовый fsync interposer заменяет sidecar на directory fsync после
атомарной публикации. Обе версии читают B с диска; старая реально отправляет A,
исправленная — B в следующем HTTP-событии. Interposer меняет только fixture-файл
`/etc/qeli` внутри private mount, без правок production или конфига хоста. Это
воспроизведение порядка записи, не проверка power loss/долговечности.

Финальные Linux-исходники `afa627069b01577bc3a14f0d956be82f6d934c41`: 2439 library
PASS, 60 ранее игнорируемых; строгий all-targets Clippy и debug daemon проверяют
тот же источник. Native-проверки и запечатывание raw отражены в machine evidence.
Игнорируемые тесты не считаются PASS.

Ошибки подготовки сохранены: неверное извлечение generic-функции, общий target
повторно использовал baseline, опечатка source-verifier, HTTP fixture писал после
закрытия status-reader и исправленный lifetime owned string в example. Ранний
producer desktop `47c973c3` завершил A/B, но source-change guard отказал в публикации
provenance после фикса кеша; он не переименован в сборку финального источника.


Дополнительная проверка настоящей библиотеки воспроизводит обход кеша симлинком на `7f5887f3`; исправленный повтор проверяет отказ после chmod, восстановление безопасных прав, отказ симлинку и восстановление обычного файла.

## Оставшиеся границы

Это не внешний Telegram receipt, положительный TLS с публично доверенным CA,
browser DOM, managed app/VPN E2E, ARM runtime или сеть Mac/iOS/router/Windows VM.
Очередь/deadline/drain/cancel сохраняют ранее проверенный контракт; обычные операции
файловой системы/NSS невозможно принудительно прервать. Выбранные администратором
метки/детали — содержимое сообщения; произвольный scrubber текста журнала не определяет
их как секреты. Packet trace хранит метаданные, не payload или реквизиты конфига.

Roaming-счётчики проверены по реальным call sites: lifetime worker/profile,
независимые relaxed snapshots, attempt после поиска locator, commit после записи
конечного ACK, failures также при detach, grace expiry отдельно. Поэтому исходы
не образуют разбиение; равенство attempts = commits + failures не гарантируется.
Ранее выполненные runtime Q23 и текущие module tests сохраняют свои границы;
свежий handover/soak здесь не заявляется.

Q32 DONE в документированной области Linux/server после сверки пяти критериев. Q29 SIGKILL/automatic-null
ENONET, Q30 callback drain и Q31 release pipeline/координация writer остаются открыты.
Платформенные исключения и D06 ACCEPTED_LIMITATION сохранены. Всего 29/37 DONE
(78,4%), осталось восемь; старый реестр долга — 14 DONE плюс принятое ограничение D06.
Push, deploy и release не выполняются.

## Общая сверка Q32

Шестнадцать сравнений точных Git-исходников/регионов сохраняют область ранее
выполненных metrics, namespace identity, usage/control/atomic publication, logs/trace
и Q23 roaming counters/control/soak fixtures. Старое выполнение переиспользуется,
а не переименовывается в свежее. Ограниченный TCP soak Q23 читает реальные счётчики
attempt/commit/failure/grace/gauges; равенство проверяется только для его сценария
успешных переключений. Текущая полная библиотека проверяет те же модули. После
последнего log/trace producer изменились только файлы notification/config-notification.

Пять критериев Q32 сверены с review, positive/negative/fault/concurrency, реальными
Linux I/O integration и финальными фиксами/evidence. Четыре итоговых native core
прошли A/B/export; Windows ABI22 и Android ART JNI23 — на финальных байтах, с
сохранением исходных AVD userdata/packages/links. Desktop A использует собственный
частичный кеш после намеренного прерывания; B независим. Cold/hermetic build и
новый физический runtime не заявляются. Native SHA/provenance и docs/bindings/diff
проходят. Границы выше описывают поддержку и доступные проверки и не превращены в PASS.
