# Q32: корректность метрик после пропусков и смены worker

<!-- normative-sync: q32-metrics-v2 -->

7–8 октября 2026. F380–F383 исправляют показания панели в `qeli/src/server/metrics.rs`.
Q32 остаётся IN_PROGRESS: этот пакет проверяет метрики, а не все usage/logs/notify.

## F380 / Q32-F002: ложный пик после сбоя control socket

Недоступный `list-clients` превращался в `(0,0,0)` и сохранялся как достоверный
предыдущий отсчёт. После восстановления вся накопленная величина выглядела как
трафик за один интервал. На исходном коде отдельный настоящий Unix socket с
ответом, разрывом и восстановлением воспроизвёл ложные 16002 Мбит/с upload.

Теперь отсутствие ответа оставляет baseline отсутствующим; первый успешный
ответ после пропуска заново устанавливает baseline, второй даёт обычную скорость.
Настоящий пустой список клиентов остаётся достоверным нулём. Формат API не менялся;
при недоступном ответе число клиентов и скорость по-прежнему отображаются как ноль.
Это не добавляет индикатор доступности и не восстанавливает потерянные интервалы.
Суммирование двух байтовых счётчиков проверяет переполнение вместо panic/wrap.

## F381 / Q32-F003: расчёт CPU и сброс счётчиков

Сумма всех столбцов `/proc/stat` включала guest/guest_nice второй раз. Ядро уже
учитывает их в user/nice: [код Linux account_guest_time](https://github.com/torvalds/linux/blob/master/kernel/sched/cputime.c).
Теперь сумма берёт первые восемь столбцов. Старая fixture возвращала busy/total
260/1070 вместо 190/1000. Ошибочный столбец больше не пропускается со сдвигом полей;
арифметика парсера проверяет переполнение.

Вычитание busy без проверки уменьшения могло panic в debug или wrap в release.
Синтетический сброс воспроизвёл panic в старом настоящем sampler. Теперь такой
интервал даёт ноль, а host CPU ограничен 100% при несогласованном delta.
[iowait может уменьшаться](https://docs.kernel.org/filesystems/proc.html), поэтому
не каждый прочитанный набор пригоден для точного вычисления CPU.

## F382 / Q32-F004: worker CPU через границу процессов

Предыдущий `utime+stime` сравнивался с новым процессом, если его CPU-счётчик был
достаточно большим. Теперь сравнение требует одинаковых PID и starttime из поля
22 `/proc/PID/stat`, в том числе при повторном использовании PID. Новый worker,
пропущенный отсчёт или уменьшение process counter начинают с нуля. Шкала top(1),
где один полностью занятый core равен 100%, сохранена. RSS остаётся best-effort;
сложение ticks и умножение страниц теперь проверяют переполнение.


## F383: sysctl fixture не должна совпадать с PID теста

Полный Linux-прогон прошёл 2421 метод и выявил три отказа в старом namespace
fixture. Мок считал PID42 мёртвым, но для собственного PID возвращал живой
starttime100. Контролируемый запуск старого binary при настоящем PID42
воспроизводит эти три отказа (33/36 PASS); при PID43 все36 PASS. Fixture теперь
использует допустимый `i32::MAX`, который не совпадает с PID тестового процесса.
Исправлен только cfg(test) fixture, код восстановления sysctl не менялся.
Начальная ошибка количества fork (фактический PID44) сохранена как невалидная
подготовка, не как отрицательная проверка. Повтор при PID42 после исправления
и полный набор отражены в evidence.

Первый full-crate compile обнаружил неверный namespace импорта control_io в новом
тесте. Fixture исправлена: wire-запрос принимает обычный BufReader, ответ пишет
Tokio; проверяемый sampler использует настоящий production control client.
Ошибки подготовки и промежуточные native snapshots сохранены. Проверка финального
source digest выполняется настоящими A/B командами; старые записи не переименованы
в подтверждение новых исходников. PassA desktop может использовать собственный
partial cache после прерванного прогона; PassB имеет отдельный target/cache.
Native-функции и профили сохранены; cold/hermetic builds этим не заявляются.
Mac cross-build предупреждения о недоступном xcrun/SDK сохранены.

## Проверки и предел

Старый исходник проверен в маленьком Linux harness: три воспроизведения отказали
ожидаемым образом. Для чтения CPU использована только подмена строки; для sampler
добавлена только передача отдельного socket path. Wire framing и send_command
взяты из продукта. Harness не является сборкой полного daemon.

Восемь проверок исправленного модуля прошли: семь новых и одна прежняя. Проверены
живой разрыв Unix socket/восстановление, обычный интервал и настоящий ноль,
guest/старый четырёхстолбцовый формат, неверные поля/overflow, reset/iowait,
PID/starttime/counter reset, настоящий `/proc` текущего процесса и sockets.
Повтор от UID/GID65534 также прошёл 8/8 без privileged операций.
Первый after-прогон переиспользовал stale harness binary через общий target и
не считается квалификацией; итоговый прогон использовал отдельный target.

Итог:2424 library PASS,60 прежних ignored; строгий Clippy all-targets с
transport-core-ffi/client-bin и debug daemon PASS.36namespace при PID42 PASS.
Все четыре native артефакта имеют независимый A/B и полный набор exports;
macOS обе подписи ADHOC/load commands PASS. Windows ABI22 и Android ART JNI23
проверены на совпадающих финальных байтах, original AVD userdata/host сохранены.
14 SHA строк и current native provenance PASS. Во время проверки исправленного
snapshot использовались две точечные передачи,315 прочих файлов сверены до,
все317 после передачи и после сборок. Семь созданных корней и отдельный каталог target удалены
после сохранения Git archives/8A-B binaries/daemon/test binaries/DEX/logs и
process/mount guards. Работающие сервисы и сетевые политики лабы сохранены.

Полная Linux квалификация и независимые native A/B записываются в
[машинное evidence](../../../../release/certification/evidence/q32-metrics-20261007.json).
Все native build functions сохранены; изменены только частные пути исходников,
выходов и offline caches в обвязке. Это не новый ABI и не платформенный VPN E2E.

Метрики по-прежнему используют сумму **активных** сессий: её уменьшение при выходе
клиента может занизить скорость. Нет гарантии точного учёта последнего пакета,
квот или crash recovery; эти сценарии относятся к оставшейся проверке usage.
Дальше: usage fold/reset/flush/corrupt store, trace/log endpoints и notify trust/SSRF.
Q29 SIGKILL/ENONET, Q30 callback drain/Apple, остаток Q31 и D06 ACCEPTED_LIMITATION
этим пакетом не закрываются. Общий статус полного плана сохраняется 28/37 DONE.
