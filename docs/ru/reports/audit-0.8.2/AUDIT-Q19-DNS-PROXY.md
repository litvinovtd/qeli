# Аудит Q19: серверный DNS-прокси

Дата: 23 сентября 2026. База: `8344392b` — коммит общей конфигурационной библиотеки
и предыдущих исправлений. Раздел 19 остаётся **IN_PROGRESS**.

## Область и архитектура проверки

Проверены разбор DNS-имён, допуск ответов в кеш, TTL после CNAME, UDP/TCP retry,
выбор резервного upstream и общий таймаут. Переносимый engine выделен из Linux
`qeli/src/server/dns.rs` в `qeli/src/server/dns/resolver.rs`: UDP и TCP используют
одну реализацию. Linux-слушатели и ProfileTasks остаются в прежнем модуле.
Тот же engine компилируется в host unit-тестах; GUI release-библиотеки его не включают.

Сетевые тесты запускают настоящие UDP/TCP-сокеты на loopback с временными портами.
Рабочая конфигурация upstream по-прежнему содержит IP-адреса и использует порт 53;
нового INI-параметра или отдельной тестовой реализации протокола нет.

## Исправления

| ID | Приоритет | До исправления | После |
|---|---|---|---|
| Q19-F004 | P2 | NOERROR/NODATA с CNAME в ANSWER принимался за положительный ответ. CNAME TTL 300 и отрицательный SOA TTL 5 давали кеш на 300 секунд. Незавершённая цепочка без SOA также могла кешироваться. | Проверяется наличие запрошенного типа записи. Для отрицательного ответа с CNAME учитываются и TTL цепочки, и SOA; без отрицательного SOA такой ответ не кешируется. Прямой запрос CNAME и цепочка с конечным A сохраняют обычное кеширование. |
| Q19-F005 | P2 | Проверка полноты пакета только перескакивала указатель имени: циклические ссылки и имена длиннее 255 байт считались корректными. Blocklist использовал другой, более строгий обход. | Один ограниченный обход для framing и blocklist: проверяются раскрытое имя, длина, ссылка назад и выход за границы; указатели в заголовок и циклы отклоняются. Корректные вложенные ссылки и граница 255 байт сохранены. |
| Q19-F006 | P2 | Ответ с TC по TCP считался успешным и назначал upstream предпочтительным. Исправный резервный сервер не опрашивался — как при принудительном TCP, так и после UDP → TCP retry. | Усечённый TCP-ответ сохраняется только как последний fallback; другие upstream получают оставшийся бюджет. Он не кешируется и не становится основанием сменить предпочтительный сервер. |

Правила отрицательного кеша сверены с [RFC 2308, §2.2 и §5](https://www.rfc-editor.org/rfc/rfc2308.html):
наличие CNAME не превращает NODATA в положительный ответ. Сжатие и ограничения имён
сверены с [RFC 1035, §2.3.4 и §4.1.4](https://www.rfc-editor.org/rfc/rfc1035.html).
Это не реализация DNSSEC-валидации.

## Проверки и evidence

Существующие 12 тестов сначала прошли после отделения engine. Пять новых регрессий
затем упали на прежней логике: CNAME TTL, цикл указателя, длинное имя, TC при TCP
и TC после UDP retry. После исправления прошли все **22 теста engine**, включая
кеш с новым transaction ID, возраст/истечение TTL, приоритет blocklist над кешем,
недоступный предпочтительный upstream и зависание внутри TCP-frame. Финальный review отдельно проверяет 255-байтовое
имя из 127 коротких меток: лимит шагов учитывает дополнительные compression hops.

Итог: **683 Rust unit + 52 editor/policy + 7 examples + 12 server-INI = 754**, PASS.
Три теста Python DNS-стенда — PASS. Linux all-targets Clippy — PASS с прежним
исключением `chunks_exact_to_as_chunks` для NDP на Rust 1.98. Это проверка компиляции
Linux daemon, не исполнение его lifecycle. Клиентские C#/JVM/Apple интерфейсы не менялись;
их тесты этого этапа повторно не запускались.

Локальные evidence: `C:/Users/litvi/OneDrive/Documents/qeli/dns-proxy-audit-20260923/`.
