# Q25-F104: чтение resolver-файлов до установки kill-switch

25 сентября 2026. База `8f4071ea`. Частичное закрытие D05/D09; Linux-клиент.

## Дефекты и исправление

Kill-switch читал `/run/systemd/resolve/resolv.conf` и `/etc/resolv.conf` синхронно,
без ограничения размера и отдельно для каждой семьи, уже после изменения firewall.
FIFO или медленное чтение блокировали обработку stop при частично созданной цепочке.
Парсер принимал `nameserver192.0.2.53` без разделителя, но терял корректные записи с
комментарием после адреса. Изменение файла между настройкой IPv4 и IPv6 давало разные
снимки системных DNS для двух семей.

Теперь файлы читаются один раз до первой мутации firewall. Read-only worker делит
общие четыре слота с системным DNS/NSS; очередь и чтение входят в существующие
15 секунд установки kill-switch. SIGTERM/SIGINT отменяют ожидание до мутаций.
Поздний worker не владеет цепочками, маршрутами или TUN и не может продолжить настройку.
Контекст закрепляется до ожидания и повторно проверяется перед изменением сети.

`transport_core/resolver/system_config` объединяет чтение и разбор для kill-switch
и проверки systemd stub. На Unix используется `O_NONBLOCK`; открытый fd должен быть
обычным файлом не более 64 KiB. Чтение ограничено 64 KiB + 1 байт; длина и metadata
проверяются до/после. Обычные symlink допустимы, имя файла не подтверждает его содержимое.
На файл и объединённый результат действует предел 64 уникальных записей.

Нужен отдельный токен `nameserver` и полный числовой IP; комментарии `#`/`;` после
адреса отделяются пробелом. Склеенный keyword игнорируется. NUL, повреждённая директива,
неподходящий тип/размер, неверный UTF-8 и обнаруженное изменение файла отбрасывают весь
этот файл, не создавая частичный список разрешений. Другой корректный файл остаётся
доступен; превышение общего лимита прерывает установку до мутаций. Это консервативный
парсер разрешений, не полная эмуляция всех расширений libc.

Scoped IPv6 (`fe80::53%wan0`, `%2`) сохраняет признак scope: такая запись не превращается
в разрешение для любого интерфейса и не отбрасывает соседний корректный IPv4 DNS.
Список со scoped DNS не считается stub-only. Поддержка scope у системного resolver
сверена с [исходником glibc 2.41](https://github.com/bminor/glibc/blob/release/2.41/master/resolv/res_init.c).
Существующая фильтрация loopback/link-local/multicast/unspecified не расширена.
Новых INI-параметров и изменений ABI нет.

## Проверки

**9 новых unit-регрессий** (7 portable + 2 Unix): разделители/комментарии/scope,
дубликаты и предел списка, отказ от частичного разбора, 64 KiB/UTF-8, изменение открытого
inode, общий предел двух файлов, symlink и FIFO. Проверки stub-only дополнены смешанными
и scoped записями. Прежняя логика удержания слота после отмены также проходит.

`audit_resolver_files.py`: **7 пар baseline/fixed (14 запусков)** с реальными UDP/53.
В каждом запуске сначала подтверждается доставка всех трёх адресов без kill-switch.

- FIFO без writer: baseline зависает после частичной установки; fixed не читает FIFO.
- Read, задержанный на 45 секунд test-only LD_PRELOAD: baseline уже меняет firewall,
  fixed ждёт до изменений. Оба старых зависших процесса не завершились по SIGTERM
  за 3 секунды; fixture завершает их SIGKILL. Fixed останавливается штатно.
- Файл больше 64 KiB и склеенный keyword: старый клиент пропускает пакеты к двум DNS,
  исправленный отклоняет эти разрешения.
- Корректные комментарии: старый клиент блокирует оба DNS, исправленный пропускает.
- Подмена файла между IPv4/IPv6: старый клиент разрешает новый IPv6 DNS; fixed использует
  общий первоначальный снимок.
- Scoped IPv6 вместе с IPv4: IPv4 остаётся доступен в обеих версиях, scope не теряется
  и не порождает широкое IPv6-разрешение.

Все семь fixed-запусков завершились с exit 0, сохранили исходные operator rules/routes
и не оставили TUN или журналов. Stop измерен в диапазоне **0,003–0,716 секунды**;
это результат сценариев, не общий SLA. Всего 33 адресные пробы: **48 разрешённых пакетов
получили ответы, 84 запрещённые попытки дали EPERM и нулевую доставку**.

Окончательная hostname-матрица: IPv4=nft/IPv6=legacy без firewalld и обратная пара с
реальным приватным firewalld. **38/38 сетевых ячеек, 34 SIGKILL/recovery, 1220 основных
утверждений и 806 вложенных проверок PASS**. Все **1088** защищённых прямых UDP-попыток
заблокированы с EPERM/ростом DROP-счётчиков/нулевой доставкой; все **656** разрешённых
проб получили ответ. TCP/UDP/QUIC, carrier/tunnel IPv4/IPv6, split, TAP, DNS A/AAAA и
MTU/PMTU/PTB проходят. Вложенные утверждения не считаются отдельными тестами.

Host: **1544 unit + 71 config integration**, все 9 feature/cross/lint проверок PASS.
Linux: **2098 обычных + 44 privileged + 8 worker lifecycle PASS**. Python compilation,
bash syntax и все 9 проверок RU/EN документации PASS. Rust 1.98 host / 1.97 Linux;
сохранено прежнее Clippy-исключение `chunks_exact_to_as_chunks`.

Первые native-прогоны v1/v2 сохранены как FAIL тестового окружения: сначала отсутствовала
обратная IPv6 neighbor-запись, затем DAD завершался после снимка маршрутов. Fixture
исправлен двусторонними статическими neighbors, контрольной доставкой и ожиданием DAD.
Промежуточные repro v3/matrix v1 PASS не подменяют итог: выше приведены окончательные
**repro v4/matrix v2**, после scoped/attached-comment регрессий.
