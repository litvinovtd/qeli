# Q25: результат неуспешного изменения carrier route

Дата: 23 сентября 2026. Baseline: `c6c64c70`.
Разделы 22, 23 и 25 остаются **IN_PROGRESS**. Q25-F023/F024 исправлены.

## Находки и изменения

**Q25-F023, P2 — частичная мутация маршрута могла считаться обратимым отказом.**
`LinuxPreparedPathRoutes::commit` записывает выполненный шаг только после успеха команды.
При ошибке add/replace откатывались предыдущие шаги, но результат текущего не проверялся.
При retirement восстанавливались предыдущие удаления, без проверки неуспешного удаления.
Если состояние ядра изменилось до возврата ошибки, предыдущий rollback мог пройти успешно,
и адаптер возвращал обычную ошибку. Linux преобразовывал её в `Rejected`, хотя этот исход
требует отсутствия изменений либо полностью восстановленного прежнего состояния.

После отката предыдущих шагов Qeli теперь снова проверяет destination неуспешной команды.
Для add неизменность означает отсутствие точного маршрута. Для replace/retirement нужен
тот же полный снимок токенов, что до мутации. Изменённое/недоступное состояние даёт
`RouteCommitStateUnknown` с исходной ошибкой команды и ошибкой проверки.
Подтверждённая неизменность сохраняет обычный отказ. Ошибка предыдущего rollback
по-прежнему означает неизвестное состояние независимо от этой проверки.

Существующий контроллер преобразует типизированную ошибку в `PlatformStateUnknown`:
ядро завершает соответствующую команду ошибкой и сбрасывает кандидата, не ставит обычный
ABORT с предположением, что прежние маршруты целы. Существующая обработка ошибок транспорта
должна остановить текущее поколение соединения. Этот проход исправляет результат route
executor, а не ABI управляющего протокола или его state machine.

**Q25-F024, P2 — многострочный снимок маршрутов терял все строки, кроме первой.**
`exact_route_tokens` принимал первую непустую строку и игнорировал остальные.
Результат с несколькими маршрутами или строками не был полным снимком для сравнения/отката.
Теперь более одной непустой строки вызывает отказ. До мутации это обычный отказ;
после её ошибки такой вывод не позволяет объявить состояние неизменным.
Пробелы внутри одной строки нормализуются в токены. Восстановление multipath/multi-route
этот проход не реализует.

Граница запуска команд допускает подмену в тестах. Production по-прежнему вызывает `ip`
с теми же argv и прежним неограниченным runner. Host test build включает переносимый
route-код; разрешение interface index остаётся под Linux cfg.
Новые fixtures подменяют команды внутри тестового потока и разделяют блокировку журнала
владения с существующими Linux shim tests. PATH процесса и сеть хоста не меняются.

**1057 host unit + 52 editor/policy + 7 examples + 12 server INI = 1128 Rust tests PASS.**

исполняются на host. Это не 23 заново написанных теста.

## Границы и оставшаяся работа

Исправлен ложный обратимый исход, не полное recovery неопределённой мутации.
Qeli не присваивает/удаляет вслепую маршрут после неуспешного add и не восстанавливает
вслепую failed replace: наблюдаемый маршрут мог установить администратор.
Неопределённый новый маршрут может остаться без cleanup-записи; прежние известные записи
сохраняются. Постоянный pending-operation ownership, точная identity для retry/cleanup
и recovery этого состояния остаются открытыми. Снимки не делают внешние изменения атомарными.

Сроки команд здесь не добавлены: timeout/overflow внедряются как I/O результаты,
настоящие зависшие процессы не запускались. Read-only route queries и изменяющие
route/kill-switch/gateway команды ещё требуют отдельного переноса с проверкой ownership.
Реальные Linux netlink/iptables/TUN/handover, устройства, native release и новый benchmark
не запускались. INI/API/ABI не изменены; полный аудит остаётся открытым.

Pending unknown/orphan recovery и сроки команд остаются открытыми.
