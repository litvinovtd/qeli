# Q25: сохранение kill-switch при ошибке очистки forwarding

Дата: 23 сентября 2026. Исходный коммит: `7ab16ac7`. Раздел 25: **IN_PROGRESS**.

**Q25-F003, P1 — ошибка NAT cleanup не предотвращала снятие защиты выхода.**
cleanup_routing_features пытался очистить gateway/exit-node, сохранял ошибку, затем
всё равно снимал kill-switch. Комментарий обещал fail-closed порядок, но первый вызов
очистки не требовал её успеха. Остаточные forwarding/NAT-правила могли сохраняться
после открытия выхода в сеть.

Политика теперь вызывает снятие kill-switch только после успешной очистки forwarding.
Ошибка возвращает исходную причину и явное сообщение `kill-switch retained`.
Штатная остановка, server kick и исчерпание повторов используют этот общий путь.
При выключенном kill-switch не выполняется операция над защитой и не заявляется её
сохранение. Ошибка самого снятия защиты также возвращается; она не описывается как
сохранение, поскольку удаление уже могло частично выполниться.

Изменение относится к штатной обработке ошибки. Намеренное сохранение после crash/
SIGKILL остаётся; безусловная очистка в Drop не добавлена. Сохранённый барьер может
ограничивать сеть до устранения причины и успешной очистки либо восстановления
администратором. Настроенные post_down-скрипты остаются под контролем оператора
и могут самостоятельно менять firewall вне этой политики.

Они моделируют результаты и порядок вызовов, а не фильтрацию реальных пакетов.

## Что осталось

Путь ошибки begin_connection после включения kill-switch ещё требует отдельного разбора;
исправление не доказывает полный network rollback. Сохранение уже установленной защиты
не является доказательством наличия каждого правила ядра или отсутствия внешних изменений.
Linux fault-injection/E2E, владение вложенными задачами и полный аудит ещё открыты.

Продолжение: [аудит жизненного цикла ядра](AUDIT-Q25-CORE-LIFECYCLE.md) закрывает обход очистки при ошибке запуска и делает ошибку остановки ядра терминальной. Полный rollback маршрутов/DNS и live Linux E2E ещё открыты.
