## Q25-F098, P1 — перестройка снимала прежний барьер

После потери процесса цепочки `QELI_KS_<tun>` оставались в kernel. Повторный `engage`
сначала удалял их OUTPUT/FORWARD jumps и сами цепочки, затем создавал новые. В этом
окне пакеты могли выйти по физическому default route. Отказ установки IPv6 DROP
запускал откат обеих семей и оставлял хост без ранее существовавшей защиты.

На исходном коде native-регрессия с потерей process-local owner и пакетами после
каждой мутации показала счётчики WAN **[0, 0] → [19, 16]** (IPv4/IPv6). Отдельный
настоящий клиент после SIGKILL и отказа IPv6 DROP дал **[8, 14] → [22, 27]**:
14 IPv4 и 13 IPv6 UDP-проб достигли разрешающего WAN-правила. Новый клиент завершился
с ошибкой, но этого было недостаточно для сохранения защиты.

## Изменение

До снятия прежней цепочки ставятся точные временные DROP-правила с комментарием
`qeli-ks-rebuild:<tun>`: OUTPUT и, при прежнем/запрошенном forwarding либо оставшемся
FORWARD guard, также FORWARD. Обе доступные семьи проходят этот этап до перестройки
любой из них. Успех команды проверяется через `-C`; отсутствие guard не разрешает
снять старую цепочку. Чужой recovery guard запрещает admission даже без обычной цепочки.

Откат затрагивает только обычные цепочки, перестройка которых действительно началась.
Он не удаляет guards. Ошибка, timeout или новый SIGKILL оставляют барьер; разрешения
`allow_ipv4_leak`/`allow_ipv6_leak` не превращают отказ замены прежней защиты в успех.
Guards снимаются после успешной установки всех требуемых семей. Отказ на этом последнем
этапе сохраняет новые обычные цепочки: после снятия IPv4 guard ошибка IPv6 cleanup
не запускает откат уже действующей IPv4-защиты. Повторный запуск с тем же TUN умеет
восстанавливаться, когда остались только guards. При явной чистой остановке снимаются
обычные цепочки и затем точные guards; чужие правила сохраняются.

Это намеренно строгие временные DROP-правила: пока новый ruleset не доступен, могут
блокироваться и прежние разрешения, включая DNS/loopback. После неудачного rebuild
запуск с DNS-именем сервера может остановиться ещё на resolve. Тогда нужен проверенный
IP сервера либо ручное восстановление после остановки владельца. Отдельный лог
`Kill-switch ENGAGED` появляется только после завершения снятия guards.

## Границы

Восстановление требует тот же network namespace, TUN name и firewall backend. Имена
цепочек и `qeli-ks-rebuild:*` зарезервированы за Qeli: это cooperative ownership,
не доказательство против root, специально создающего идентичные правила. Смена
backend, произвольные nft/firewalld политики и внешнее вмешательство между проверкой
и командой не сертифицированы. Межсемейная транзакция не атомарна; временная потеря
доступности допустима, удаление существующего барьера до готовности замены — нет.
Срок установки и отдельного отката остаётся по 15 секунд; DNS/NSS и внутренние I/O
не стали прерываемыми. Первая установка без прежнего барьера не обещает блокировку
с момента запуска процесса. Новых INI-ключей, ABI и wire-изменений нет.

D04 остаётся IN_PROGRESS: клиентские маршруты, legacy global DNS, живой persistent TUN
и полная mixed firewall матрица требуют дальнейшей работы. Все сетевые проверки —
приватные namespaces на `.11`; работающий `.10` не изменялся. Windows VM/Mac/iOS/router
runtime остаются SKIPPED по решению пользователя.
