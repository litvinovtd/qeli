# Q25-F142: имя профиля не выходит из каталога серверного ключа

30 сентября 2026. База: `fba54679`. D07 остаётся **IN_PROGRESS**.

В имени профиля раньше запрещалась запятая, но разрешались `/` и `\`. По умолчанию путь приватного identity-ключа собирается как `/etc/qeli/identity/<profile>.key`; поэтому `[profile:../escape]` меняет целевой путь на `/etc/qeli/escape.key`. Безопасный baseline `qeli check-config` на изолированной лабе `.11` подтвердил ложный `OK` для такого INI. Запись ключа за пределы приватного каталога в baseline не выполнялась.

Общий `is_valid_profile_name` теперь запрещает оба разделителя пути наряду с запятой. Эту проверку используют INI-парсер, панельная форма, ссылки пользователей на профили и startup-валидация. Публичные helper'ы загрузки и поворота identity-ключа дополнительно проверяют имя непосредственно перед файловым доступом, в том числе если `ProfileConfig` создан программно. Явный `identity_key` остаётся административным способом выбора другого пути.

Проверка: два адресных unit-теста на имена и отсутствие файлового эффекта, тесты `server_ini_audit`, `cargo fmt --check`, строгий Clippy и Linux CLI-пара: опасное имя отклоняется, обычное имя с `@` принимается. Логи: `C:/Users/litvi/OneDrive/Documents/qeli/audit-debt-20260925/server-nat44-egress-phase/identitybaseline.log` и `identityfixed.log`.

Имя старого профиля с разделителем надо изменить вручную вместе со ссылками из `users.conf`; чтобы сохранить существующий приватный ключ и пиннинг клиентов, после переименования можно задать `identity_key` с прежним абсолютным путём. D07 остаётся открытым для полной матрицы полей и путей; доверие к произвольному `identity_key` из внешнего INI требует отдельной сверки.
