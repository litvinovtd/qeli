## Что проверено

- Общая INI-грамматика, типизированные читатели, отслеживание прочитанных ключей и ошибок.
- Структура серверных секций, scalar/list/map-семантика, маршруты профиля и пользователя.
- Связь `parse_server_config`, `parse_server_config_reporting`, `UsersDb::parse_strict`
  с отказом при некорректном вводе; по коду прослежены startup, SIGHUP, Quick Start и
  сохранение через панель. HTTP и сигналы живому серверу не отправлялись.
- Отсутствующее значение против пустого списка; default/roundtrip, диапазон route metric,
  IPv4/IPv6 gateway, изоляция диагностик 32 параллельных разборов.
- Четыре поставляемых серверных примера через настоящий переносимый парсер;
  Linux-валидация этих примеров скомпилирована, но здесь не исполнялась.

Мёртвых исполняемых модулей в этом срезе не подтверждено. Удалены устаревшие комментарии
о порядке TOML-сериализации и о якобы допустимых предупреждениях при startup.
Нормализация AWG, совместимость известных retired-ключей и default для пустых значений
`parse_or` не объявлены новыми дефектами: это существующие отдельные контракты.

## Находки и исправления

### Q01-F001 — P2: ошибочные маршруты терялись или меняли смысл

**До:** `route = nonsense` исчезал из списка, а `route = 10.0.0.0/8 metric=no`
терял metric. Опечатки вроде `metirc=7`, повторные `metric`/`gateway`/`cidr` и лишние
токены принимались. Поиск подстроки `desc=` мог скрыть ошибочную опцию `notdesc=`.
Диагностика не попадала в `doc.bad_values()`, поэтому строгое вызывающее место
не видело причину отказа. В пользовательских маршрутах ошибка metric также терялась.

**После:** проверяются синтаксис, CIDR, семейство gateway, неизвестные/повторные опции
и metric `0..=4294967295`. Ошибка сохраняется в диагностике конкретной секции.
`desc=` распознаётся на границе опции и сохраняется в маршруте профиля;
неподдерживаемый `desc` в пользовательском маршруте отклоняется.

**Проверки:** `invalid_profile_routes_produce_findings`,
`route_option_typos_and_duplicates_are_rejected`, `user_routes_share_strict_option_validation`,
`route_options_and_profile_descriptions_round_trip`.

### Q01-F002 — P2: повторные и пустые ключи словарей молча преобразовывались

**До:** две строки `pool.reservation.alice` выбирали последнее значение без ошибки;
`pool.reservation. = 10.9.0.2` исчезал с предупреждением. Аналогично для IPv6;
повторный `metadata.note` перезаписывал первое значение.

**После:** полный динамический ключ уникален, суффикс непустой; ошибочная запись
добавляет finding. Имена пользователей в резервациях проходят `is_valid_ident`.
Разные имена пользователей/метаданных по-прежнему разрешены.

**Проверка:** `dynamic_map_keys_must_be_unique_and_nonempty` и общий roundtrip.

### Q01-F003 — P2: разрешённые повторные списки отклонялись как scalar-дубли

**До:** проверка наличия списка через `get()` отмечала повтор как нарушение
скалярного контракта, хотя следующий `list()` правильно объединял значения.
Пример: две строки `pool.exclude`. Затронуты также IPv6 exclude, DNS-списки,
REALITY short_ids, round_sizes, списки web и allowed_networks группы.

**После:** проверка наличия не навязывает scalar-семантику. Списки объединяются
по порядку, а отсутствие ключа отличается от явно пустого списка.

**Проверки:** `repeated_profile_lists_merge_in_source_order`,
`repeated_web_and_group_lists_are_accepted`, `missing_and_explicit_empty_lists_remain_distinct`.

### Q01-F004 — P2: неверная форма глобальных секций проходила схему

**До:** `[web:main]` интерпретировался как глобальный `[web]`, потому что поиск
секции игнорировал instance. Повторная пустая глобальная секция и пустая неизвестная
секция могли пройти проверку unread keys: в них просто не было ключей.

**После:** `[auth]`, `[web]`, `[logging]` уникальны и не имеют instance;
неизвестные секции отклоняются независимо от содержимого.

**Проверка:** `malformed_and_duplicate_singleton_sections_are_rejected`.

### Q01-F005 — P2: неверные элементы round_sizes молча удалялись

**До:** `obf.traffic_normalization.round_sizes = 512,no,1500` превращался в
`[512,1500]` через `filter_map(parse().ok())`, без ошибки конфигурации.

**После:** неверное целое, отрицательное значение и переполнение типа фиксируются
как ошибки. Проверка допустимых runtime-размеров остаётся отдельной ответственностью
валидатора профиля; парсер не заменяет её.

**Проверка:** `malformed_numeric_list_members_produce_findings`.

### Q01-F006 — P2: обычный API чтения обходил накопленные ошибки

**До:** `parse_server_config` не проверял findings, в отличие от строгих путей
startup/panel. Quick Start читает через него текущий конфиг перед перезаписью;
ошибочная строка могла исчезнуть при сериализации, и последующая проверка уже
не видела исходную ошибку. CLI также использует этот entry point.

**После:** общий API вызывает reporting-парсер и отказывает при непустой диагностике.
Низкоуровневый `ServerConfig::from_ini` остаётся сборщиком для диагностических
сценариев: его вызывающие места обязаны проверять `bad_values` и unread keys.

**Проверка:** `ordinary_server_parser_does_not_discard_findings` отдельно упала до
этого исправления и проходит после него. Это доказательство контракта API;
полноценный HTTP/CLI-сценарий требует Linux.

### Q01-F007 — P3: «полный» roundtrip не доказывал заявленное покрытие

**До:** основной Rust-fixture не задавал десять читаемых ключей:
`listen`, `perf.udp.recv_buffer_size`, `perf.udp.send_buffer_size`, четыре `roaming.*`,
`routing.ipv6.ndp_proxy`, `routing.ipv6.ndp_proxy_interface`, `users_file`.
Генератор и встроенный fixture разошлись; regex пропускал многострочные accessors,
а широкий список исключений скрывал отсутствие некоторых значений. Часть полей
имела отдельные тесты: находка не означает, что их вообще никогда не проверяли.

**После:** fixture синхронизирован, добавлены IPv6 reservation и metadata.
`python scripts/gen_roundtrip_fixture.py --check` проверяет имена ключей, три семейства
динамических ключей и совпадение с реальным Rust-fixture. Команда включена в CI.
Единственное исключение — read-only retired `tun.netmask`, который нельзя писать обратно.

**Предел доказательства:** 163 уникальных имени ключей и 3 семейства присутствуют
в проверке; это не доказательство non-default значения каждого поля, всех комбинаций
или применения всех полей runtime. Формулировки теста/генератора исправлены.
