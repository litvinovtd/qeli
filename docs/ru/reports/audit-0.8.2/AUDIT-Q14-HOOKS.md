# Q14: память вывода и завершение hook-процессов

Дата: 23 сентября 2026. Исходный коммит: `843d2eaa`. Раздел 14: **IN_PROGRESS**.

## Находки и исправления

**Q14-F014, P2 — накопление всего stdout/stderr до усечения журнала.** Оба вида
Linux-хуков вызывали `Command::output()`. `logged_output` ограничивал только итоговую
строку, после накопления двух полных буферов и дополнительной concat-копии. Шумная
доверенная команда могла исчерпать память worker/клиента за разрешённые 30 секунд.

Один общий runner теперь одновременно читает обе pipe блоками 4 KiB и удерживает
кольцевые хвосты по 8 KiB на поток. Достижение лимита не прекращает чтение. Форматирование
журнала работает только с этими хвостами; потоки подписаны и усечение явно отмечено.
Невалидный UTF-8 заменяется при отображении, поэтому размер строки в журнале может быть
больше числа сохранённых исходных байтов, но остаётся ограниченным. При таймауте хвосты
также доступны. Ошибки spawn и I/O/cleanup различаются в typed result и журнале.

**Q14-F015, P2 — потомки shell оставались живы после таймаута/отмены.** Прежний
`kill_on_drop(true)` относился только к `/bin/sh`. Скрипт мог оставить дочерние команды,
продолжающие менять сеть, либо удерживающие pipe после выхода shell. Если shell уже
завершился, уничтожение future его `output()` не останавливало таких потомков.

Теперь Linux-команда запускается в отдельной группе. Timeout, read error и отмена
отправляют SIGKILL этой группе; owned Child остаётся fallback для самого shell. В normal
и timeout/error paths shell дожидаются через wait. При Drop/отмене освобождение дочернего
процесса завершается штатным reaper Tokio, без новой detached application task.

Защита от повторного использования PID: wait/try_wait shell не вызываются, пока обе pipe
не закрыты. Даже уже завершившийся лидер удерживает идентификатор группы до cleanup.
После wait защита группы снимается без промежуточного await. Нормальный выход shell и
EOF обоих потоков **не убивает** намеренно перенаправленную фоновую службу. Код одинаков
для server и standalone Linux client; GUI-библиотеки в release этот runner не включают.

## Проверки

- Regression с реальным изолированным процессом выдаёт по 1 MiB в stdout и stderr.
  Прежний `output()` сохранял 1 048 599 байт stdout (включая test harness), тест FAIL.
  Новый runner удерживает не больше 8 KiB на поток и сохраняет заключительную диагностику.
- **8 поведенческих host-тестов + 1 дочерний fixture — PASS**: flood двух pipe,
  непрерывный flood с deadline, timeout, cancellation с TCP witness, exit/spawn error,
  ошибочный reader, границы ring buffer и UTF-8. Первый cancellation test ожидал только
  FIN; Windows вернул ConnectionReset после убийства. Исправлен test oracle: FIN/reset
  считаются закрытием, timeout остаётся ошибкой. Лог исходного результата сохранён.

## Границы и продолжение

Linux shell/group semantics требуют выполнения тестов на Linux. SIGKILL не гарантирует
быстрого выхода из неразрываемого kernel wait; при отмене async reaping зависит от жизни
runtime. Группа не удерживает потомков, сознательно сделавших setsid/смену группы или
привилегий. Это управление доверенными hook-командами, а не изоляция враждебного кода.
Остановка штатно запущенных фоновых служб остаётся обязанностью hook/service manager.

Далее: startup rollback и lifetime фоновых usage_sweep/udp_drop_report, привязка проверки
trusted config к реально распарсенному файлу, Linux E2E отмены профиля/worker. Раздел 14
и общий аудит Qeli ещё не закрыты.
