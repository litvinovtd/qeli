## Область и реализация

Проверен production DNS engine в `qeli/src/server/dns/resolver.rs`: структура
и содержимое записей, TTL всех секций, EDNS/опции, локальные ошибки, усечение
и хранение в кеше. Общий ограниченный обход записей используется для framing,
проверки распространённых RDATA, минимального TTL и EDNS. Удалены отдельный
обход TTL только ANSWER и повторная логика OPT для размера/RCODE. Linux listeners
по-прежнему используют тот же engine. Новых параметров, зависимостей и изменений
клиентского ABI нет; конфигурация остаётся INI.

## Совместимость и ограничения решений

Проверки RDATA охватывают IN A/AAAA, NS/CNAME/PTR/DNAME, MX, IN SRV, SOA и TXT.
Это проверка известных форматов, а не согласованности owner/alias/RRset, DNSSEC
или всех типов IANA. Неизвестный код опции допустим, если её TLV помещается в OPT.

Все непустые опции обходят кеш, включая PADDING, COOKIE, ECS и NSID. Такая
консервативная политика может снизить долю cache hit. Ответ с OPT не в конце
также не сохраняется: удаление байтов нарушило бы последующие compression offsets.
Ответ без OPT на EDNS-запрос пересылается без кеширования; неожиданный OPT на
запрос без EDNS отклоняется. Обычные согласованные обмены с пустым OPT продолжают
кешироваться. Производительность этим проходом не измерялась.

Контракт подписанных сообщений сохранён: байты не меняются, кеш обходится,
криптографическая проверка не выполняется. TCP-регрессия подписанного обмена
теперь включает EDNS-опции. Слишком большой подписанный UDP-ответ по-прежнему
отбрасывается; при обычном усечении создаётся OPT без полезной нагрузки опций.

## Проверки и доказательства

До исправлений упали шесть регрессий: короткий TTL authority/additional, старший
бит TTL, неверный OPT запроса, потеря расширенной ошибки при усечении, повреждённый
RDATA и кеширование опций. В финале проходят **51 DNS-тест**, включая:

- failover через IPv4 loopback UDP/TCP при неверном EDNS и RDATA;
- обмены с IPv6 loopback upstream по UDP и TCP;
- cache hit без сохранённого OPT ответа, с созданием новых полей EDNS;
- сохранение неизвестных опций и обход кеша, локальные BADVERS/NXDOMAIN;
- положительные/отрицательные RDATA-векторы, перебор усечений и мутаций байтов.

При ревизии обнаружена промежуточная ошибка реализации: обработчик UDP-размера
подавлял локальный FORMERR для неверного OPT запроса. Интеграционная проверка
воспроизвела это; теперь применяется предел 512 байт и ошибка доходит до клиента.
Финальный unit-прогон включает эту проверку. Она отделена от дефектов базы.
