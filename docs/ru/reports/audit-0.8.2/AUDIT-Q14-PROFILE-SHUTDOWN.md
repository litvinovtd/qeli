# Q14: ошибки задач профиля и очистки TUN при остановке

Дата: 23 сентября 2026. Исходный коммит: `e3fd3c6e`.
Разделы 14, 17, 18 и 19: **IN_PROGRESS**. Q14-F027 исправлена **частично**.

## Подтверждённая проблема

Результат worker уже учитывал DNS/IPv6 sysctl cleanup и usage flush, а внешний supervisor
передавал nonzero exit. Однако profile supervisors возвращали `()`, результаты завершения
их JoinSet отбрасывались. Ошибки listeners/services и паники дочерних задач также могли
теряться после reaping или отмены ожидания shutdown. Drop профиля журналировал отказ
удаления TUN, игнорировал паники очередей и всё равно писал об успешном teardown.

## Исправление

`ProfileTasks`, `ProfileServices` и `WorkerServices` возвращают результат остановки.
Обнаруженные ошибки сохраняются в ограниченном накопителе: первые восемь причин,
до 256 символов имени и 2048 символов текста каждой; число остальных указывается отдельно.
Отмена ожидания не стирает уже полученные ошибки. Повторные и одновременные ожидания
`ProfileTasks::shutdown` получают сохранённый результат. Штатная отмена дочерних задач,
listeners и services при abort не считается ошибкой; паники и завершившиеся ошибки учитываются.
Worker services завершаются кооперативно, поэтому их неожиданная отмена считается ошибкой.

Профильный supervisor передаёт результат последнего поколения при полученном запросе
остановки, включая сигнал во время post_down. Worker собирает результаты всех профильных
supervisors, продолжая ожидание после отказа, паники или неожиданной отмены одного из них.
Ошибки control task и worker services входят в ту же категорию итогового результата.

Переносимый `profile_teardown` сохраняет ошибки Drop в общем отчёте, который wrapper
читает после однократного разрушения guard. Порядок очистки ресурсов сохранён.
Потоки TUN по-прежнему получают повторные wake-up и до трёх секунд на завершение;
join выполняется только для завершённых потоков. Незавершённые потоки отсоединяются,
но теперь timeout, паника завершённого потока и ошибка удаления TUN влияют на результат.
Это не добавляет повторную попытку удаления устройства.

Итог worker содержит категорию `profile/worker task cleanup`. Даже при её ошибке
выполняются итоговая проверка известных сетевых leases и usage flush. Остановка по сигналу
возвращает exit 1; внешний supervisor передаёт этот отказ вызывающему CLI.
Новых INI-параметров нет, ABI и wire format не менялись.

## Открытые границы и следующий проход

Q14-F027 остаётся открытой для generic NAT cleanup и общей картины владения ресурсами.
Неудача прежнего поколения не сохраняется как глобальная ошибка после его замены;
остановка во время retry backoff по-прежнему может вернуть Ok. Для этих случаев нужно
отдельно отслеживать незавершённую очистку поколения, не превращая устранённую временную
ошибку запуска в постоянный отказ. Политика respawn внешнего supervisor не менялась.

Следующий проход [sysctl recovery](AUDIT-Q14-SYSCTL-RECOVERY.md) исправляет ложный Ok
при неустранённых stale entries и потерю владельца при повторном acquire.
[Q14-F031](AUDIT-Q14-IPV6-PARTIAL-ACQUIRE.md) затем добавляет учёт частичного IPv6 acquire
до первой попытки изменения. DNS ownership хранится
в памяти worker, постоянного журнала нет. [Q14-F032](AUDIT-Q14-NAT-COMMANDS.md) затем ограничивает каждую команду server NAT;
общий срок последовательности операций остаётся открытым.
Успешный итог не доказывает отсутствие всех ресурсов старых поколений или процессов.

Реальный Linux worker, сигналы, firewall/TUN/DNS, systemd, устройства, native release,
SSH/Actions и бенчмарки не запускались.

Предыдущий этап: [итоговые leases и внешний supervisor](AUDIT-Q14-OWNED-SHUTDOWN.md).

Продолжение: [Q25-F059–F060](AUDIT-Q25-TUN-LIFETIME.md) удаляет очистку TUN по имени и сохраняет исходные дескрипторы до конца cleanup. Identity DNS/маршрутов при внешней подмене и таймаут workers остаются открыты.
