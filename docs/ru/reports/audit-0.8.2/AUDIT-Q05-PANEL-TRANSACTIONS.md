## Q05-F002, P2 — синхронные сетевые пробы под блокировкой записи

Form/INI/history/Quick Start и restart запускали синхронный preflight из async handler.
Четыре команды имели отдельные лимиты 15 секунд; ожидание занимало executor и
блокировку, необходимую другим операциям записи. Quick Start дополнительно мог
синхронно проверять доступность ip6tables.

Панель теперь запускает дочерние процессы напрямую через общий async runner.
Сбор IPv4/IPv6 и дополнительная проверка ip6tables делят один бюджет 15 секунд,
включающий ожидание допуска к пробам. Допускаются четыре одновременных наблюдения;
отмена запроса освобождает допуск и останавливает принадлежащую ему команду.
Синхронные startup/check-config/restore тоже используют общий бюджет 15 секунд для
четырёх `ip`, сохраняя нужный этим вызывающим сторонам синхронный порядок.

Панель собирает сеть перед config write lock. После получения наблюдений остаётся
пять секунд на получение блокировки и подготовку кандидата к проверке. Истёкшее
наблюдение отклоняется с просьбой повторить действие. Занятый допуск или блокировка
не превращаются в «сеть неизвестна, разрешить запись». Текущий INI, revision, hooks,
пользователи и итоговая запись по-прежнему проверяются в одной критической секции.
Ошибка чтения `ip` сохраняет прежнюю политику fail-open с предупреждением; успешный
IPv4 не теряется при отказе IPv6, а обнаруженное пересечение по-прежнему запрещено.

## Q05-F003, P1 — отмена restore освобождала блокировку раньше записи

`spawn_blocking` продолжает работу после отмены ожидающего async-запроса. Раньше
блокировка оставалась у запроса: его отмена разрешала другому сохранению изменять
дерево одновременно с продолжающимся restore. У download отмена также могла
разрешить запись до завершения чтения архива.

Общий `config_transaction::blocking` передаёт owned guard самой фоновой операции.
Он возвращает guard вместе с результатом для последовательных фаз download. При
отмене guard остаётся у фоновой работы до завершения, при panic освобождается во
время unwind. Это согласует время жизни блокировки с фактической работой. Restore
может закончиться после отмены запроса; отмена не обещает rollback опубликованных файлов.

## Q05-F004, P2 — ожидание restart держало запись без предела

Worker restart теперь немедленно сообщает о занятой/закрытой очереди supervisor,
вместо неограниченного ожидания send под config lock. Проверка polkit выполняется
вне блокировки записи. Отложенный full restart заново собирает сеть, получает lock
и проверяет последний конфиг. `systemctl restart` использует общий runner с лимитом
15 секунд и 64 КиБ на поток вывода. При неизвестном результате панель предлагает
проверить unit/journal: timeout не доказывает, что systemd не принял запрос.

## Проверки и границы

Переносимые регрессии проверяют отмену фоновой записи, сохранение блокировки между
фазами, panic, совпадение политики sync/async, отзывчивость executor и завершение
реального дочернего процесса при отмене, единый срок последовательных проб.
Linux API-helper проверяет занятый/просроченный snapshot и возможность соседней
записи во время preflight. Полный Linux/feature-набор и worker lifecycle запускаются
на изолированном снимке; итоговые результаты записаны ниже.
