# Q25: владение NAT exit-node и конфликт политик kill-switch

Дата: 23 сентября 2026. Исходная точка: `166ece80`.
Q25-F043–F045 исправлены в описанных пределах. Разделы 17/18/25 остаются **IN_PROGRESS**.

## Находки

**Q25-F043, P2 — остановка exit-node удаляла NAT соседа на общем WAN.**
`exit_masq_rule` содержал WAN, packet mark и одинаковый комментарий для всех TUN.
Два профиля использовали одно правило. Очистка любого удаляла его, пока другой
профиль продолжал работать. Дефект затрагивал IPv4, IPv6 и старый/новый WAN,
сохраняемые при roaming. Отдельные WAN-карты TUN не делали само правило NAT отдельным.

**Q25-F044, P2 — очистка выводила владение из текущего default route.**
При отсутствии записанного WAN cleanup обнаруживал текущий WAN и удалял совпадающие
правила. Ещё не запущенный exit-профиль мог удалить NAT работающего. После частичной
dual-stack очистки повтор мог заново обнаружить и затронуть уже очищенную семью.

**Q25-F045, P2 — отдельные kill-switch chains оставались конфликтующими политиками хоста.**
Каждая цепочка TUN заканчивается DROP и ставится первой в OUTPUT/FORWARD. Запуск
другого профиля мог сообщать успех, хотя его более ранний DROP блокировал carrier
первого. Старый путь миграции также удалял общую `QELI_KS` без доказательства владения
новым профилем. Разные имена разграничивали удаление, но не совмещали политики пакетов.

## Изменения

NAT exit-node получает точный комментарий `qeli-exit-node:<tun>`. Остальные exit-правила
сохраняют `qeli-exit-node` и уже различаются интерфейсными selectors. Правило NAT
каждого TUN/WAN удаляется независимо, в том числе если правило другого TUN принадлежит
иному процессу и отсутствует в локальном реестре. Локальный счётчик владельцев общего
совпадения больше не нужен.

Условие обработки пакетов остаётся прежним WAN/mark: это эквивалентные NAT-правила
с разной идентичностью для очистки, а не разные packet marks для TUN.
Биты, выбранные `0x51/0x51`, зарезервированы для exit-трафика Qeli: посторонняя
маркировка firewall не должна их переиспользовать. Остальные биты сохраняются.

Очистка использует только запомненные цели установки. Fallback с обнаружением WAN
и два устаревших теста этого helper удалены. Production-тесты теперь проверяют
отсутствие команд без владельца и повтор частично очищенного семейства. Неудачные
семьи сохраняют цели; другие семьи и release sysctl по-прежнему проверяются.

Публичный запуск kill-switch проверяет обе доступные filter-таблицы до изменения
правил. Нужны успешный UTF-8 вывод и корректная структура с политиками трёх встроенных
цепочек и объявленными источниками правил. Чужая `QELI_KS_<tun>` или старая `QELI_KS`
вызывает явную ошибку конфликта, в том числе при включённых разрешениях утечек.
Неизвестный, некорректный или неполный снимок также запрещает установку.
Свой TUN может перестроить собственную цепочку; цепочки администратора сохраняются.
Публичные engage, обновление IP сервера и очистка сериализованы внутри процесса:
два одновременных запуска не могут оба пройти исходную проверку.

Это явный отказ при несовместимых одновременных full-tunnel профилях с kill-switch
в одном network namespace, а не объединение их политик. Обычные gateway/exit-node
без такого конфликтующего kill-switch остаются независимыми. Независимо защищённые
туннели следует разделять по network namespaces.

## Обновление и восстановление

Новая очистка не присваивает и не удаляет старый MASQUERADE без суффикса TUN.
После остановки/восстановления подтверждённого старого владельца проверьте точные
семью, таблицу, WAN и комментарий перед ручным удалением: массовое удаление по tag
может затронуть живые профили. Общая старая `QELI_KS` также требует явного восстановления
до включения нового профиля. Чужая per-TUN цепочка без hook консервативно считается
конфликтом.

Netns-сценарий exit-node теперь проверяет `qeli-exit-node:qrex0` для MASQUERADE.
Синтаксис shell проверен; сам сценарий с namespaces не выполнялся.
Ключи INI и служебные JSON-протоколы не менялись.

## Ограничения и следующая работа

Linux проверен cross-compilation, не runtime. Модели команд/sysctl не проверяют
forwarding ядра, непрерывность conntrack/NAT flows и sysctl leases на диске.
Общий журнал sysctl не менялся. Разный комментарий NAT подтверждает различие
selectors, но не является межпроцессным lease поколения; одновременное использование
одного имени TUN этой гарантией не покрыто.

Допуск kill-switch — снимок и mutex процесса, не межпроцессная транзакция.
Одновременно запускаемые разные процессы или администратор ещё могут создать гонку.
Убитый после частичной установки процесс может оставить цепочку для восстановления.
Общий deadline операции, новый benchmark и native certification не добавлены.
Далее: межпроцессный допуск и stale TUN identity, доказательства IPv6-защиты,
DNS/carrier globals, Q14-F027 TUN workers/FD и Linux E2E восстановления.

Продолжение: [Q25-F046–F047](AUDIT-Q25-KILL-SWITCH-LIFETIME.md) добавляет
кооперативный lease на срок защищённой Linux-сессии и проверку IPv6 fail-closed.
Межпроцессное ограничение выше описывает состояние на момент этого отчёта.
