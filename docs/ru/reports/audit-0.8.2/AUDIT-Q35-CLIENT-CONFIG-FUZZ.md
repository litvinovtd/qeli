# Q35 — инварианты клиентского INI и qeli:// при fuzzing

<!-- normative-sync: audit-q35-client-config-fuzz-v1 -->

10 октября 2026 года расширен fuzz target `client_config`. Раньше он передавал произвольные байты в парсер клиентского INI, JSON-сервис редактора и декодер `qeli://`, но отбрасывал успешный результат: потеря параметра при повторной сериализации не считалась ошибкой. Служебный JSON API редактора сохранён; форматом конфигурации остаётся только INI.

Для входов до 8 КиБ новый target проверяет неподвижную точку `разбор → канонический INI/URI → строгий повторный разбор → повторная сериализация`. Каждый вход дополнительно порождает структурированные INI и `qeli://` с IPv4/IPv6, TCP/UDP, тремя режимами roaming, кодированными `%`/`:` в пароле и меткой. Для ссылки проверяются точные пользователь, пароль, порт и roaming. Более крупные входы по-прежнему подаются в исходные парсеры и редактор, но без дополнительной сериализации. Это обнаруживает ошибки, которые не приводят к panic, и удерживает проверки в ограниченном объёме памяти.

В изолированном каталоге лабы .11 изменённый target собран под закреплённым `nightly-2026-06-10`, `cargo-fuzz 0.13.2` и ASan. Семь начальных входов воспроизведены; затем выполнено **18 494 fuzz-запуска за 61 с**, новых crash artifacts нет. SHA256 fuzz lock остался `cc451c34452ab43cdf475b7a915c8fbdc16b825d2ee262bd3903eeb6f92355f4`; SHA256 исходника target — `426b5ea87dfa1803de19fdd30480e0c7c91ad501ce20e51d1f557827bdc702c3`, бинарного target — `ada8d0616654d1a2ceb16b9e6900ccb4020c7863c57d87c0bfec6496c2ce664b`. Все 701 итоговых corpus-файла, журналы и квитанции собраны в 723 файла доказательств, проверены по SHA. Использован ранее запечатанный архив исходных входов; остальные 14 target не пересобирались.

Первый локальный сборщик доказательств остановился на `SyntaxError` из-за отступа в `try`, уже после успешного fuzz-прогона и до каких-либо изменений на сервере. Отказ сохранён, исправленная версия собрала доказательства. Собственный каталог лабы удалён после проверки процессов, открытых дескрипторов, mount points, службы и SHA `/usr/bin/qeli`; свободное место в `/var/tmp` восстановлено. Служба сохранила PID 777/845, исходное состояние хоста совпало с итоговым.

Это проверка одного усиленного target в течение минуты, а не полный nightly, доказательство безопасности парсеров или завершение всего Q35. Общий статус — **30/37 DONE (81,1%)**, Q35 `IN_PROGRESS`.
