# Q25-F144: доверие к нестандартному auth.users_file

1 октября 2026. База: `d10e6452`. D07 остаётся **IN_PROGRESS**.

`auth.users_file` задаёт путь к файлу, который изменяют CLI `add-client`, сброс пароля через `share-link --reset`, панель и control socket. До исправления worker/supervisor и `check-config` принимали нестандартный путь даже из server.conf с правами `0666` или через symlink; CLI тоже доходил до `UsersDb::update_locked`. Такой INI мог перенаправить привилегированную запись на другой отсутствующий путь или существующий корректный INI-файл.

Проверка теперь использует решение о доверии того же открытого inode, из которого прочитаны значения. Если `auth.users_file` отличается от стандартного `/etc/qeli/users.conf`, `check-config`, оба startup-пути и `add-client` требуют обычный файл, принадлежащий root/эффективному UID, без group/world write и без symlink. `share-link` проверяет это перед фактическим сбросом пароля; повторная выдача уже восстанавливаемого секрета остаётся чтением. Worker/supervisor отказывают до создания состояния, из которого панель и control socket берут путь. Стандартный путь остаётся допустимым и для INI без доверия к произвольным путям.

Проверка: unit-тест сохраняет отказ после последующего `chmod 600` того же pathname и подтверждает новый доверенный снимок; `cargo fmt --check`, строгий Clippy и Linux CLI-матрица на изолированной .11: отказы `check-config`, `server`, `_worker`, `add-client` при `0666`, отказ symlink, отсутствие созданного users-файла, затем успешные `check-config` и `add-client` при `0600` с приватным users-файлом. Лог: `C:/Users/litvi/OneDrive/Documents/qeli/audit-debt-20260925/server-nat44-egress-phase/userspathtrust3.log`.
