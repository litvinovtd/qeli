# Q25: откат gateway, изоляция туннелей и проверки firewall

Дата: 23 сентября 2026. Исходная точка: `86b8cccb`.
Q25-F040–F042 исправлены в описанных пределах. Разделы 17/18/25 остаются **IN_PROGRESS**.

## Находки

**Q25-F040, P2 — общие флаги gateway теряли состояние очистки другого туннеля.**
Один IPv4-флаг и один IPv6-флаг представляли всех клиентов процесса. После включения
двух профилей очистка первого сбрасывала общий флаг, поэтому очистка второго
пропускала его правила. Даже очистка неактивного TUN могла сбросить флаг другого.
Неудачная очистка теряла возможность повтора после остановки соседнего профиля.

**Q25-F041, P1 — ошибка проверки kill-switch позволяла вставить ACCEPT перед защитой.**
`ensure_rule` принимал любую ошибку проверки наличия за отсутствие. Если проверка
permit показывала отсутствие, проверка kill-switch завершалась ошибкой, а вставка
проходила, permit попадал на позицию 1 перед существующим jump kill-switch.
Последующая успешная проверка permit принимала такое состояние. Уже существующий
permit вообще обходил проверку порядка jump: реконнект мог принять permit перед
защитой. Ошибка исходной проверки NAT/другого правила также разрешала слепую вставку.

**Q25-F042, P2 — очистка восстанавливала MASQUERADE из последнего конфига.**
При смене LAN-подсети для того же TUN старый помеченный MASQUERADE оставался
неучтённым. Очистка удаляла правило только для последней подсети и сообщала успех.

## Изменения

Состояние gateway хранит каждый TUN, семейство IP и подсеть попытки установки до
первого изменения sysctl. Очистка использует сохранённые параметры, пробует все
подсети и общие правила обеих семей, сбрасывает только полностью проверенное
семейство. Неактивный TUN не проверяет и не удаляет правила другого владельца.
После ошибки записи соответствующей семьи остаются для повторной очистки.

Единый публичный `disengage_plan` обслуживает остановку и откат NetworkPlan.
Вызывающий код больше не копирует и не передаёт текущие LAN-подсети для undo.
Неиспользуемые частичные `disengage`/`disengage_exit` удалены после проверки вызовов
по репозиторию.

Установка использует общий классификатор «есть / отсутствует / ошибка проверки».
Ошибка запрещает изменение проверяемого правила. Новый и повторно используемый
FORWARD-permit должны подтвердить, что обнаруженный jump Qeli kill-switch первый;
новый permit ставится за ним. Проверки вывода цепочки отвергают невалидный UTF-8.
Проверка после установки остаётся обязательной: ложный успешный статус отвергается,
а правило, обнаруженное после потери результата команды, учитывается через свой
scope и удаляется при очистке.

Публичные router-операции, включая обновление exit-path и освобождение sysctl,
сериализованы внутри процесса. Очистка больше не может перемешаться с новой
gateway-acquire между удалением записей и освобождением sysctl. Это не атомарная
транзакция ядра и не блокировка всего многошагового NetworkPlan. Общий постоянный
журнал sysctl не менялся: release пробуется даже после ошибки firewall, ошибки
объединяются, leases других владельцев сохраняются. Успешный release не превращает
неудачную очистку firewall в успех.

## Пределы и следующая работа

Учёт правил находится в памяти и привязан к имени TUN, без постоянного lease
поколения. Точное совпадение помеченного правила не доказывает авторство во внешней
гонке: другой процесс может изменить firewall между проверками. Сохранён предел
восемь попыток удаления. Deadline команды — 15 секунд; общего deadline всей
сериализованной операции пока нет.

Модель sysctl проверяет orchestration gateway, но не поведение knobs ядра и не
сохранение журнала на диске. Полный guard клиента, очистка route/TUN и утечки пакетов
требуют Linux-интеграции. Этот проход не сертифицирует несколько одновременных
kill-switch chains и владение общим WAN/NAT у exit-node. Это следующие проверки;
затем обнаружение необходимости IPv6-защиты, оставшиеся DNS/carrier globals,
Q14-F027 TUN workers/FD, crash recovery, native certification и новый benchmark.
Ключи INI и служебные JSON-протоколы не менялись. Полный аудит не завершён.
