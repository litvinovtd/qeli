# Q25-F171: кодировка desktop-хранилищ профилей

1 октября 2026. База: a1b64ece. D08 остаётся **IN_PROGRESS**.

Windows DPAPI store и macOS AES-GCM store декодировали расшифрованный JSON-контейнер через `Encoding.UTF8.GetString`, который заменяет ошибочные UTF-8 последовательности на U+FFFD. В нормальном новом контейнере сериализатор пишет корректный UTF-8, но старый plaintext store или восстановленная запись могли содержать испорченные байты. Замена до JSON-парсера могла изменить пароль или другое строковое поле без явной диагностики кодировки. JSON здесь является только внутренним контейнером хранилища; формат клиентского конфигурационного документа остаётся INI.

Оба desktop store теперь используют декодер UTF-8 с исключением на неверной последовательности. Windows переходит к legacy plaintext только при ошибке DPAPI, а не при ошибке декодирования уже расшифрованного текста. Ошибка попадает в существующий путь сохранения повреждённого файла отдельно; на macOS затем предпринимается предусмотренная попытка восстановления из `.bak` с той же строгой проверкой. Действительные зашифрованные контейнеры и формат записи не меняются.

Проверки: `dotnet build` для QeliWin и QeliMac с `--no-restore` прошёл без предупреждений и ошибок; `git diff --check` прошёл. Загрузка реального повреждённого store и UI-откат при неудачной записи не проверялись; последнее остаётся отдельным открытым условием D08. Mac runtime и Windows VM недоступны по согласованному ограничению стенда.
